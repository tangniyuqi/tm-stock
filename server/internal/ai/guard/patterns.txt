# AI 护栏句式规则（红线检测的第二部分；第一部分是 words.txt 词表词）
#
# 格式：规则名 = 正则（Go RE2 语法）。# 开头为注释，空行忽略。
# 匹配对象是"骨架视图"（见 normalize.go）：已做 NFKC、去零宽、转小写、繁转简，
# 并且去掉了空白与除下面几个以外的全部标点符号：句末符  。！？!?；;  与百分号 % 。
# 所以规则里不需要写空白与标点的容错；用 [^。！？!?；;]{0,N} 表示"不跨句的一小段文字"。
# 例外：正则前写 @raw 的规则，匹配的是"规范化视图"（只做了 NFKC、去零宽、折叠空白，保留全部标点）。
# 只有"依赖标点本身"的规则才需要它（如编码字符引用 &#…; 与 \u…），因为骨架视图会把这些标点丢掉。
#
# 维护规则（与词表一致）：
#   1. 只增不减——发现新的越界说法就加进来，删规则必须有律师意见或误杀数据支撑并留痕；
#   2. 每条规则必须在 eval/ 或 testdata/ 里至少有一条正例（TestEveryRuleHasCoverage 会检查）；
#   3. 本文件是 .txt，不在用户可见文案的合规词门禁扫描范围内；这里出现违规措辞是在"定义禁令"。
#
# 已知的误杀类型（有意取严，命中后走"截取或转人工"，不是直接丢掉）：
#   - 业绩与大宗原料类的合法预测句（如"预计原材料价格将会上涨"）会命中 forecast_move；
#   - 描述 AI 产品能力的句子（如"大模型预测蛋白质结构"）会命中 ai_self_opinion；
#   - 信用评级、投顾业务披露等文字偶尔命中 injection_output。
