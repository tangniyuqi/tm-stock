# 已知坑点库

> **规则：同一个错误犯第 2 次，就必须写进这里；能机器检测的，就做成门禁。**
> 知识只往底层沉淀——坑 → 规则 → 门禁，不要停留在"下次注意"。

## 如何使用

- 遇到诡异问题**先查本文件**，不要从零排查。
- 修复后回写：现象 / 根因 / 判据 / 修法。
- 判据要**可复现**，不要写"感觉是网络问题"。

## 环境与工具

### P1. 本机没有 jq（hook 不能依赖它）
- **现象**：hook 静默不生效，或报 `jq: command not found`。
- **根因**：Windows / 精简环境普遍无 jq。
- **修法**：用 `sed` 提取 JSON 字段（见 `.claude/hooks/post-edit-check.sh`）。

### P2. Windows 路径是反斜杠，通配匹配全部失效
- **现象**：hook 收到 `D:\a\b.uvue`，所有 `case $FILE_PATH in *.uvue)` 判断都不命中。
- **修法**：先 `tr '\\' '/'` 转正斜杠再匹配。

### P3. hook 里 exit 0 会吞掉 stderr
- **现象**：hook 明明 echo 了错误，AI 却看不到。
- **根因**：exit 0 时 stderr 被丢弃。
- **修法**：要拦截并反馈给 AI → **exit 2**；只提醒不拦截 → 走 stdout 的 `{"systemMessage": "..."}`。

### P4. printf '%b' 会把 \n 展开成真实换行，破坏 JSON
- **现象**：Stop hook 输出的 systemMessage 解析失败，hook **静默失效**（表面没报错）。
- **根因**：JSON 字符串里不能有裸换行，必须是转义的 \n 两个字符。
- **修法**：用 `printf '%s'`，让 \n 保持字面量。
- **判据**：`bash hook.sh | node -e "JSON.parse(...)"` 能解析才算通过。

### P5. git status --porcelain 会折叠未跟踪的新目录
- **现象**：新建 `pages/foo/bar.uvue` 后，检测代码改动的脚本判空。
- **根因**：默认只输出 `?? pages/foo/`，不展开到文件。
- **修法**：加 `-uall`。

### P6. Git Bash 的 /tmp 与 Node(Windows) 解析不一致
- **现象**：bash 写入 `/tmp/x.json`，Node 读 `/tmp/x.json` 报 `D:\tmp\x.json` 不存在。
- **修法**：跨工具传文件用**绝对路径**。

### P7. 本仓库 clone 必须用 partial clone
- **现象**：`git clone` 反复 `SSL_ERROR_SYSCALL` / early EOF。
- **根因**：`uni_modules` 含大量大二进制（3MB tflite 等），叠加本地代理不稳。
- **修法**：`git clone --filter=blob:none --depth 1 <url>`。

## 门禁与脚本

### P8. grep -E 不支持 \x27（单引号转义）
- **现象**：密钥扫描规则看着对，实际**永远不命中**，明文密钥能溜进仓库。
- **修法**：不写引号字符类，改用"值前允许 1 个非字母数字字符"涵盖任意引号。
- **教训**：**正则写完必须造正例 + 反例各测一次**，只看语法通过等于没测。

### P9. 扫描不排除三方目录 → 门禁常红 → 门禁失效
- **现象**：`hybrid/katex.js` 里的 `const token = parser.fetch()` 被当成明文密钥。
- **修法**：排除 `uni_modules / hybrid / static / .kiro / docs / node_modules`；
  并放行"函数调用 / 属性访问"形式的值（`= foo(` / `= foo.bar`）。
- **教训**：**红灯常态化 = 门禁失效**，宁可先关掉也不要让它天天红。

### P14. 同一检查的两种模式范围不一致 → 一边绿一边红
- **现象**：\`harness-checks.sh\`（--all 模式）全绿，但 \`git commit\` 被 pre-commit 拦住。
- **根因**：\`--all\` 用 \`--include\` 白名单（当时漏了 \`*.py\`），而 staged 模式扫
  \`git diff --cached\` **不限文件类型** → 两者覆盖面不同。
- **修法**：同一检查的不同模式**文件范围必须对齐**；改了一个模式记得改另一个。
- **教训**：门禁自己不自洽，比没有门禁更让人困惑。

### P18. 门禁用裸 grep 查依赖 → 把注释当成违规（2026-07-31 实测）

- **现象**：`handler/response.go` 被判"跨层引用 repository"，但它根本没 import。
- **根因**：规则写作 `grep -rln "internal/repository"`，匹配的是**任意出现位置**。
  而该文件的包注释里有一句「本层不得 import database/sql 或 internal/repository」——
  **规则把自己的说明文档判成了违规**。
- **⚠️ 最危险的地方是"看起来很好修"**：删掉那句注释就绿了。
  但那句注释是有价值的，删它等于**把文档改坏去迁就工具**。
  同类思路见「门禁文案本身制造缺陷」——修工具，不要修被工具误伤的正确内容。
- **修法**：让规则认得 Go 的 import 语法（行首空白 + 可选别名 + 引号路径）：
  `^[[:space:]]*([_.]|[A-Za-z][A-Za-z0-9_]*)?[[:space:]]*"[^"]*(<路径>)"`
  已抽成 `imports_of()` 供规则 1–4 共用。
- **判据**：改完必须两头验——注释不再误报 **且** 造真 import 仍被抓到。

### P17. mysql CLI 灌数据不指定字符集 → 中文双重编码（2026-07-31 实测）

- **现象**：接口返回的中文是 `å…‰åˆ»æœº` 这种乱码，但**同一份 JSON 里
  来自 Go 字面量的中文却是好的**。
- **判据**：一半正常一半乱码 → 就不是终端显示问题，是**数据本身坏了**。
  查 `SELECT HEX(name)`：`光刻机` 正确应为 `E58589E588BBE69CBA`，
  实际存的是 `C3A5E280A6...`（把 UTF-8 字节当 latin1 又编了一次）。
- **根因**：`docker exec -i ... mysql ...` 不带 `--default-character-set=utf8mb4` 时，
  客户端按系统 locale 协商连接字符集，管道进去的 UTF-8 中文被双重编码。
  **列本身是 utf8mb4 也救不了**——坏在写入路径，不在存储。
- **为什么隐蔽**：ID、计数、状态类断言全绿，只有中文取出来是坏的。
  `verify-migrations.sh` 一直带着这个问题，因为它的断言恰好都不含中文。
- **修法**：所有 `mysql` CLI 调用加 `--default-character-set=utf8mb4`；
  Go 侧 DSN 加 `charset=utf8mb4`（走驱动这条路径本来就是对的，
  集成测试断言中文能过就是证明）。

### P16. 门禁"静默失效"三连（密钥扫描实测，2026-07-30）

> **共同特征：门禁照样打印 `[OK]`，只是什么都没拦住。不报错，所以没人会发现。**
> 教训：**给门禁本身写测试**。已落 `scripts/dev/verify-secret-scan.sh`（13 项正反例）并接入 CI。

**① 基线文件的注释行被当成匹配模式（最严重）**
- **现象**：值里带 `#` 的明文密钥**完全隐形**，扫描一律 `[OK]`。
- **根因**：`grep -vFf "$BASELINE"`——基线文件里有一行只写 `#`（注释），
  `-F` 把它当**固定字符串**，于是"任何含 `#` 的行"都被当作已豁免而 `-v` 掉。
  而 `#` 是密码里极常见的字符。
- **同类**：基线里出现**空行**会匹配所有行，等于把整个扫描静默关闭。
- **修法**：当模式用之前**先剥掉注释与空行**：
  `BL_CLEAN="$(grep -vE '^[[:space:]]*(#|$)' "$BASELINE")"`，且 `BL_CLEAN` 为空时跳过过滤。
- **判据**：造一个值里带 `#` 的密钥，必须被抓到。

**② 键名模式漏了 `PW` 缩写**
- **现象**：`ROOT_PW=` / `DB_PW=` 带真密码，扫描器看不见。
- **根因**：模式只写了 `pass|pwd|secret|token|...`，`PW` 不在其中。
  实测三条样本只有 `MYSQL_PWD` 命中，`ROOT_PW` 与 `DB_PW` 全漏。
- **修法**：键名模式加 `pw`。加完**必须全仓回扫确认没造成误报**。

**③ staged 模式丢失文件归属 → 无法排除任何文件**
- **现象**：合法的测试夹具（自测脚本必须含探针密钥）会**永久卡住 pre-commit**，
  且报错看不出命中在哪个文件。
- **根因**：`git diff --cached | grep '^+' | sed 's/^+//'` 把文件名扔了。
- **修法**：用 awk 跟踪 `+++ b/<path>` 头，给每行补上 `file:` 前缀；
  排除项只列**具体文件名**，不整目录放行。
- **附带收益**：staged 与 `--all` 两种模式的排除口径终于一致（对照 P14）。

### P15. 放行规则漏了"表达式赋值"形态
- **现象**：\`_token = (body.get("data") or {}).get("token")\` 被当成明文密钥。
- **根因**：放行规则只覆盖 \`= 标识符.\` / \`= 标识符(\`，没覆盖 \`= (\` / \`= [\` / \`= {\` 开头。
- **修法**：值以括号/方括号/花括号开头的一律视为表达式放行。
- **判据**：修放行规则后**必须回测真密钥仍能被抓**，否则就是把门禁改瞎了。

## 前端（uni-app x）

### P10. 时间字段声明成 string 会直接崩
- **现象**：`type 'int' is not a subtype of type 'String?'` 类错误。
- **根因**：后端统一返回**毫秒时间戳（number）**，前端却声明 string。
- **修法**：model 里声明 number；展示时统一用格式化函数转换。

### P11. 新页面忘记在 pages.json 注册
- **现象**：页面写好了但跳不过去。
- **修法**：新增 `.uvue` 必须同步注册；CI 已加一致性检查（warning）。

## 合规（本项目最高风险区）

### P12. 以为"加了免责声明就安全"
- **现象**：页面写了免责，仍然违规。
- **根因**：荐股认定采**功能实质测试**，与免责无关；结构违规时免责反成"明知故犯"证据。
- **修法**：合规靠**功能与结构改造**，不靠声明。见 `compliance-redline.md`。

### P13. 规范文档自身含禁用词，导致门禁自己拦自己
- **现象**：合规词检查把 `compliance-redline.md` 也拦了。
- **修法**：检查范围只含用户可见文案（`pages/ server/ static/ hybrid/`），
  排除 `.claude/ .kiro/ docs/ scripts/`——它们是在**定义禁令**，必然包含这些词。
