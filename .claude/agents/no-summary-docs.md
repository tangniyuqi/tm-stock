# 禁止任务总结文档

## 规则

**禁止创建这类文件**：`SUMMARY.md`、`IMPLEMENTATION_REPORT.md`、`XX完成报告.md`、
`XX实施总结.md`、`XX开发完成报告.md` 等一次性总结文档。

## 为什么

这类文档**写完即过期**，堆积后：
- 让 `docs/` 变成垃圾场，真正的规范被淹没；
- 后来者读到过期信息，比没有文档更糟；
- 消耗 token 和注意力，不产生复用价值。

## 正确做法

| 想记录的东西 | 应该写到哪 |
|------------|----------|
| 这次做了什么 | **对话里说 1-2 句** + 关键文件路径 |
| 架构决策与取舍 | `docs/adr/`（ADR，长期有效） |
| 需求与验收标准 | `docs/specs/{需求}/` |
| 反复踩的坑 | `.claude/agents/` 里的规范文件（变成规则） |
| 操作步骤 | runbook（可执行的操作手册，不是报告） |

**判据**：这份文档三个月后还有人读吗？没有 → 不要写。
