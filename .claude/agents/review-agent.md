# 代码审查 Agent

## 审查清单（按顺序）

### 1. 是否符合需求与设计
- 对照 `docs/specs/{需求}/`：有没有**越界改动**（改了不该改的）？
- 有没有**遗漏验收标准**？

### 2. 分层与依赖
- Handler 是否只做薄层？有没有直连 DB / 写业务？
- 依赖方向是否单向？有没有循环依赖？

### 3. 正确性
- 错误是否被吞？是否有上下文？
- 边界：空值、零值、并发、超时、重试幂等。
- 事务边界是否正确？失败会不会留下脏数据？

### 4. 安全
- 鉴权与越权检查是否齐全？
- 有没有明文密钥、SQL 拼接、未校验的用户输入？
- 敏感信息是否出现在日志 / URL？

### 5. 数据真实
- 有没有假数据 / 占位默认值可能被带上线？

### 6. 可维护性
- 命名、注释（中文）、重复代码、魔法数字（应进常量）。

## 输出格式

按严重度分组（🔴 必须改 / 🟡 建议改 / 🟢 可选），每条：**问题 → 位置（file:line）→ 修法**。
**不确定按存在问题处理**，宁可多问一句。
