# 代码审查 Agent

## 审查清单（按顺序）

### 1. 是否符合需求与设计
- 对照 `docs/specs/{需求}/`：有没有**越界改动**（改了不该改的）？
- 有没有**遗漏验收标准**？

### 2. 分层与依赖
- Handler 是否只做薄层？有没有直连 DB / 写业务？
- 依赖方向是否单向？有没有循环依赖？

### 3. 正确性
- 错误是否被吞？是否有上下文？
- 边界：空值、零值、并发、超时、重试幂等。
- 事务边界是否正确？失败会不会留下脏数据？
- HBuilderX 5.26 的 H5 `uni.showModal` 决策回调先于关闭动画结束。浏览器验收须等原弹窗实际隐藏后，再操作背后的页面并核对目标请求/可见结果；不能仅凭按钮文字存在或点击调用返回就认定事件已交付。疑似详情消失时先区分事件未派发、请求未发出与响应后被清空，不用固定延时、补写请求或盲目重复创建掩盖。
- 异步按钮及`onShow`触发的读取须检查拒绝处理；前置非必要接口（如账号设置）失败不能阻断独立的身份/资料核验。验收同时覆盖原脚本拒绝反例与实际登录返回页，并检查未处理Promise；登录成功、任务成功或门禁通过均不能代替错误路径证据。隔离网关未开放的路径须如实记录，不补假成功响应掩盖异常。

### 4. 安全
- 鉴权与越权检查是否齐全？
- 有没有明文密钥、SQL 拼接、未校验的用户输入？
- 敏感信息是否出现在日志 / URL？

### 5. 数据真实
- 有没有假数据 / 占位默认值可能被带上线？

### 6. 可维护性
- 命名、注释（中文）、重复代码、魔法数字（应进常量）。

### 7. GVA后台接线与旧入口退役
- 权限反例须经过实际JWT/Casbin中间件，并断言拒绝后零上游调用；GVA可能以HTTP200/code7表示权限不足，不能仅检查HTTP状态或把它当提交未知。专用页面可局部归一化，不凭此更改全站错误契约。
- 页面专项宿主不能代替原统一Axios拦截器、路由守卫、续签或KeepAlive停用验证；测试必须说明实际执行层与替换层。
- `import.meta.glob`会将无菜单引用的旧组件纳入整包构建。删除API导出后仍须核对这些消费者；不得为消除缺失导出错误恢复已退役写接口，保留旧路径时须明确只读停用且零写请求。
- 整包构建在隔离副本验证，不覆盖用户原dist/配置；禁用安装脚本后缺少依赖生成入口，先检查对应初始化脚本再有界执行，不外置缺失模块或伪造导出蒙混通过。构建成功仍须保留兼容性/包体警告，不能当作浏览器验收。
- 本地登录验收须使用原登录表单、密码校验、菜单和角色授权接口，不用直接注入JWT替代。测试路径以实际router大小写为准，不能只照Swagger注释；SQLite `:memory:`夹具须保证并发查询共享数据库，并对角色面板的并行请求设反例。测试口令应按会话随机生成且不记日志，不能给产品引入默认账号或口令。

## 输出格式

按严重度分组（🔴 必须改 / 🟡 建议改 / 🟢 可选），每条：**问题 → 位置（file:line）→ 修法**。
**不确定按存在问题处理**，宁可多问一句。

## 本地迁移脚本排序

PowerShell执行迁移须明确使用`StringComparer.Ordinal`排序；`Sort-Object Name`的文化排序可能将`conversations_tasks.sql`放在`conversations.sql`前，引发外键目标不存在。不得靠重写迁移或关闭外键掩盖。新增启动路径须在空隔离库真实执行全部迁移，再验证运行账号的正例及明确权限错误码；脚本语法通过不代表顺序或权限正确。
