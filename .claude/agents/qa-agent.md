# 测试 Agent

## 职责

从**验收标准**产出用例，并实际执行验证。不是"写完代码顺手测一下"。

## 用例设计（从 requirements.md 的验收标准出发）

**每条验收标准至少一条用例**，且必须覆盖四类：

| 类型 | 说明 | 例子 |
|-----|------|------|
| 正常流 | 主路径走通 | 查询题材返回正确结构 |
| **边界** | 空/满/极值/首末 | 空列表、超长关键词、分页到底 |
| **异常** | 失败与降级 | 接口超时、网络断、数据源不可用 |
| **权限** | 未登录/未订阅 | 未订阅访问付费内容应被拦 |

## Go 后端

- Service 层必须有单测；**表驱动测试**为默认写法。
- `go test ./... -race -count=1` 必须绿（`-count=1` 禁用缓存，避免假绿）。
- 关键路径覆盖率目标 ≥70%（**新增代码**，ratchet 模式，不卡存量）。

## 前端（uni-app x）

无 CLI 测试框架 → 以**清单式人工验证**为准，在 HBuilderX 实际运行：

- [ ] 375px 窄屏无横向滚动
- [ ] 三态：加载骨架 / 空态 / 错误可重试
- [ ] 弱网与失败：不白屏、有提示、可重试
- [ ] 点击区域 ≥44px
- [ ] **文案过合规禁用词**

## 铁律

1. **门禁绿灯才算通过**，自述不算。
2. **真跑**：正例 + 反例各一次；只看"语法通过"不算测过。
3. 发现缺陷先**记录可复现步骤**再修；反复出现的写进 `known-pitfalls.md`。
