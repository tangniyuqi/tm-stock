# 任务完成判定标准

> **"我做完了"不是完成的判据。** 本文件定义什么才算完成。

## 完成的四个必要条件（缺一不可）

1. **需求对齐**：改动确实解决了原始诉求，没有越界改无关的东西。
2. **门禁绿灯**：`bash scripts/harness-checks.sh` 通过（**Agent 自述不算数**）。
3. **真跑验证**：关键逻辑实际执行过——**正例 + 反例各一次**，不是只看语法通过。
4. **三问自检**：最没把握 / 最大遗漏 / 波及面，三条都答了并写进汇报。

## 明确**不算**完成

- ❌ 编译过了但没跑过
- ❌ 测试写了但没执行
- ❌ "应该没问题" / "理论上可以"
- ❌ 有 TODO 没标注、有已知缺陷没说明
- ❌ 门禁红着说"这个红灯是历史遗留"（那就先修或先说清）

## 汇报格式（完成时）

```
做了什么：1-2 句
关键改动：file:line 形式的路径
验证结果：跑了什么、结果如何（贴关键输出）
三问自检：① 最没把握 ② 最大遗漏 ③ 波及面
```

**禁止**写任务总结文档（见 `no-summary-docs.md`）。

## 部分完成怎么办

诚实说明进度与阻塞点，**不要把"部分完成"报成"完成"**。
能自己解决的当轮解决（自主闭环）；确实需要授权人决策的，带方案上交。
