# ADR-0022：创建准入计划与执行持久绑定

- 状态：开发中；真实调用、收费与部署保持关闭。
- 背景：ADR-0021只固化价格/预算，实际执行规划器可能另选资料、模型或批准引用；格式与当前复核不能替代首次范围的持久约束。

## 决定

1. 新会员创建在原冻结/任务/首事件的同一事务保存准入计划。新增不可变准入记录及任务上的可空摘要标记；新建必须成对写入，任一失败整体回滚。标记只能在任务INSERT时设置，不能后补、擦除或替换。旧内部任务的NULL不是新会员创建的降级选项。
2. 准入记录含任务/用户/原请求摘要、锁价、预算、资料元数据、模型公示及批准引用、完整执行规划摘要。采用有版本的严格规范JSON及SHA-256，不存令牌、来源正文或Agent原文，不增加公开DTO字段。摘要不代表批准真实。
3. 执行摘要包含Agent操作人/标识/配置/资源、判定配置与策略、题材及快照内容身份；排除创建后才有的任务编号、操作键和租约围栏。资料与域名规范排序，不因规划器返回顺序不同产生新授权范围。调用前核对持久计划与任务；每次规划Recheck仍核对持久绑定和当前授权，不允许历史批准绕过撤回。
4. 标记存在但记录缺失、损坏、身份/锁价/预算或规划摘要不符时不执行模型。原键核查同样检查绑定记录，但不因外部批准撤回拒绝已确认的创建收据。已提交回执未知只核查原键，不另写或补计划。
5. 旧内部任务可保持无准入记录以供既有开发核使用；新增读取须同时确认标记和记录均不存在。新增受控会员创建永远走有计划的原事务路径。迁移不补造历史批准，不自动迁移生产库；启动检查验证新增结构和实际拒写保护。
6. 持久准入校验进入报告转换、终检的每次事务内读取（包括写后确认及原键重放），会员报告读取复用同一校验，不只在执行规划器外层检查。记录缺失、损坏或读取提交不明时返回空结果；写后确认失败必须回滚报告、任务成功与结算。报告启动自检也实测准入保护，不能等到首个会员请求才发现迁移或权限缺失。本条已接线并通过单元正反例，双版本真库验收尚在推进。
7. 记录存在不等于报告可用。转换所用快照、最终候选及历史报告还须比对首次模型名称/公示编号、题材和实际引用的快照编号/哈希/链接/来源类别/采集时点。可引用原范围的子集，但不能追加其他当前已授权却未被首次准入的来源。范围不符返回空结果并保留原键/冻结，不自动当作业务失败退款；已结算历史报告拒读不撤销结算或补调用。结构不合法的候选仍走原失败/释放流程，不借此交付。此检查不代替完整执行摘要、模型配置/质量/远端硬预算与当前来源/发布批准。

## 验证

单元及双版本真库验证原子回滚/未知提交/同键竞争、标记不可变、记录不可变、伪造摘要/身份/预算、缺保护启动拒绝、来源及批准撤回、规划变更零调用、原键不补记录。完整主链仍以示例来源和回环测试模型运行，不以结构验证代替生产授权或模型质量。

报告侧补充验收：成功后删除/损坏准入记录、两次读取之间失效、读取提交不明均不得出正文；在终检初次读取、最终写事务及写后确认注入故障，核对无半份报告/成功事件/结算，恢复原依赖后仅复用原执行结果，不新增模型调用或冻结。

首次范围补例先复现旧核在记录可Bind但模型或快照范围不符时仍保存/结算，补验转换、终检、历史读取与重放的模型/公示/题材/出处各字段及合法子集。该单元夹具只验证内部范围门禁，不代表完整会员L1流水线或真实多Agent/判定质量；真库仍复用实际HTTP创建、完整worker与原账本/报告事务。
