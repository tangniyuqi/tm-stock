# ADR-0029：题材资料 Agent 使用显式对象与用途

日期：2026-11-04。范围：获授权开发环境的真实题材资料接线；不改变生产发布前置。

## 背景

原 TradingAgents-CN V2 联调已完成真实报告、问答与反馈闭环，但其输入仍是固定合成包。现有 agents.Request、提交接口和执行登记强制六位 symbol，原图包含交易与风险意见角色。正式机关节选目前只获单独 bounded-material-qa 开发用途，不能自动解释为 Agent 用途，也不能用题材编号猜股票代码。

## 决定

保留原股票请求、固定原图和合成输入协议作为原有回归。新增明确的资料请求分支：会员、题材/专题对象及资料包摘要均参与不可变登记，股票代码为空；两类请求互斥，旧 JSON 字节和旧身份不自动升级。复用原 Agent 执行登记、幂等状态、原任务和积分系统，不另建收费链路。

真实题材通过单独的资料用途批准和当前权限装配取得不可变快照，由服务端构建资料包，不能接受会员上传的正文、URL、模型或许可声明。提交前和实际调用期间复核当前范围，撤权后停止新增发送；结果未知按原请求核查，不重提。正式资料问答许可不能充当此批准。

复用固定社区版的 BaseAgent、AgentFactory 与 WorkflowEngine，配置资料抽取、口径核验、来源/缺口整理和汇总角色，不把股票意见工作流改名后称为题材研究。新角色及编排使用独立显式协议，原十四节点审计不能用少数角色替代。缺失资料保持未知，不提供投资判断。

真实输入存证与当前会员读取采用独立于 synthetic v1 的声明，绑定实际来源/快照/正文摘要及全部实际模型请求；内部上下文不公开。先以已有三类正式机关节选接服务和原终检/结算，再扩展覆盖；节选、真实调用和工程测试不能计为人工金标或质量优势。

## 后果与验收

执行表新增互斥对象字段和不可变保护，旧记录保留为空，原请求重读与重放不得变化。启用新分支前迁移并更新读取/运行进程，旧代码不负责读取新类型；当前不部署线上。

分别验证旧请求编码/身份不变、新请求混用及类型/范围篡改拒绝、受限账号、SQL 约束/不可变事件和双版本并发；继而验证真实快照→社区 Agent→输入审计→原报告终检/一次结算。旧合成闭环、真实节选用途、人工质量和实际 H5 分开验收。具体契约及推进记录维护在 AI design/tasks，不以本决策作为完成证明。
