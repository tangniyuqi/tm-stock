# 0027 · L2 深度多 Agent 与报告追问生产启用的待决边界（提议）

- **状态**：**C（公开发布）已选择“建议包”（2026-10-22）**，实施中；真实模型尚未注入，默认开关仍关闭，不构成上线授权。
- **日期**：2026-10-22
- **关联**：requirements 第 0 节“仍待确认”、C-7/C-5、ADR-0015/0019、tasks 第 11 节。
- **目的**：把必须由产品/合规负责人决定的事项集中列出，避免研发擅自定价、放宽质量门槛或把 L1 包装成 L2。

## 1. 当前事实

- 会话、资料问答、轻度资料整理、报告读取、报告追问（本地测试装配）、反馈受理/处理已分别完成源码/真库/官方 H5 验证。
- 深度资料整理在界面与接口上均明确“暂不可用”；未实现 L2 编排、定价或交付策略。
- L2 最小交付政策、质量阈值、正式价格、生产容量在需求中仍标注“待确认、不得默认启用”。
- 真实多 Agent 仅做过本地隔离测试，不能视为生产资料质量。

## 1.1 已批准参数（C 建议包）

| 项目 | 值 |
|---|---|
| 价格 | 30 积分/次 |
| 最小交付 | 四节报告 + 至少 6 条逐字引文 |
| 质量 | 引文逐字；蕴含/语义判定均通过 |
| 失败/取消/超时 | 全额释放，不做部分交付 |
| 容量 | 每用户 1 并发、全局 5 |
| 模型 | 必须已备案；当前未注入，开发验收仅用回环模型 |

实现必须逐项落实，缺一项不得公开报价或创建深度任务。

## 1.2 已批准生产参数（2026-10-22）

- 材料：仅使用已登记且当前启用的 `tm_ai_sources`；至少 2 个独立来源，最多 16 个快照；类别限公告、年报、招股书、官方产业目录、互动易问答；无合格来源时深度不可用。
- 预算：`MaxCalls=10`、`MaxTokens=24000`、`MaxPages=6`、`MaxDuration=300s`；选择输出8192、判定输出1024（2026-10-22 用户批准 A）。
- 并发：每用户 1、全局 5。
- 价格：30 积分/次。
- 失败/取消/超时：全额释放，不做部分交付。
- 上述为产品批准值；真实模型验收后如调整，需重新批准并记录。

**真实模型探测（2026-10-22）**：DeepSeek Key 可用，模型为 `deepseek-flash`、`deepseek-v4-pro`；两者均不支持 `response_format=json_schema`（400）。已加默认关闭的 `JSONSchemaFallback`（改用 json_object 并把 schema 放入提示词）。用 `deepseek-flash` 跑真实深度时，选择请求在 2048/4096 输出预算下只返回推理、正文为空，未通过六引文选择；批准的 12000 总 token 预算不足以覆盖该模型的推理+选择+双判定。真实深度验收未通过。后续以可配置输出上限探针（8192/1024、总预算24000）跑到结算，证明 8192 可解决空正文，但结算报“账务幂等键与原请求不一致”；该参数未获生产批准。后续真实对比：v4-pro在3分钟租约、8192/1024/24000下曾完整通过一次，但RC/RR复跑均在选择阶段empty_content；reasoner两次guard_rejected；flash持续空正文。结论：现有Key无稳定深度模型，需外部json_schema模型或预算内重试/更高预算，另行批准。

**实施进度（2026-10-22）**：类型 2 终检/准入契约、30 积分报价/创建（测试控制面）、类型 2 真库执行到终检与结算、每用户1/全局5并发限制均已跑通；选择阶段对深度报告按句拆分逐字引文以满足≥6条。生产控制面与 worker 装配、前端深度确认仍未接，故生产仍不可下单。深度生产开关 `TM_AI_DEEP_SUBMIT_ENABLED` 默认关闭；启用需创建开关、控制面 `ReadyDeep` 与原子限流器同时就绪，否则启动失败。

## 2. 选项

### A. 首发不开放深度（推荐）

- 首发范围：会话 + 资料问答 + 报告追问（如批准生产装配）+ 轻度资料整理 + 报告 + 反馈。
- 深度保持“暂不可用”，不展示假进度、不预留积分、不承诺交付。
- 优点：不引入未验证的 L2 质量与退款争议；先把已验收闭环跑稳。
- 代价：少一个高客单场景；需要后续用真实数据再评估。

### B. 受控内测深度（不公开计费）

- 仅指定内部/受邀账号，人工审批后创建；不公开价格、不扣真实用户积分。
- 必须记录：审批人、对象范围、任务上限、失败处理、关闭开关。
- 用途：收集真实多 Agent 质量、时延、成本数据，为 C 提供依据。
- 仍需决定：内测账号名单、任务上限、数据保留与对外表述。

### C. 公开发布 L2

在 B 取得真实质量数据并通过合规复核后再评估，至少需要以下决定：

| 必须决定 | 说明 |
|---|---|
| 正式价格与档位 | 积分/次或套餐；不得由客户端权重决定 |
| 最小交付物 | 章节数量、最少可追溯引文数、公司事实是否包含 |
| 质量阈值 | 逐字引文、蕴含/语义判定通过率、来源数量/时效、失败率上限 |
| 失败/取消/超时 | 全额释放、部分交付是否存在、重试次数与退款口径 |
| 范围 | 题材/专题、资料授权类别、模型与备案信息 |
| 容量与时限 | 并发、单任务时限、排队/降级策略 |
| 披露与审计 | AI 标识、模型/备案、人工复核与留痕 |

## 3. 建议

1. 首发采用 A；C-7 维持“明确不可用”。
2. 若需要商业化验证，先做 B，且只在隔离环境/内部账号，不向公众收费。
3. C 必须等待：真实 Agent/模型质量数据、法务对交付与退款的书面意见、正式价格与容量决定。

## 4. 不做什么

- 不因本 ADR 修改默认开关、价格、任务创建或积分逻辑。
- 不把本地回环测试、L1 报告或演示数据表述为 L2 已交付。
- 不在未决定前实现“看似可下单”的深度入口。
