# ADR-0028：专题档案版本与用途授权分离

## 背景

2026-10-30用户确认将AI目标扩展为专题档案、原文核验和版本变化，并在目标模式设置完整目标。原sources已管理不可变资料快照；qa范围包含问答策略摘要及模型执行语义；finalreport负责报告交付和当前授权。新增档案读取不能仅凭快照存在或问答范围存在就开放。

## 决定

1. 复用原来源、正文及快照，不新建另一套抓取/证据库。专题版本引用不可变快照和字段依据；专题版本与原报告分别保存，不覆盖历史、不改原结算。
2. 单文档文本比较先作为无权限、无发布能力的纯计算内核。它只比较同来源、同规范链接的采集版本，不推断事实更正、政策废止或业务进展。跨链接版本关系和事实差异需要另行显式绑定证据。
3. 专题档案按新用途建立明确的审核/发布批准与读取授权。问答批准、来源许可、档案发布批准及会员读取权限分别核验，不从一种权限隐式推导另一种。实现可复用原鉴权与数据库事务设施，不复制账户或账本。
4. 档案内容版本不可变，是否可读由当前授权决定。来源撤回或任一版本无权时，正文、摘要、引用和变化计数均不返回；历史曾经可读不能替代当前许可。比较必须先验证双方属于所选题材及用户读取范围。
5. 首批依托既有题材主数据，不把尚未接线的topic目录伪装可用。两至三个真实题材需资料许可和覆盖证据；合成样板独立于正式目录。原文展示继续经过固定模板、引文与发布规则，不把整个来源正文直接转发前端。
6. 手动档案查询/比较不执行模型或账务。新报告沿用原报价、用户确认、任务和终检结算；自动更新、推送和新套餐不由此次架构增量默认开启。
7. 首个接口只在显式本地隔离配置下注册。结构回滚探针使用独立准备连接，业务连接保持资料只读，两者必须是同一实例和专属库、不同账号；准备检查结束立即关闭连接。此方式仅用于本地验证，连接分离不等于操作系统进程隔离，准备凭据仍来自该进程环境，不能据此作为生产凭据隔离方案。生产启动批准和准备进程分离须另行设计验收。
8. 版本目录也复用单版原文重建和当前授权，在一个外层事务内借用读取流程，不复制另一套许可规则、不建立嵌套提交。分页只携带已复核可读版本的游标；有限扫描未结束时返回不可用，不把未检查历史当空结果。档案级比较按档案身份排序，支持旧快照回用；仅描述摘录/字段/出处/缺口变化，显式事实更正必须另有可核验的更正证据。

## 备选与后果

- 直接复用QA批准开放所有快照：减少表和校验，但扩大原用途且缺少版本发布语义，不采用。
- 为档案复制来源库、鉴权及账本：会产生不同授权时点和重复收费路径，不采用。
- 复用不可变快照，新增用途明确的版本与批准记录：采用。增加迁移、撤回竞争与授权读取测试；未完成前仅保留离线内核，不注册公开入口。

需求及验收以requirements第0.3节为准；具体字段、API、迁移和测试在design第13节与tasks的DR矩阵维护。本ADR记录实现方向，不代表新授权已取得或档案服务已完成。
