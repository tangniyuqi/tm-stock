# ADR-0018：模型判定先隔离，再纯回放终检

状态：开发接线；生产控制器与质量证明未就绪，真实调用默认关闭，无启动/公开装配。

## 背景

终检回调必须是纯校验。若在 Finalize 内直接请求模型，事务提交未知后重复终检可能再次消耗远端预算，且模型返回值不稳定；仅有词语共现和逐字回取也不足以证明章节含义或语义安全。

## 决定

1. 蕴含和语义使用独立的受限判定计划。输入由最终结构/证据绑定后生成，与终检使用同一构造函数；蕴含接候选与本任务正文，语义只接最终可见文字，不含来源全文/URL/授权归档。
2. 固定无工具系统提示、严格 JSON Schema、64输出 token、一次尝试、无重试/路由。直连适配器无代理/重定向，16KiB响应上限；HTTP只限显式回环评估，非秘密端点/模型/时限摘要必须匹配计划。判定只能是 `pass/block/uncertain` 与按类型封闭的理由码。模型/终止原因/回执/真实用量异常、估计用量、错误/未知字段均不能变成通过；供应商原文不进入最终报告。
3. 独立 `AIReportCheckWorker.RunOwned` 在既有租约内执行一个判定步骤；`ReserveStep` 在原事务内限制步骤序号与固定键，再调用前审计、模型、调用后审计、隔离 Capture/Complete。先预留再调用，只允许 `NewlyReserved` 发起；提交未知/缺响应保留原键，不自动补发。独立心跳贯穿网络，旧围栏不能写，新围栏可复用已捕获结果。
4. 原隔离阶段表保存受限响应，不新建模型执行表。判定步骤使用 `judge` 类型，但不表示报告已合格；最终独立的候选 judge 检查点才进入 ADR-0016 的报告/任务/账本原子事务。预算是保守上界，最终本地候选提交步骤的预留不冒充真实调用数。
5. 计划绑定任务号，蕴含另绑定主题编号；执行核对实际用户/任务，直连客户端模型不可覆盖，不能跨任务组合两道判定。`CheckEvidence` 只持已捕获的不可变判定；`NewCapturedPolicy` 校验实际提示/Schema/模型/审批/质量/硬预算配置版本，按输入哈希回放，不能访问 Provider。蕴含不通过可不调用语义；缺语义绝不补造一次调用，纯回调保持 uncertain。终检重放不会再次发起模型请求。

## 后果与剩余关口

- 必须显式提供当前准入和持久审计控制器；非空归档引用不构成许可、质量或远端硬预算的证明。仓库没有生产放行控制器，也没有默认通过策略；测试控制器和本地模拟服务只在测试文件中。
- 当前闭环测试可使用真实 SQL 阶段/账本及显式模拟模型验证，但不能证明真实模型的中文金融判定质量、实际成本或远端停止状态。
- 统一任务编排仍须衔接 Agent、选择器、判定与最终提交，并处理转换前/调用中/终检前的来源撤回。会员报告读取、公开发布门禁与本地页面验收另需完成。
- 随套件增长，将原生与 CI 的整包测试看门狗显式设为每轮20分钟；单次 SQL、网络、租约和业务期限不变，原超时/上下文失败证据保留，不以时限调整掩盖断言失败。
