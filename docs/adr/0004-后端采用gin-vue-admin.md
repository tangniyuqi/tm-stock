# ADR-0004：后端采用 gin-vue-admin v3.0.0（购买 BSL 商业授权）

- **状态**：已采纳
- **日期**：2026-07-30
- **决策人**：董事长
- **相关**：`.claude/agents/backend-standards-go.md`

## 背景

后端需要一套成熟底座，而不是从零搭 Gin 分层。候选是
[gin-vue-admin](https://github.com/flipped-aurora/gin-vue-admin)（24.9k star）。

它提供：Gin 1.9 + GORM + Casbin RBAC + JWT + Redis + Viper + Zap + Swagger +
**代码生成器** + Vue3/Element Plus 后台前端。

对本项目而言最有价值的是**运营后台**能力——董事长明确"题材核心在于维护这个库"，
题材库的录入、审核、权限、依据字段管理正是 GVA 擅长的部分。

## ⚠️ 许可证陷阱（决策的关键约束）

**gin-vue-admin 于 2026-05-28 从 Apache 2.0 切换为 Business Source License 1.1。**

| 版本 | 发布日期 | 协议 | 商用 |
|-----|---------|------|------|
| v2.9.2 | 2026-05-26 | Apache 2.0 | ✅ 永久免费 |
| v2.9.2-stable / **v3.0.0** | 2026-07-17 | **BSL 1.1** | ❌ **须购商业授权** |

BSL 1.1 关键条款：
- Licensor：北京翻转极光科技有限责任公司
- **"You may not make Production Use of the Licensed Work except as expressly permitted
  by a separate commercial license obtained from the Licensor."**
- Change Date：每个版本发布后 **3 年**自动转为 Apache 2.0
- 商务联系：business@gin-vue-admin.com

**Additional Use Grant 允许的开发期用途**（不需付费）：
内部技术评估测试，且**不处理真实用户/业务数据**、**不支持实际业务运营**、
**不部署给第三方**、**不可公网访问**。

## 决定

**采用 v3.0.0 并购买 BSL 商业授权。**

理由：能持续获得更新与官方支持；不必为规避协议而钉死在两个月前的旧版上。

### 🔴 由此产生的强制义务

| 义务 | 时点 | 状态 |
|-----|------|------|
| 联系 business@gin-vue-admin.com 完成商业授权采购 | **公网上线前必须完成** | ⛔ 未完成 |
| 保留版权声明与许可证副本 | 引入代码时 | ⛔ 未开始 |
| 授权凭证归档（合同/发票）到公司法务留存 | 采购后 | ⛔ 未开始 |

**开发期红线**：授权采购完成前，GVA 代码**只可用于内部开发与评估**——
不接真实用户数据、不对公网开放、不部署给第三方。
**违反 = 侵权**（这与合规红线是两类风险，但同样是公司级）。

## 架构边界（已定 · 2026-07-30）

GVA 的 `sys_user` + Casbin 是为**后台运营人员**设计的；
而 C 端是**手机号注册的会员**，两套用户体系不同、并发特征也不同
（C 端高并发只读 + 缓存，后台低并发读写 + 强权限）。

因此建议：

```
server/
├── admin/     ← gin-vue-admin 底座：题材库维护、依据录入与审核、运营账号 RBAC
└── api/       ← 独立 C 端服务：题材查询、快讯、会员；共享 model 与 repository 层
```

- 后台与 C 端**分服务、共库、共 model**
- C 端不引入 Casbin，用轻量 JWT 会员鉴权
- C 端可独立扩容，不被后台框架绑架

**为什么不合成一个服务**：

1. **两套用户体系**。`sys_user`（运营人员，Casbin 细粒度权限）与 C 端会员
   （手机号 + 订阅状态）在鉴权模型、生命周期、风控要求上都不同。
   混在一个服务里迟早出现"用后台中间件保护 C 端接口"这类错配。
2. **两种负载形态**。C 端是高并发只读 + 重缓存；后台是低并发读写 + 强权限校验。
   合在一起时，后台的一个慢查询能拖垮 C 端。
3. **合规隔离**。C 端是**用户可见面**，禁用词扫描、依据完整性过滤、付费墙判定
   都集中在这里；边界清晰才检查得干净。
4. **降低 BSL 牵连面**。GVA 代码集中在 `admin/`，C 端不引入它——
   万一将来协议或授权出问题，要替换的范围是可控的。

**代价（接受）**：共享 model 层需要约定归属，避免两边各改一份。
约定：`model/` 与 `repository/` 为共享层，**变更须同时跑两边的测试**。

## 后果

**正面**：运营后台白拿一套成熟 RBAC + 代码生成器，题材库维护后台可快速成型。

**负面**
- 新增一笔商业授权费用（金额待询价）
- 上线前多一道**必须闭环**的采购动作，漏掉即侵权
- 绑定该框架的升级节奏与技术选型（Element Plus、GORM）
