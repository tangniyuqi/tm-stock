# ADR-0001：采用 ADR 记录架构决策

- **状态**：已采纳
- **日期**：<YYYY-MM-DD>

## 背景

架构决策（选型、分层、取舍）如果只存在于聊天记录和人的脑子里，
半年后没人记得"当初为什么这么做"，于是被随意推翻或重复讨论。

## 决定

重大技术决策写成 ADR，存放于 `docs/adr/NNNN-<标题>.md`，包含：
**背景 / 候选方案 / 决定 / 后果（含负面）**。

## 什么算"重大"

- 引入或替换关键依赖、框架、中间件
- 数据模型或 API 契约的重大变更
- 影响多个模块的分层/边界调整
- 有明显取舍、且未来可能被质疑的选择

## 后果

- ✅ 决策可追溯，新人能读懂"为什么"
- ✅ 避免同一问题反复讨论
- ⚠️ 需要纪律：决策当下就写，事后补写基本写不出来
