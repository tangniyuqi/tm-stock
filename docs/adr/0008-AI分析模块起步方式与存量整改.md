# ADR-0008：AI 分析模块——L0 内部先行，并先清理存量冲突

- **状态**：已采纳（D11 待裁决；D14 为独立专项）
- **日期**：2026-10-02
- **决策人**：用户（2026-10-02 会话中确认"按推荐"启动阶段 0 与阶段 1；同日确认 D16 按推荐下线、AC-G2 分两层并在阶段 4 前补第二道防线、〔2012〕40 号条号更正）
- **相关**：[ADR-0003](0003-个股客观事实层可做.md)、[ADR-0004](0004-后端采用gin-vue-admin.md)、
  [ADR-0005](0005-一期不做AI分析.md)、[ADR-0006](0006-G1最小验证路径.md)、
  [ADR-0007](0007-复用现有addon_quant数据表.md)；规格 `docs/specs/ai-analysis/`
- **与 ADR-0005 的关系**：**不取代**。面向公众的 AI 分析仍受 ADR-0005 的七项前置条件约束；
  本决定只放行**不对外的 L0 内部证据抽取助手**，并规定对外 L1/L2 的关口。

## 背景

商业方向已确认：轻度 AI、深度多 Agent AI 按任务消耗积分，结果可溯源，不输出个股投资评价。
ADR-0005 的核心反对意见——生成模型是概率性的，而合规上"一次输出就是一次违规"——仍然成立。
本方案的回应不是压低概率，而是**把概率性挡在展示层之外**：模型只做抽取与二分类判定，
输出经确定性校验后由代码模板渲染，展示层没有自由文本。

2026-10-02 对现状做了实地取证（`docs/specs/ai-analysis/requirements.md` 第 2 节，F1–F15）。
其中四项直接动摇既有 ADR 的前提：

1. GVA 里的 AI 入选逻辑输出"梯队（龙头/跟风/边缘）"与"相关度"，结果以启用状态直接入库，
   无依据、无审核，并经 C 端 DTO 展示——与 ADR-0003 的"无依据禁止入库""不评价"相冲（F1–F4）。
2. GVA 的 `AutoMigrate` 注册了 `addon_quant_theme_stock`：会静默削弱依据约束（NOT NULL、CHECK、默认值），
   或建出没有依据列的旧形态；ADR-0007 记录的"上线库当时没有该表"已经过期（F7）。
3. 后台与 C 端共用同一把签名密钥与 claims 结构，会员令牌不带类型，`ClientJWTAuth` 只验签名——
   后台令牌会被当成同号会员；ADR-0004 早已预见这类错配（F9）。
4. 基础股票 AI 分析为每只股票生成基本面、财务、业绩兑现等评价类文本，存入共用表，并经免鉴权的开放接口原样返回（F15；已由 D16 下线）。

## 决定

D1–D10、D12–D16 采纳推荐方案（D16 是实施中新发现的一项，2026-10-02 经用户确认按推荐处理）；D11 待用户裁决；D14 作为独立专项。

| 编号 | 决定 |
|---|---|
| D1 | 第一个交付对象是**内部 L0 证据抽取助手**，不对外 |
| D2 | 模型只用国内已备案的模型 API（走"登记"）；C 端禁用境外模型 |
| D3 | MVP 输出为结构化证据档案，**没有自由文本段落**；受限自由句待质量达标并经律师确认后再议 |
| D4 | AI 不生成任何关于个股的句子；个股只由代码模板渲染"归属事实 + 涨跌幅 + 依据" |
| D5 | 积分账本放在 `server/`，用 `tm_` 前缀的专用表；GVA 旧积分字段废弃或只读镜像 |
| D6 | `server/` 校验 GVA 签发的 JWT，并按令牌类型隔离（见下） |
| D7 | 共表以本仓库迁移为准：GVA 不再迁移 `addon_quant_theme_stock`，写入走"依据 + 审核"流程 |
| D8 | 下线 GVA 存量 AI 的梯队、相关度、龙头输出与 C 端暴露；以后在 `server/` 按 L0 重建 |
| D9 | 实测之前不定价；价格由实测成本按公式给出，任务级锁价加硬上限 |
| D10 | 赠送积分不参与贡献分成 |
| D12 | 终检通过才结算，不通过全额释放（二值，无部分结算） |
| D13 | 恢复 `docs/adr/` 并补记本 ADR |
| D14 | 广告业务与新规作为独立专项交律师评估；**AI 与广告严格隔离** |
| D15 | L0 的人审先走脚本与 CSV；GVA 界面待确认 BSL 授权后，才用于真实业务数据 |
| D11 | **待定**：非会员能否单买积分、使用 AI |
| D16 | 下线基础股票 AI 分析（`ai_analyze`，F15）：停止生成与写入五个评价类字段和分析时间；历史值保留在库里，但不再从任何接口输出；删除不再有调用方的大模型调用与联网搜索代码 |

## 本决定带来的硬规则

### 1. 共表治理（D7）

- 权威定义是 `server/migrations/20260730_addon_quant_theme_stock.sql`；已被旧 GVA 改坏或建成旧形态的库，
  用 `server/migrations/20261002_converge_addon_quant_theme_stock.sql` 收敛（幂等；没有依据的旧行整表封存，
  **不伪造依据**；认不出的形态主动中止）。两处建表定义必须一致，由测试逐项比对。
- 部署顺序：**先**部署已从 `AutoMigrate` 移除该模型的新版 GVA，**再**执行收敛迁移；
  旧版 GVA 一旦重启，表会再次被改坏，重跑收敛迁移即可。上线库须先做只读核查（`scripts/ops/theme-stock-audit.sql`）。
- GVA 写路径：新建一律为草稿；改动关键字段或依据会把记录重置为草稿并清除审核人（不能在同一次编辑里自审通过）；
  驳回必须写理由；通过要求依据洁净（无占位文字、无禁用词、链接与时点合法）。
- C 端可见 = `audit_status = 2 AND status = 1 AND deleted_at IS NULL AND 依据非空`，且题材与股票均未删除；
  排序只用股票代码，不用人工权重；后台列表返回全部状态，**不得**直接喂给 C 端。
- 机检守卫：`TestAutoMigrateNeverRegistersThemeStock`、`TestThemeStockDDLInSyncBetweenMigrations`、
  `TestIntegration_Converge_*`（需 MySQL）、`TestThemeStockRouterNoPublicDataEndpoints`、
  `TestClientThemeDTOHasNoEvaluativeFields`。

### 2. 令牌类型隔离与签名密钥（D6）

- 令牌：HS256；payload 的键名是 Go 字段名（`ID`、`UserType`、`AuthorityId` 首字母大写），
  另有 `iss`、`aud`（`["GVA"]`）、`exp`、`nbf`。后台令牌 `UserType=admin`；会员令牌 `UserType=client` 且不带后台角色。
- 中间件**只认白名单**：`JWTAuth` 只放行 `admin`，`ClientJWTAuth` 只放行 `client`；
  类型为空或未知一律拒绝，**不做兼容放行**——兼容分支会变成永久绕过口。
  代价：部署后已登录的会员需重新登录一次。
- `server/` 的 C 端接口同样只收 `client`，并校验 `iss`、`aud`、`exp`、`nbf`；内部管理接口不走用户令牌（见 design.md 2.4）。
- 签名密钥：仓库内只放占位符。GVA 的 `config.yaml`（initdb 生成，现已加入 `.gitignore`）由部署流程从密钥库渲染——
  GVA 自己不读环境变量；`server/` 读环境变量 `TM_JWT_SIGNING_KEY`。两边必须是同一个值；本机放 `~/.tmstock-credentials`。
- 轮换：GVA 只验一把密钥，所以切换密钥的那一刻**所有现有会话（后台与会员）失效**，这是已知代价。
  `server/` 侧应支持新旧两把密钥验签的过渡窗口（`TM_JWT_SIGNING_KEY_PREVIOUS`）。顺序：先发布 `server/`，
  再切换 GVA，旧密钥保留不少于令牌有效期（GVA 的 `jwt.expires-time`）后移除。怀疑泄露时立即轮换，不等窗口。
- 机检守卫：`middleware/token_type_test.go`、`service/member/auth_token_test.go`、`router/client/member_router_test.go`
  （含"后台令牌同号冒充会员"与"类型检查先于查库"）。

### 3. 词表与门禁

词表单一源是 `scripts/compliance-forbidden-words.txt`，只增不删。GVA 与 `server/internal/ai/guard` 各嵌入一份副本，
由 `scripts/sync-guard-words.sh --check` 守卫一致；含违规措辞的测试夹具放 `eval/`，不放进被扫描的源码目录。

### 4. 评价性文字不得经任何接口输出；第二道防线（D16、AC-G2）

- 四类 AI 任务（`ai_add`、`ai_update_one`、`ai_update_batch`、`ai_analyze`）全部下线：遗留任务落成失败、不能重启，
  入口、路由、后台页面与大模型调用代码已删除。
- 基础股票上的六个遗留列（`fundamentals`、`financial`、`realization`、`momentum`、`risk`、`ai_analyzed_at`）：
  历史值保留在库里，模型上标 `json:"-" form:"-"`，任何接口都带不出、也写不进——含免鉴权的 `getBaseStockPublic`
  （它此前直接复用后台列表，会把这些文字原样返回给任何人）。恢复这些文字的展示必须先经律师确认并加红线终检。
  守卫：`TestBaseStockLegacyAnalysisColumnsNeverSerialize`、`TestBaseStockPublicEndpointNeverExposesLegacyAnalysis`、
  `TestRetiredAiTaskTypeSetIsExactlyTheFourKnownTypes`。
- 确定性层对 HTML 数字实体与 `\u` 转义"出现即拦"（不解码）；谐音、拼音、emoji、Base64 与纯语义改写仍拦不住，
  由**第二道防线**（语义分类器 + 抽检）承接：契约与门槛见 design.md 3.4.1，任务 P4-0，
  **未达标不得向公众开放 L1/L2**；AC-G2 因此分两层验收。第二道防线需要模型 API 账号，目前只有契约，没有实现。

## 后果

**正面**

- 合规命门（依据 NOT NULL + CHECK）不再被另一个系统的启动悄悄削弱。
- 后台令牌冒充会员的口子关闭，后续的资金型资产（积分账本）有了可信的身份基础。
- 先做 L0 直接降低"题材库与依据采集"这项唯一真正的工作量，且不触发对外 AI 的备案与关口。

**负面（正视）**

- 收敛迁移会把旧 GVA 形态表里没有依据的行封存：C 端的题材股票列表可能暂时变空、"热度"（可见股票数）归零，
  直到内容团队带着真实依据重新录入。
- 下线 GVA 的 AI 选股与基础股票分析，运营少了"快速出初稿"的入口，直到 L0 在 `server/` 重建；
  基础股票上已有的 AI 分析文字不再可见（历史值保留）。
- 令牌类型强制检查会让已登录的会员在部署后重新登录一次。
- 多了需要长期维护的东西：两份词表副本、`server/` 与 GVA 的密钥同步、MySQL 8.0 与 9.x 两个版本的验证。
- 对外的 AI 上线仍被一串**外部动作**卡住（律师书面意见、模型登记、来源授权、BSL 授权），技术方案不能替代它们。

- D11 待裁决；D14 独立专项。
- 监管文件跟踪清单（`docs/监管跟踪清单.md`）已建，**负责人尚未指定**（P0-7 验收要求有负责人）。
- 第二道防线（P4-0）未实现，也没有任何实测数字；公开上线前它是硬关口。
- GVA 启动时仍要求 `config.ai.yaml` 存在（`loadAIConfig` 缺失会 panic），但其中的大模型 API 密钥已没有任何代码使用：
  部署环境可以换成不含密钥的占位文件；彻底移除加载器与 `config.AI`、`config.WebSearch` 另列，本次没做。
- GVA 在免鉴权分组上还注册了大量"开放接口"（bi 12、quant 21、cloud 4、cms 4、system 3、addon 1 条），
  其中有真实行为的未逐一核查：已知 `getAccountPublic` 按 id 返回整条账户记录（含资金账号与交易密码字段）、
  快讯与交易记录的 `createPublic` 免鉴权写入、问财 `query` 免鉴权代理——另起安全专项处理，不在本决定范围内。
- GVA 的 BSL 商业授权是否已采购：仓库内没有任何凭证，状态未知（ADR-0004 记为未完成）。
- 实测基线（P1-7）需要模型 API 账号与"评估用途来源"的法务确认；**实测之前不报价、不写成本数据**。
- 上线库（MySQL 9.7.0）的实际形态未核查，收敛迁移须先在副本上演练。本机已在 8.0.46 与 9.7.0 上把迁移、集成测试和只读核查脚本各跑过一遍，结论一致——这说明脚本在两个版本上行为一致，不说明上线库里是什么。
- `/client/theme/*` 等 C 端公开接口仍无需登录；本决定不改变这一点，是否上付费墙另议。
- CI 目前只在 MySQL 8.0.x 上验证（本机两个版本都跑过），9.x 的 CI 作业排在阶段 3（P3-4）。
