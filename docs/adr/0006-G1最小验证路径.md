# ADR-0006：一期先跑 G1 最小验证路径

- **状态**：已采纳
- **日期**：2026-07-30
- **相关**：[GOALS.md](../GOALS.md) G1、[ADR-0003](0003-个股客观事实层可做.md)
- **影响**：五份 spec 的任务从 **80 项**收敛到 **37 项**（-54%）；
  上线前置义务从 **7 项**降到 **4 项**

## 背景

截至目前已产出五份完整规格：`theme-query` / `theme-daily` / `flash-news` /
`admin-console` / `member-center`，合计 **80 个任务**、**22 处 ⛔ 阻塞**。

这与"一期 MVP 从简"的定调不符，也与 G1"先验证再开发"的顺序相冲突。
**规格写全是对的，但不等于要全做。**

## 🔑 首先：G1 要验证的问题已经变了

GOALS.md 里 G1 的原始表述建立在**旧红线**上：

> "合规裁定后，一期只能做题材/行业客观信息（**不含个股**），
> 这部分接近大厂免费层已有的内容 —— 愿不愿为它付费尚未被证明。"

[ADR-0003](0003-个股客观事实层可做.md) 推翻了"不含个股"，**产品变了，待验证的假设也必须跟着变**：

| | 旧假设 | 新假设 |
|---|-------|-------|
| 卖什么 | 阉割版题材信息（无个股） | 题材 → 环节 → 成分股 + **归属依据** |
| 验什么 | 有人为**阉割版**付费吗 | 有人为**"可审计的题材库"**付费吗 |
| 对手免费给什么 | 几乎全部 | 成分股列表 + 涨跌幅 |
| 我们独有什么 | **几乎没有** | **每家公司凭什么归到这个环节，有原文可查** |

**G1 的新命题**：
> 用户愿不愿为「**依据可查**」付钱——即知道"茂莱光学被归入光源环节，
> 是因为 2025 年报披露该业务收入占比 34.2%"这件事，值不值 ¥29/月。

## 🔪 由此推出的第一刀：涨跌幅不做

如果差异化在**依据**，那**涨跌幅就不是差异化**——它是大厂免费层遍地都有的东西。
做它：
- 不增加任何付费理由
- 却要付**行情数据商用授权年费**
- 还要把上线时点绑在签约进度上

**砍掉它，验证效力毫发无损，却直接移除一项前置授权阻塞。**
（`quote.enabled=false` 这个开关在 `theme-query` 设计里已经预留。）

## 决定

### 阶段 0：无开发验证（先行，GOALS G1 原定做法）

内容（小红书）+ 私域（知识星球 ¥29/月 concierge 人工交付）。
**人工交付的正是"题材 + 环节 + 成分股 + 依据原文"**——与产品化后的价值主张一致，
所以它测的是同一个假设。

**原定：只有阶段 0 达标（≥30–50 人真金付费 + 次月续费 ≥50%），才进入阶段 1。**

### ⚠️ 2026-07-30 修正：门改为「按投入类型分级」，而不是一刀切

董事长决定**并行推进**：阶段 0 尚未启动，阶段 1 代码即刻开始。
原文那句"只有阶段 0 达标才进入阶段 1"若原样保留，就成了**一条没人执行的门**——
文档里挂着不被遵守的规则，比没有规则更糟（会连带削弱其他规则的可信度）。

因此改为按**投入是否可回收**分级：

| 投入类型 | 是否受阶段 0 门限制 | 理由 |
|---------|-----------------|------|
| 数据模型 / 迁移 / 分层骨架 | ❌ **不受限，可立即做** | 任何路径都需要，验证失败也不浪费 |
| 依据机制（存储 + 过滤 + 接口 + 浮层） | ❌ **不受限** | **它就是被验证的东西本身**，不做就没得验 |
| 合规守护与门禁 | ❌ **不受限** | 属 G2 地基 |
| **题材库大规模内容录入** | ✅ **受限** | 纯人工、不可回收，是真正的沉没成本 |
| **公网上线 / 运营投放 / 收款开张** | ✅ **受限** | 触发 ICP、PIPL、律师复核等前置义务 |

**一句话**：**写代码可以并行，砸人力和上线不行。**
真正昂贵且不可回收的是"人工采集几百条依据"与"上线运营"，
而不是把表建好、把过滤逻辑写对。

### 阶段 1：最小产品（阶段 0 达标后才启动）

| 需求 | 处置 | 说明 |
|-----|------|------|
| `theme-query` | ✅ **做，但简化** | 砍三级分类下钻（改为题材列表 + 搜索）、砍行情 |
| `member-center` | ✅ **基本全做** | 登录 / 兑换码 / 注销 —— 收钱与续费归属的必要条件 |
| `admin-console` | 🔻 **降级为脚本** | CSV 导入器 + 兑换码生成脚本，**不上 GVA 后台** |
| `theme-daily` | ❌ **不做** | 依赖行情快照；引流走站外 |
| `flash-news` | ❌ **不做** | 引流走小红书/知识星球；且卡第三方授权 |

### 保留的核心（一项都不能少）

1. 题材详情页：**题材 → 产业链环节 → 成分股**
2. **归属依据浮层**（来源类型 + 原文摘录 + 原文链接 + 采集时点）← **这就是被验证的东西**
3. 付费墙 + 试吃
4. 手机号登录 + 兑换码激活 + 账号注销
5. **题材库内容与依据采集** ← 唯一真正的工作量

## 📉 由此解除的阻塞（最大收益）

| 前置义务 | 原状态 | 最小路径下 |
|---------|-------|-----------|
| gin-vue-admin **BSL 商业授权** | ⛔ 必须购买 | ✅ **不需要**（不上 GVA，C 端是纯 Gin 服务） |
| **行情数据商用授权** | ⛔ 必须签约 | ✅ **不需要**（不展示涨跌幅） |
| **第三方快讯源授权** | ⛔ 必须取得 | ✅ **不需要**（不做快讯） |
| 网站 ICP 备案 | ⛔ | ⛔ 仍必须 |
| PIPL / 隐私政策与协议 | ⛔ | ⛔ 仍必须 |
| 持牌律师书面复核 | ⛔ | ⛔ 仍必须（**且是最高优先**） |

**三项要花钱、要签约、周期不可控的授权，全部移出关键路径。**

剩下四项里，只有律师复核是真正的前置门槛——它本来就该最先做。

## 为什么不连账号体系一起砍

考虑过更激进的方案：**不做登录，输兑换码直接解锁（存本地）**。
这能再省 6 个任务并大幅降低 PIPL 义务。**但否决了**：

1. **G1 的生死线指标是"次月续费 ≥50%"**——没有账号就无法归属订阅与续费，
   等于砍掉了要测的核心指标。
2. 付费产品在用户换设备后失去访问权，会直接产生退款纠纷。
3. PIPL 的成本是**任何要收钱的产品迟早都要付的**，提前付掉比事后补便宜。

## 后果

**正面**
- 任务量 **80 → 37**（-54%）。口径：

  | 需求 | 全量 | 最小路径 |
  |-----|-----|---------|
  | `theme-query` | 19 | **16**（3 项不做、2 项降级） |
  | `member-center` | 18 | **18**（1 项降级，不减数） |
  | `admin-console` | 20 | **3**（降级为 CSV 导入 + 兑换码生成脚本） |
  | `theme-daily` | 14 | **0** |
  | `flash-news` | 9 | **0** |
  | **合计** | **80** | **37** |

  > 砍幅看着不如预期大，是因为 `member-center` 几乎砍不动——
  > **收钱这件事本身就有固定成本**（登录 + PIPL + 激活 + 注销）。
  > 真正被砍掉的是"产品看起来完整"的部分，不是"能不能收到钱"的部分。
- 三项授权阻塞移出关键路径，上线不再被签约周期绑架
- 资源集中到唯一真正的护城河：**题材库与依据采集**

**负面（正视）**
- 首页会比较空（无快讯、无题材动态），产品观感偏单薄
- 运营录入靠 CSV 脚本，**效率低于后台界面**，且缺审核流
  → 三重防线只剩两层（导入器校验 + DB CHECK），**审核靠人工抽检补**
- 若阶段 0 达标后要快速铺量，后台仍需补建

## 被推迟的东西并未作废

`theme-daily` / `flash-news` / `admin-console` 三份规格**保持有效**，
只是**排到阶段 1 之后**。规格已写好，届时可直接开工，不需要重新设计。

> ⚠️ 唯一有时间敏感性的是 `theme-daily` 的**每日快照**——
> 数据起始日 = 任务首次运行日，之前补不回来。
> 但它依赖行情授权，而行情已被砍出最小路径，
> 因此**快照的起点自然被推迟到行情签约之后**，这是可接受的代价。
