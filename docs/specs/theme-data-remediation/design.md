## 1. 设计目标

以“来源可查、归属可查、状态诚实”为优先级，重建两个受影响页面：

1. **首页题材动态**：免费展示已审核的事件标题、题材标签、来源与发布时间。
2. **题材详情**：免费显示题材顶层信息；获得服务端权限后，显示折叠的产业链、客观股票标识和“查看依据”入口。

本设计刻意不使用原始上游的相关度、分层、模型理由、个股分析字段，也不在行情授权前展示任何涨跌数值。

## 2. 数据流与安全边界

```text
上游量化接口
    ↓（仅服务端读取；超时、限流、字段白名单）
隔离适配层
    ↓（丢弃评价/模型/详情字段）
审核与证据库
    ↓（来源、链接、审核、四项归属依据均完整）
本项目 /api/v1/*
    ↓（鉴权、分页、时间戳、缓存）
uni-app x H5 页面
```

浏览器不可越过本项目 API 访问上游。数据库中的原始入站数据与 C 端可发布数据分层保存，避免后续“为了方便”把未经审核字段透传到页面。

## 3. 页面规格

### 3.1 首页题材动态（`pages/index/index`）

**入口**：底部“首页”。

**顶部结构**：

- 标题“题材动态”；副标题只说明公开信息整理范围。
- 日期栏：上一日、当前日期、下一日。未来日期不可点。
- 排序提示常驻：一期固定“按发布时间排序”。行情授权并通过合规评审后，才允许增加客观的题材快照排序。
- 日期选择采用平台原生 `picker`（限制在数据起始日与当前日期之间）；一期不额外实现月视图浮层，避免在 H5 与原生端维护两套日期状态。

**列表单元**：

| 字段 | 展示规则 |
|---|---|
| 标题 | 已授权原文转载或已审核的中性转述；最多两行 |
| 题材标签 | 显示题材名称；点击进入 `/pages/segment/detail?id={themeId}` |
| 来源 | 必填，显示来源名称 |
| 时间 | 使用内部毫秒时间戳格式化；缺失数据不发布 |
| 原文 | 明确的外链入口；无有效 URL 时整条数据不发布 |

**状态**：加载骨架、当日非交易日、当日无动态、早于数据起始日、网络失败可重试。禁止使用最近交易日回填。

### 3.2 题材详情（`pages/segment/detail`）

**免费顶层**：题材名、客观说明、更新时间、来源说明。

**受限中层**：

- 每个产业链环节为可展开卡片；默认仅展开第一个环节，且不是按任何价值指标决定。
- 展开后展示股票的名称、代码、市场和“查看归属依据”按钮。
- `quoteEnabled=false` 时完全隐藏行情列；授权后才显示延时口径、数据时点和数值/`—`。
- 未登录、试吃可用、订阅有效、试吃耗尽的状态均由服务端 `locked` / `trialLeft` 驱动。遮罩只做体验，不承担安全职责。

**关联动态区**：只复用同样通过来源审核的事件；没有数据时不显示伪造时间线。

### 3.3 归属依据浮层（`pages/segment/components/ThemeEvidenceSheet`）

由“查看归属依据”按钮触发，不跳转到个股详情。

| 字段 | 规则 |
|---|---|
| 所属公司与环节 | 仅作当前映射的上下文，不加评价词 |
| 来源类型 | 公告、年报、招股书、官方目录或已核验的其他来源 |
| 原文摘录 | 审核后保存的原句，支持长文滚动 |
| 原文链接 | 仅允许已校验的 HTTPS 链接，显式确认后打开外部页面 |
| 采集时点 | 内部时间戳格式化的采集时点 |

四项证据任一缺失时，按钮和股票记录都不应出现。

## 4. C 端 API 契约

### 4.1 动态列表

`GET /api/v1/theme-daily/list?date=YYYY-MM-DD&sort=publishAt&page=1&size=20`

```text
ThemeDailyPage {
  date: string
  isTradingDay: bool
  emptyReason: "" | "NON_TRADING_DAY" | "NO_DATA" | "BEFORE_RANGE"
  dataFrom: string
  sort: "publishAt"
  list: ThemeDailyItem[]
  total: int
  hasMore: bool
}

ThemeDailyItem {
  id: int64
  title: string
  themeId: int64
  themeName: string
  publishAt: int64
  source: string
  sourceUrl: string
}
```

一期的动态 DTO 不含 `sentiment`、热度、置顶、评分、股票或行情字段。标题、来源和链接均来自审核库，不从上游响应直接透传。

### 4.2 题材详情与依据

保留既有 `GET /api/v1/theme/{id}` 和 `GET /api/v1/theme/{themeId}/stock/{tsCode}/evidence` 的方向，但其数据只能来自审核库。

`StockItem` 只允许：`code`、`tsCode`、`name`、`market`、`changePct`（允许为 `null`）、`hasEvidence`。不允许为“便利”加入上游任何嵌套对象或评价字段。

## 5. 上游字段处理表

| 上游字段 | 处理 | 原因 |
|---|---|---|
| 动态 `id`、`theme_id`、`theme_name`、`title`、`publish_time` | 候选入站字段，经过来源/审核/时间完整性检查后再发布 | 这些字段本身不足以证明可发布 |
| 动态 `source`、`url` | 发布必填；为空则拦截 | 需要来源与原文可查 |
| 动态 `sentiment`、`top`、`hot`、`heat` | 丢弃 | 不提供可审计的客观展示口径 |
| 股票 `stock.symbol`、`stock.ts_code`、`stock.name`、`stock.market` | 作为候选标识，先做名称/代码一致性校验 | 仅可用于客观标识 |
| 股票 `change_pct` | 授权行情源的替代实现完成前丢弃 | 缺延时、时点与商用授权信息 |
| 股票 `relevance`、`tier`、`reason`、`model_name` | 永久丢弃，不进入审核库的 C 端字段 | 评价、模型输出或主观解释 |
| 股票 `fundamentals`、`financial`、`realization`、`momentum`、`risk` | 永久丢弃 | 个股详情与分析边界外内容 |

## 6. 视觉规范

- 以 375px 宽度设计，内容左右边距 16px，卡片圆角 18px。
- 主色沿用现有产品品牌色 `#E93030`；琥珀色只用于资料完整性提示。页面不以品牌色承载涨跌暗示。
- 所有可点击元素最小 44×44px；信息按钮和外链必须有文本替代，不只依赖图标。
- 来源、时间、排序与权限说明是信息层级的一等公民，不能折叠到二级页面。
- 原型用“界面示意，非生产数据”角标，避免被误解为真实题材、股票或行情。

## 7. 实施顺序

1. 确认授权、审核责任、行情与会员前置决策。
2. 先实现服务端隔离适配、审核数据模型、证据校验和内部 DTO 合同测试。
3. 实现题材动态按日查询与空态，再把首页从静态入口替换为动态页。
4. 完成题材详情的折叠、权限与依据浮层；未经四项证据校验的股票始终不可见。
5. 取得授权后再单独评审行情接入，不能与页面布局整改混为一次上线。

## 8. 回退策略

- 来源、授权或审核失效：关闭对应数据源，页面退回真实空态。
- 行情源故障：只关闭行情区域或显示 `—`，不影响题材与依据数据。
- 法律意见收紧：关闭详情中层与依据入口，保留免费顶层信息。
- 上游字段变更：适配层合同测试失败即阻断发布，不让新字段直达 C 端。
