# 题材数据接入整改 · 需求规格

- **等级**：D（外部数据接入、合规边界与现有页面重构）
- **关联目标**：`docs/GOALS.md` G2；涉及 G1 的题材查询能力时，仍受 G1 验证结论与律师书面复核约束
- **状态**：既有前端整改曾完成 H5 开发运行态核验；本轮已补会员状态机、登录/兑换码/注销的受控交互结构，HBuilderX Web 编译命令已通过，关键状态运行/截图回归仍待完成；数据接入、会员后端契约与正式法律文本仍待完成
- **范围基线**：2026-08-20 对题材动态与题材股票两个上游接口的匿名只读核验；前端已按本规格完成原型对应页面和安全降级状态，仍不接入生产数据

## 1. 背景与边界

当前前端已具备题材动态首页、题材搜索页、题材详情页、归属依据浮层与会员页面框架；会员页面已补加载/错误/权限/受控关闭状态，本轮 HBuilderX Web 编译已通过，但关键状态运行/截图仍需核验；仍未形成可安全使用的“上游数据 → 审核数据 → C 端页面”链路。

本次核验的上游地址：

- `GET https://go.noooya.com/api/quant/themeTopic/list?page=1&pageSize=10`
- `GET https://go.noooya.com/api/quant/themeStock/list?theme_id=100166`

核验时没有携带 Cookie、Token 或其他鉴权头。以下结论只描述当次实际返回，**不能把上游当前字段当成稳定契约**。

整改后的边界必须保持：

1. 浏览器不得直接请求上述量化接口；C 端只请求本项目同源 `/api/v1/*`。
2. 个股只可呈现“名称、代码、经授权的延时行情（如启用）、归属依据入口”等客观事实；不呈现评价、预测、排序打分、模型理由、财务分析或个股详情。
3. 无来源、原文链接、审核状态或归属依据的数据宁可不展示，也不以推断、旧值或演示值补齐。
4. 行情授权未落地前，页面不展示任何真实或模拟涨跌数据。

## 2. 实测证据

| 观察项 | 实测结果 | 影响 |
|---|---|---|
| 题材动态首屏 | 返回 10 条；10/10 的 `source`、`url` 为空；4/10 的 `content` 为空；1/10 的 `publish_time` 为 `null` | 不能证明转载授权、无法给用户原文出处，且时间与正文都可能缺失 |
| 题材动态字段 | 有 `sentiment`、`top`、`hot`、`heat` 等字段；样本未给出可审计的计算口径 | 这些字段不能透传或作为排序、样式、高亮依据 |
| 题材股票接口 | 匿名请求即返回 16 条完整股票映射；传 `page=1&pageSize=3` 后才返回 3 条 | 若该地址对公网可达，会绕过题材详情的付费权限；服务端必须自行做鉴权与分页上限 |
| 题材股票字段 | 返回 `relevance`、`tier`、`reason`、`model_name`，并嵌套 `fundamentals`、`financial`、`momentum`、`risk` 等字段 | 同时违反产品边界与合规边界，绝不能进入 C 端 DTO |
| 归属依据 | 样本中没有 `source_type`、`source_excerpt`、`source_url`、`collected_at` 四项归属证据 | 无法证明“为什么该公司属于该题材”，不得展示为成分股 |
| 行情 | 仅有 `stock.change_pct`，没有授权主体、数据时点、延迟分钟数或失效策略 | 不得展示为行情；不能把缺失值当作 0 |
| 数据一致性 | 映射记录 `id=100474` 的文字说明与嵌套 `stock.name` 指向不同公司 | 现有上游不能被视为已校验的映射来源，需建立一致性校验与人工复核 |

## 3. 整改清单

严重度按“是否阻断对外展示”排序。所有 🔴 项关闭前，不得把对应数据接到正式 C 端。

| 编号 | 严重度 | 问题与证据 | 整改要求 | 验收结果 |
|---|---|---|---|---|
| R01 | 🔴 | 原始题材股票接口匿名可读，且包含拟付费的映射信息 | C 端仅访问本项目 API；上游地址移入服务端配置；题材详情和依据接口沿用服务端权限判定 | 浏览器网络请求中不出现 `go.noooya.com/api/quant/*`；匿名直调本项目付费接口返回受控结果 |
| R02 | 🔴 | `relevance`、`tier`、`reason`、`model_name` 是评价/模型输出而非客观归属依据 | 新建白名单 DTO；适配层显式丢弃上述字段，数据库审核流程也不得把它们转换成用户文案 | 契约快照与字段扫描均不存在这些字段；页面没有相应排序、标签或文案 |
| R03 | 🔴 | `reason` 中出现价值判断、未来推演和“待核实”内容 | 原始理由字段不得展示、不得作为归属依据；仅允许人工审核后的公开原文摘录 | 注入含评价、预测或待核实文本的原始记录后，C 端没有可见条目 |
| R04 | 🔴 | 股票映射缺少 `source_type`、`source_excerpt`、`source_url`、`collected_at` | 以 `addon_quant_theme_stock` 的四项证据字段为唯一展示门槛；缺一项即停在审核队列 | 缺任一证据字段的记录不进入详情和依据接口；完整记录弹层四项齐全 |
| R05 | 🔴 | 原始嵌套股票对象带基本面、财务、动量、风险等个股详情字段 | 适配层只取 `symbol`、`ts_code`、`name`、`market`；禁止透传嵌套对象 | API schema 与响应快照中不存在详情字段；无个股详情路由 |
| R06 | 🔴 | `change_pct` 缺少授权、延时、数据时点和失败口径 | 在授权合同、数据源、15 分钟延时和数据时点均落实前，服务端 `quoteEnabled=false`；前端不渲染涨跌区域 | 未授权环境响应不含可见行情值；授权环境每次均显示延时与数据时点，失败显示 `—` |
| R07 | 🔴 | 上游映射记录存在“文字说明公司”与 `stock.name` 不一致的样本（`id=100474`） | 入库时校验证券代码、名称、题材 ID、证据所指主体一致；异常记录转人工复核，禁止发布 | 构造名称/代码不一致记录后，发布任务失败并留审计日志；C 端不可见 |
| R08 | 🟡 | 上游默认列表的层级、相关度等可能影响顺序，且不具备可公开口径 | C 端默认按股票代码排序；若未来开放客观排序，白名单、口径和当前排序须常驻展示 | 改变上游 `relevance`/`tier` 不改变 C 端排序；非法排序参数返回 400 |
| R09 | 🔴 | 题材动态样本的来源与链接均缺失 | 动态发布前必须有来源名称、原文链接、发布时间和审核状态；缺失记录不发布 | 上游缺来源或链接的 10 条样本全部进入待补全队列，C 端动态列表为空态而非照常展示 |
| R10 | 🔴 | 题材动态含未定义的 `sentiment`、`top`、`hot`、`heat` 字段 | 适配层不存、不传、不使用这些字段；排序仅允许发布时间，行情授权后才可按题材快照的客观值排序 | DTO、SQL 和页面均无这些字段；排序白名单测试通过 |
| R11 | 🔴 | 原始动态标题可能含夸张、评价或前瞻措辞，且无来源可回查 | 仅发布“已授权原文转载”或“基于原文的中性转述”；两种模式均需来源、链接、审核人与时点 | 文案审核测试命中风险文本时不可发布；页面始终显示来源与原文入口 |
| R12 | 🟡 | 上游日期为 ISO 文本、`publish_time` 可空；提供的 URL 只明确了分页，未证实按日查询能力 | 内部契约统一毫秒时间戳；建立按日落库、交易日历和日期边界，不能用当前数据回填历史 | `null` 时间走“时间待补全、不可发布”；历史日查询只读该日快照 |
| R13 | 🔴 | 原问题的前端部分已修复：首页现有日期切换、日期选择、排序标识、分页及加载/空/错状态；真实列表仍依赖 R14 内部接口 | 按原型重做首页首屏为题材动态；无审核数据时展示明确空态，不用假数据 | 页面具备加载、非交易日、无数据、日期越界、网络失败和正常列表状态 |
| R14 | 🔴 | 当前服务只注册题材查询三条路由，未实现题材动态内部接口（`server/internal/handler/theme.go:65-67`、`server/cmd/api/main.go:79-83`） | 实现受控的 `GET /api/v1/theme-daily/list`，后端负责校验、分页、日期边界、来源过滤和契约收敛 | 合同测试覆盖正常、无数据、非交易日、越界、非法排序和超时降级 |
| R15 | 🟡 | 题材搜索/详情页调用的是现有 `/api/v1/theme/*` 契约（`pages/libs/theme-api.uts:79-94`），与上游两种返回结构不兼容 | 保持前端只认识内部 DTO；服务端通过审核库而非直接把上游 JSON 转给页面 | 原始上游增加无关字段时，C 端响应快照不变；字段白名单测试通过 |

## 4. 功能需求与验收标准

- [ ] **AC1（隔离）**：H5 运行时不会请求上游量化地址；所有页面只调用同源 `/api/v1/*`。
- [ ] **AC2（白名单）**：动态 DTO 只含已审核的 `id`、标题、题材 ID/名称、发布时间、来源、原文链接；股票 DTO 只含允许的客观标识、行情状态和依据入口。
- [ ] **AC3（来源）**：来源名称、原文 URL、发布时间、审核状态任一缺失时，动态记录不对 C 端返回。
- [ ] **AC4（归属依据）**：股票映射四项证据任一缺失时，详情与依据接口均不返回该股票；完整记录的依据浮层四项可见。
- [ ] **AC5（数据一致性）**：代码、名称、题材、证据主体不一致的映射不能发布，并可在审核后台定位原因。
- [ ] **AC6（行情）**：未授权时不显示数值；授权后显示“延时 15 分钟”和数据时点；缺失或失败时显示 `—`，不显示 0 或旧值。
- [ ] **AC7（动态页）**：首页支持日期切换、未来日期禁用、按发布时间排序、来源展示、题材标签跳转以及加载/空/错状态。
- [ ] **AC8（权限）**：动态页免费；题材详情顶层免费；产业链、股票和依据均由服务端统一判定订阅/试吃权限。
- [ ] **AC9（合规）**：C 端页面、DTO、缓存和日志不包含模型理由、评价分层、个股基本面/财务/风险/技术指标字段；全量合规词检查通过。
- [ ] **AC10（性能与分页）**：动态首屏 p95 小于 800ms、题材详情 p95 小于 1s；服务端强制 `page`/`size` 边界并返回 `hasMore`。
- [ ] **AC11（回归）**：后端单元/合同测试、前端 H5 编译、接口 mock 测试、截图回归及 `bash scripts/harness-checks.sh` 全部通过。

## 5. 不做什么

- 不把上游 `reason` 改写后作为用户文案，也不把 `relevance`、`tier` 改名后保留。
- 不展示原始接口中嵌套的财务、风险、动量、技术指标、AI 分析等个股详情。
- 不在授权未落实时展示涨跌幅、成交额或历史行情图。
- 不新建个股详情页、个股推荐、收藏、提醒或交易入口。
- 不用“最近数据”填补历史日期、非交易日或缺失时间。

## 6. 前置决策与依赖

| 事项 | 需要确认的结论 | 未确认时的处理 |
|---|---|---|
| 上游商用授权 | 动态内容、原文链接与行情是否可在 H5 商用展示，授权范围和期限是什么 | 不发布相应内容；页面显示空态 |
| 内容审核责任 | 谁审核来源、标题中性性、题材归属与四项证据 | 记录停留待审核，不能流入 C 端 |
| 行情授权 | 授权主体、延时要求、数据时点、缓存和审计要求 | `quoteEnabled=false` |
| 会员与试吃 | 用户身份来源、每日额度与兑换码流程 | 前端状态结构已落地；服务端保持 fail-closed，不开放真实付费层 |
| 合规法律意见 | 归属依据展示、客观排序、转载边界是否获书面认可 | 题材详情中层保留总开关，不上线 |
