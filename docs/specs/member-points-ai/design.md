## 授权与架构边界

根 LICENSE 区分默认 Apache 2.0 与 app/、frontend/ 专有部分；README 与战略稿另有更广泛商业限制表述。首版自行实现，不导入对方专有代码。任何源码级复用逐文件确认授权并保留必要声明，不能根据单个徽章判断整个项目可商用。

根 server 与 backend/server 继续分离，不整体迁移到 Python、MongoDB。现有 Provider 包仅有接口与环境配置，没有真实模型调用。运营配置与审核放运营后台；C 端只消费经过权限控制的业务结果。积分账本与任务必须由同一明确业务服务管理，不能两套后端各扣一次。

AI 输入仅使用授权资料，输出逐项关联来源；来源正文按不可信数据处理，不接受其中的指令。报告保留模型、提示词版本、资料快照与数据时点。模型认为正确不代表事实已获核验。

## 顺序与验收关口

1. 页面与原型映射：从 Git 历史找到原型候选，核对新会员、收费、贡献语义，补齐缺失状态并展示 PNG；用户确认后写页面代码。
2. Provider 基础补强：严格配置校验、地址与密钥脱敏、真实 HTTP 适配、取消与超时、用量字段；本地模拟服务测试成功、鉴权失败、限流、畸形响应与超时。真实服务另作联调。
3. 积分账本与授权：先完成订单幂等、冻结/结算/释放、购买去重、充值回调核验及审计，再开放收费 AI；双请求、重复回调与崩溃恢复必须验证。
4. 轻度 AI：来源明确的事实整理任务，任务与积分预留关联；失效报告不交付收费。
5. 深度 AI：有限工作流与持久化状态；服务重启可恢复，阶段重试不重复扣费；SSE 只传任务进度与可公开结果，不暴露内部推理或敏感日志。
6. 贡献与奖励：审核、有效分享、延后分账、退款冲正及反刷；消费账与奖励账关联但独立记载。
7. 广告：广告主、投放地区、素材审核、有效期、外链白名单、点击归因、签名回调与分佣对账。证券开户与跨境银行卡分别核对服务地区和合作资格；不把普通点击当成功开户。
8. 优化：按用户权限及资料版本隔离缓存、限流、失败追踪、报告导出；不得通过缓存泄漏其他用户报告或绕过付费权限。

## 持续跟踪

本任务每日跟踪上游提交、发布、许可证与商业文档；仅有可行动变化时通知。每项吸收都附源提交、采用或不采用原因、测试证据；不上游自动合并、不自动部署。

本轮未核验真实模型账单、支付渠道、数据授权或广告合作合同。它们影响实际定价和上线，不能由架构参考替代。
