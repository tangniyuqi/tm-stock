# 运营后台（题材库生产工具）· 需求规格

- **等级**：A（护城河的生产工具 + 合规的第一道关口）
- **关联目标**：GOALS.md G1 的**供给侧**——没有库，付费点就是空的
- **状态**：草案，待评审
- **创建**：2026-07-30
- **技术底座**：gin-vue-admin v3.0.0（[ADR-0004](../../adr/0004-后端采用gin-vue-admin.md)，
  BSL 商业授权待购）
- **合规定性**：🔴 **最高关注**

## 1. 业务背景

董事长定调：**"题材核心在于维护这个库。"**
本后台就是维护这个库的地方——它不是"配套管理界面"，它是**产品价值的生产车间**。

### 更关键的一点：这里是合规的生产现场

C 端所有合规保证——"归属依据可溯源"、"不出现评价性文案"、"无依据不展示"——
**最终都取决于运营在这里录入了什么**。

代码层的禁用词门禁只扫**代码里的文案**，扫不到**运营录入的内容**。
而运营录入的题材解读、事件标题会**原样显示给用户**。
→ **门禁必须前移到录入表单**，否则整条合规链在这里断掉。

## 2. 用户与场景

- **谁**：内容运营（录入）、内容主管（审核）、技术管理员
- **什么情况**：每天维护题材库、补充成分股归属依据、录入当日题材动态
- **想达成**：录得快、录得准、**录错了能被拦住**

## 3. 🔴 合规要求（本需求的第一约束）

### 3.1 三重防线：无依据不得入库

| 层 | 手段 |
|---|------|
| 表单层 | 四项证据字段必填，缺任一项**保存按钮不可用** |
| 服务层 | 保存接口二次校验，空串同样拒绝 |
| 数据层 | `theme_stock_mapping` 四字段 `NOT NULL` + `CHECK <> ''` |

> 三层都要有。表单可绕过（直接调接口）、接口可能漏改（批量导入路径），
> DB 约束是最后一道。

### 3.2 录入内容必须过禁用词检查

- 运营录入的 **题材解读 / 环节说明 / 事件标题 / 依据摘录** 在**保存时**校验
- 命中禁用词 → 拒绝保存 + 明确提示命中词与所在字段
- 词表与 C 端**同一份**（`scripts/compliance-forbidden-words.txt`），
  不允许后台维护一份副本（会漂移）

### 3.3 后台自身不得引入评价维度

**禁止**在任何表/表单中出现 `score` / `relevance` / `purity` / `is_leader` /
`recommend_level` / `importance` 等字段。

> 理由：只要后台能录，它迟早会被某个接口带到 C 端。
> **不给运营提供"打分"的工具，就不会有打分泄漏。**

### 3.4 全量操作留痕

谁、在什么时间、把哪只个股挂到了哪个环节、依据是什么、谁审的——
**必须可追溯**。这是监管问询时的举证材料，不是可选的审计功能。

## 4. 功能需求

### 4.1 题材库维护
- 分类体系（一/二/三级）增删改、排序
- 题材：名称、所属三级分类、一句话解读、数据来源
- 产业链环节：题材下的环节增删改、排序、环节说明

### 4.2 ⭐ 成分股归属录入（核心功能）

录入表单字段：

| 字段 | 必填 | 说明 |
|-----|-----|------|
| 所属题材 / 环节 | ✅ | 级联选择 |
| 股票代码 | ✅ | 输入代码自动带出名称（来自 `stock` 表） |
| 来源类型 | ✅ | 下拉：公告 / 年报 / 招股书 / 官方目录 |
| **原文摘录** | ✅ | 多行文本，**不允许空白或"见链接"之类占位** |
| **原文链接** | ✅ | URL 格式校验 |
| 采集时点 | ✅ | 日期选择 |

- 支持**批量导入**（CSV），但**每行同样要过四项校验**，不合格行整行拒绝并报错行号
- 同一环节下同一股票**唯一**（`uk_node_stock`），重复导入提示冲突

### 4.3 审核流

`草稿 → 待审 → 已通过 / 已驳回`

- **只有"已通过"的映射才会出现在 C 端接口**
- 驳回须填原因
- 审核人与审核时间落库（`reviewer` / `reviewed_at`）
- 录入人**不能审核自己录入的条目**

### 4.4 题材动态录入
- 按交易日录入：事件标题、来源、原文链接、发布时间、归属题材
- 标题保存时过禁用词检查
- 可查看某日已录条目并编辑

### 4.5 快讯源管理
- 数据源配置（启停、拉取周期）
- 拉取状态与失败告警查看
- 单条快讯下架（违规内容应急处理）

### 4.6 运营账号与权限
- 基于 GVA 的 Casbin RBAC
- 角色：内容运营（录入）/ 内容主管（审核+录入）/ 管理员
- **录入与审核权限必须可分离**（支撑 4.3 的"不能自审"）

### 4.7 兑换码管理

一期不做在线支付，会员通过**兑换码**激活（见 `docs/specs/member-center/`），
生成能力落在本后台：

- 生成兑换码：指定**可延长天数**、码本身有效期、可选绑定手机号
- 必填 **`order_ref`（站外订单号）**——这是收入对账的唯一钥匙
- 可作废未使用的码；可查询某码的使用情况（谁用的、什么时候）
- 批量生成（一次 N 个）
- **不在此后台做任何收款动作**——只管发码，钱在体外收

### 4.8 数据看板（轻量）
- 题材总数 / 已通过映射数 / 待审数 / 无依据被拒次数
- 兑换码：已发 / 已用 / 未用
- **不做**任何行情或收益类看板

## 5. 验收标准（可测）

- [ ] **AC1**：分类/题材/环节的增删改查可用，层级与排序正确
- [ ] **AC2**：成分股录入表单六项必填，缺任一项**保存按钮禁用**
- [ ] **🔴 AC3**：绕过表单**直接调保存接口**且缺证据字段 → 服务端拒绝（400）
- [ ] **🔴 AC4**：直接向数据库插入空证据字段 → **被 CHECK 约束拒绝**
- [ ] **🔴 AC5**：录入含禁用词的题材解读 → 保存被拒，**提示命中词与字段名**
- [ ] **🔴 AC6**：后台使用的词表与 C 端为**同一文件**（改一处两边同时生效）
- [ ] **AC7**：CSV 批量导入，不合格行整行拒绝并**报出行号与原因**，合格行正常入库
- [ ] **AC8**：同一环节重复导入同一股票 → 提示冲突，不产生重复记录
- [ ] **🔴 AC9**：仅"已通过"状态的映射出现在 C 端 `/theme/{id}` 返回中；
      草稿与待审**不得**出现
- [ ] **AC10**：录入人无法审核自己录入的条目（按钮不可用且接口拒绝）
- [ ] **AC11**：驳回必须填原因；审核人与时间正确落库
- [ ] **🔴 AC12**：所有写操作有审计日志（操作人/时间/对象/变更前后值）
- [ ] **🔴 AC13**：全库检索确认**不存在**评价类字段
      （score/relevance/purity/is_leader/recommend_level/importance）
- [ ] **AC14**：题材动态按日录入与编辑可用，标题过禁用词检查
- [ ] **AC15**：快讯单条下架后，C 端列表与搜索**立即**不再返回该条
- [ ] **边界**：股票代码不存在时提示"未收录该证券"，不允许凭空创建
- [ ] **权限**：内容运营看不到审核按钮；非管理员看不到账号管理

## 6. 不做什么（Out of Scope）

- ❌ 任何**打分 / 评级 / 推荐度**录入能力（红线，非排期）
- ❌ 行情看板、收益看板、命中率统计
- ❌ 自动抓取生成题材内容（质量不可控，且依据无法溯源）
- ❌ C 端用户管理（会员在 `member-center`，且后台不查看用户明文手机号）
- ❌ 多租户 / SaaS 化
