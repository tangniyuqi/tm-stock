## 1. 方案概述

2026-10-30 产品目标调整：保留会话与原交付链路，优先构建少量题材的专题档案、原文核验和版本变化样板；增量设计与实现边界见第13节，验收见requirements第0.3节。历史段落的“已实现/待接”按其日期理解，不替代tasks的当前证据。

2026-10-30本地问答装配增量：实际API显式接受独立`TM_AI_LOCAL_QA`，只用于带同库隔离标记、合成资料、固定会员/题材和字面回环协议模型的验收。文件绑定三模型元数据/端点摘要、域名、额度和有效期，严格精确字段、无凭据、规范摘要冻结，每次读取/执行重新核验文件和实例；模型提交权限仍受原三个独立开关控制。资料范围批准/日配额由原五表提供，不自动登记或放宽；登记用原问答核的PolicyDigest，与执行摘要同源且保留原协议版本。报告追问取同一当前报告读取器的本人引文，继续复核终检/结算及许可；没有报告读取器时报告提交拒启动。受限账号通过固定只读过程取得QA触发器完整定义，保留原定义比对/结构校验/回滚探针，不授TRIGGER/DDL。该配置不能启动生产或真实模型，不把HTTP证明算作H5验收。

2026-10-30本地反馈进程装配：会员反馈复用原API和原反馈服务；独立ai-admin显式读取版本1隔离启动文件时，仅装配内部反馈路由，启动前核对专属库/实例标记并实测原反馈结构约束，拒绝L0模型抽取。监听以本地文件为准，内部操作人和凭据仍从原环境配置绑定，不放到文件/页面；不注册来源管理、抽取或公众任务路由。没有本地文件时保留原管理服务行为，不自动授予生产批准。验收需实际API、worker、ai-admin和原密码登录桥的独立进程，核验反馈提交/复读/处理/终态、越权及零新增模型/账务；HTTP与浏览器证据分别记录。

2026-10-30深度最低交付修复：最低六条逐句引文同时约束Policy.Decode及首次范围匹配，不足时在原选句结构校验拒绝并沿原失败释放路径收尾，不到最终发布才当作幂等冲突。终检语义版本递增为closed-quote-report-v2，原v1档案/检查点不得静默沿用或自动补交；需要重新核验的本地旧任务保留原记录。数量门禁不替代来源、逐字引用、蕴含/合规及原子结算校验。

2026-10-30实际H5进程验收增量：原替身H5与真实H5共用原登录/API/worker装配辅助，真实入口单独声明processBrowser并运行精确LiveH5根组。完整H5从正式目录报价、会话意图和原确认接口创建任务，网关只转发响应及公开SSE。真实模式不提供替身完成按钮或接口，须等待真实引擎自然完成；报告复读、原库唯一报告/结算/六审计及双会员原登录验证完成后，才能输出独立H5证明。父桥回执分别记录HTTP和H5证明，HTTP成功不能充当browser_verified。各次实际成功/失败证据见任务清单，新增入口本身不代表验收通过。

2026-10-30本地进程增量：worker允许环境注入受控父桥的临时模型会话，原无认证回环工厂继续拒绝配置中的Key。会话不进入文件、日志或端点档案摘要；真实供应商Key仍仅由父桥持有。专用liveagents HTTP入口通过原密码路由签发JWT、实际API会话意图及独立队列worker执行，报告终检/审计/结算复用原核；独立进程证明必须单独签发，回执明确browser_verified=false，不能替代H5真实模型验收。默认真实调用关闭及生产批准边界不变。

版本1启动文件仍为real_calls:false，Go侧只连接字面回环服务；该字段不能证明桥后的模型一定是替身。隔离真实试跑由独立父桥显式execute和专用liveagents入口共同控制，并在回执中如实记录真实供应商调用；临时认证会话本身不构成费用或生产授权。

2026-10-21隔离执行边界：本地社区版V2核心用真实`deepseek-flash`验证协作，资料仅为标注的测试资料。临时模型网关固定官方目的地址、模型与输出上限，真实Key不交给第三方源码；原V2类/执行图保留，观测钩子核对每个Agent的真实调用成功。新增**项目自有的一次性异步评估桥**：网站创建原任务后，原Go适配器向桥提交、轮询及取回隔离报告；桥先落盘queued，再启动真实V2引擎，只有真实回执完整才completed。每会话只接受一次提交，已存在日志不得接管重跑；失败/未知不补交，取消未实现远端安全停机，明确拒绝而非假称停止。

该桥仅存在`scripts/dev/`及`integration && liveagents`验收入口，不是社区版MongoDB/Redis Web服务的部署，也不是生产执行服务或持久队列替代方案。原适配器的600001仅为格式占位，原引擎始终处理非证券TMEVAL测试主体；桥固定执行完整V2图，不声称复现上游Web参数裁剪。报告线索只取真实原引擎报告字段，不可信原文不得进入公开正文；后续选句、蕴含与合规判定使用真实模型，仍由原Go严格解码、回取快照、终检并原子结算测试账本。为兼容DeepSeek Chat接口，评估网关明确将json_schema请求转换为JSON对象模式并原样附加schema约束，不改写响应，不能宣称供应商提供strict schema保证。此翻译仅为本地评估协议，不改变生产Provider或政策默认值。来源、质量、披露与价格批准均是隔离测试配置，不能作为生产批准。产品执行开关保持关闭，操作边界见内部手册。

AI 在这里是**资料整理与核验助手**，不是分析师。它只处理已授权、已固化的来源，输出里每一句话要么由代码按封闭句式渲染，要么是绑定证据编号的逐字引文。

ADR-0005 的核心反对意见是"生成模型是概率性的，一次输出就是一次违规"。本设计的回应不是把概率压低，而是**让概率性碰不到展示层**：模型只做抽取与二分类判定，它的输出必须先过确定性校验，用户看到的文字由代码模板与逐字引文构成。因此合规不靠提示词，而靠**结构**：

1. **入口受限**：原收费任务仍只接收"分析类型 + 对象 + 价格版本"。2026-10-21 用户确认会话式受限自然语言问答，独立契约见第12节；不再声称整个助手没有提问注入面，新增输入须按不可信数据隔离。
2. **来源封闭**：只吃白名单来源的不可变快照；来源正文一律当**数据**，不当指令。
3. **输出封闭**：schema 里没有评级、分数、排名、龙头、方向这类字段，"A 是龙头"在结构上写不出来。
4. **确定性校验在前，模型判断在后**：逐字子串、数字对账、实体与题材共现、红线规则都是代码；模型只做"是否蕴含"的二分类，且 fail-closed。
5. **账务与任务同事务**：冻结与建任务同一 MySQL 事务；终态只能由一次 CAS 决定；重试不产生第二笔冻结。
6. **成本封顶**：预算（调用数、token、页数、时限、重试）在网关与任务两层强制，不放在提示里。

用户在 2026-10-15 明确选择实际复用 TradingAgents-CN 服务，修订此前“只借模式”的取舍，见 [ADR-0010](../../adr/0010-TradingAgents-CN作为隔离执行服务.md)。先接独立的内部执行链路，不直接向公众转发上游结果；现有 L0 和本节六项公开边界保持不变。外部 LLM 网关仍不引入。

## 2. 总体架构

### 2.1 组件与边界

|---|---|---|
| AI 接口层 | `server/internal/handler/ai` | 报价、创建、查询、取消、历史、报告、反馈；只做绑定与转换 |
| 任务编排 | `server/internal/service/ai_tasks.go`、`ai_task_budget.go`、`ai_task_stages.go`、`ai_reports.go` | 已实现创建/冻结、抢占/心跳、失败终结、保守预算预留和隔离阶段检查点；恢复型 worker 及关闭的内部报告原子提交核已接，完整公众流水线待接，事务边界在服务层 |
| 积分账务 | `server/internal/service/points*.go` | 批次、冻结、结算、释放、冲正、欠款抵扣、对账 |
| 证据流水线 | `server/internal/ai/pipeline` | 采集、抽取、校验、渲染的纯函数与接口，便于离线测试 |
| 校验器链 | `server/internal/ai/guard` | 逐字、数字、共现、红线检测 |
| 渲染器 | `server/internal/ai/render` | 句式白名单与模板，注入标识与公示 |
| Provider | `server/internal/provider`（扩展） | HTTP 适配、中间件、模型注册表、mock |
| 工作进程 | `server/cmd/ai-worker` | 已实现显式单任务恢复：启动自检、接管、独立心跳、既有结果校验/复用；不发起外部调用。全队列调度与完整流水线待接 |
| 内部管理接口 | `server/internal/handler/ai_admin`，独立监听 | 给运营脚本（日后也给 GVA 后台）调用：L0 抽取、待审队列、价格簿、模型注册表；服务间凭据走环境变量（占位符），不对公网暴露 |
| 运营后台 | 先用脚本与 CSV（ADR-0006 阶段 1 的做法）；GVA（`backend/`）界面待授权确认后再做（D15） | 只是薄客户端：审核界面与配置界面；**不直接写 AI 产物表与账本**。GVA v3.0.0 为 BSL 1.1，处理真实业务数据属"生产使用"，授权状态未知（F13） |

依赖方向沿用规范：`handler → service → repository`，`ai/*` 不依赖 HTTP 层。

### 2.2 数据流

```
用户 → handler(报价/创建) → service/aitask ─┬─ 同一事务：建任务 + 冻结积分 + 事件#1
                                            │
ai-worker ← 抢占(租约+围栏) ← tm_ai_tasks ──┘
   │ 规划(封闭分类法) → 采集(白名单域名，代码) → 快照固化
   │ → 抽取(无工具 LLM，单来源，封闭 schema + 逐字引文)
   │ → 逐字/数字/共现(代码) → 蕴含裁判(2 个异源模型) → 红线检测 → 渲染(模板)
   └ 终检通过：同一事务 写报告 + 任务→成功 + 冻结→结算；否则 任务→失败 + 冻结→释放
用户 ← 轮询任务状态/报告（SSE 仅作增强）
```

### 2.3 信任边界

- 不可信：来源正文、模型输出、用户请求体、供应商错误信息。
- 可信：代码、数据库、价格簿、模型注册表、禁用词表（单一来源 `scripts/compliance-forbidden-words.txt`）。
- 抽取模型**无工具、无外联**；规划模型只看题材库与对象，看不到来源正文；"读过不可信输入的模型不能触发后果性动作"，后果性动作（落库、结算）只由代码在校验通过后执行。

### 2.4 身份接入（决策 D6 的落地规则）

`server/` 没有自己的登录，用户身份来自 GVA 签发的会员 JWT。GVA 用**同一把 HS256 密钥与同一 claims 结构**签发后台管理员令牌与会员令牌；起步审计时会员令牌不带类型（requirements F9），所以"验签名取 ID"会让后台令牌冒充同号会员——这正是 ADR-0004 预见过的"用后台中间件保护 C 端接口"类错配。GVA 签发处现已补 `client` 类型。规则：

1. 校验签名、`exp`、`nbf`、`iss`、`aud`；密钥只经环境变量（`TM_JWT_SIGNING_KEY`）注入，仓库内只放占位符，轮换约定见 ADR-0008。
2. **令牌类型**：只接受 `UserType=client`；类型为空、`admin` 或其他值一律拒绝，**不设过渡期放行**（过渡放行会变成永久绕过口）。GVA 一侧已在 `issueToken` 写入 `client`，并让 `JWTAuth`（只认 `admin`）与 `ClientJWTAuth`（只认 `client`）强制检查，见 ADR-0008；代价是部署后已登录的会员需重新登录一次。
3. 按 `BaseClaims.ID` 到共享库查会员，存在且启用才放行（GVA 的会员令牌是无状态的，登出不失效，所以撤销只能靠这次查库）。
4. 不信任客户端传入的 `user_id`；服务内部一律用中间件写入上下文的会员编号。
5. 内部管理接口不走会员令牌：独立监听、服务凭据（环境变量，占位符）、来源 IP 白名单。

#### 2.4.1 会员任务只读入口（2026-10-15 开发增量）

- `cmd/api` 独立开关 `TM_AI_TASK_READ_ENABLED`，默认关闭，关闭时不注册路由；不受 `TM_DEV_GRANT_PAID` 放行影响。开启时必须显式配置 `TM_JWT_SIGNING_KEY`、`TM_JWT_ISSUER`、`TM_JWT_AUDIENCE`，可配置 `TM_JWT_SIGNING_KEY_PREVIOUS`。密钥至少 32 字节，新旧不能相同；不修改 GVA 的签发配置。签发者和受众必须与实际 GVA 配置一致，不能因校验失败改成忽略。
- 复用 GVA 当前 claims 的精确键名，HS256 算法白名单、必需且有效的 `exp/nbf/iss/aud`、正整数 `ID`、`UserType=client`、后台角色 `AuthorityId` 缺省或 0。拒绝重复/大小写冲突键、未知 claims、动态取钥头、超 8192 字节令牌；`iat` 若存在必须有效。仅单个标准 Bearer 头，不接受 Cookie、x-token、查询令牌或客户端身份编号。密钥轮换由运维显式移除旧钥结束，泄露时不能保留过渡窗口。
- 每次请求按 `addon_member.id` 查询 `deleted_at IS NULL AND status=1`，无身份缓存；身份校验/任务读取分别最多 3 秒，尊重更短父上下文。后台/无效令牌先拒绝，不触达会员表。未知/删除/停用会员返回统一 401；校验依赖故障返回固定 503，不返回驱动异常或令牌。
- `GET /api/v1/ai/tasks?before_id=<正整数>&limit=<1..100>`：默认 20 条，`before_id` 省略表示首页，按编号倒序且不包含游标本身。返回 `{items,nextBeforeId,hasMore}`；只在确有下一页时返回末条编号作为游标，其余为 0，空列表为 `[]`。使用既有 `(user_id,id)` 索引，不联表或查询总量。
- `GET /api/v1/ai/tasks/{id}`：轮询进度。详情和列表均从认证上下文取得会员编号，并在 SQL 按用户过滤；非本人和不存在的任务同为 404。拒绝未知/重复/空参数、非规范正整数、畸形查询编码。读取为只读事务，不锁账户、不写事件、不冻结/释放/结算积分。
- 进度 DTO 精确白名单：`id,analysisType,subjectType,subjectId,status,currentStep,eventSeq,cancelRequested,errorCode,deadlineAt,reportAvailable`；列表使用独立摘要 DTO，只含 `id,analysisType,subjectType,subjectId,status,deadlineAt,reportAvailable`，不复用详情。截止时间是 Unix 毫秒；不输出提示词、幂等键、散列、租约、围栏、预算、原始 Agent 报告或任意错误文本。列表的 `reportAvailable` 恒为 false；成功详情只有显式装配报告可用性核验且当前核验通过时才为 true，不能仅凭成功状态推导；无虚构完成百分比。额外报告核验的锁和权限边界见2.4.4，不将它冒充原无锁详情查询。
- 本节开关只注册只读 GET（标准库也支持对应 HEAD），事件增量查询另见 2.4.3，不因开启读取而开放写入。取消入口另见 2.4.2，独立开关默认关闭；报告入口另见2.4.4；仍没有创建、报价、反馈或收费入口，不调用模型。P3-5、AC-S4/T4 的全部退出标准仍未满足，线上 GVA 版本、实际密钥/会员表及浏览器接线另行联调。

#### 2.4.2 会员取消入口（2026-10-16 开发增量，默认关闭）

`POST /api/v1/ai/tasks/{id}/cancel` 仅取消本人已有任务，不创建任务、不调用 Agent。独立 `TM_AI_TASK_CANCEL_ENABLED` 默认 false；启用必须同时启用任务读取、通过会员 JWT 配置与任务/账本联合启动自检。仅开读取不注册写路由，开发付费放行也不启用取消。执行账号需十四张任务依赖表 DML 与 `addon_member` SELECT，无 DDL/TRIGGER 权限；开启后启动自检失败则整个 API 启动失败，不能降级开放写入口。

身份仅取标准 Bearer 验签后实时有效会员上下文。路径编号为规范正整数；不接受任何查询参数（包括空查询标记）、Content-Encoding、重复媒体类型或自报会员/原因/围栏/金额字段。请求体最多 64 字节，可为空或 JSON 空对象；非空体须单个 `application/json`（可选 UTF-8 charset），未知字段、null、数组、尾随 JSON 和过大体均拒绝。无需客户端幂等键，复用原任务的不可逆取消状态/唯一终态；取消重放返回当前状态而非首次响应缓存。

服务取消最多 10 秒、服从更短父上下文，调用既有 `AITaskService.Cancel`，账户→任务→冻结单/批次锁序不变：排队任务的取消、事件与释放同事务；运行任务只置取消请求，保留冻结，等待有效 worker 或原租约接管终结。既有终态保持原样，不把成功/失败/到期改为已取消。返回独立白名单 `id,status,eventSeq,cancelRequested,errorCode,reportAvailable`，报告始终不可用；没有金额、退款承诺或远端已停止标志。HTTP 200 只表示当前取消状态读取/提交确认，不等于运行任务已终止。

会员页取消交互复用此接口与现有会员令牌，由独立取消封装发送固定任务编号、空JSON正文，不扩展只读API为通用写入口。仅排队/运行且未申请取消时显示入口；先展开就地确认，再显式提交一次。确认和提交期间暂停该详情轮询，状态仍以原任务GET为准；不把取消DTO当作进度或报告许可。异常/超时保留结果未确认提示，仅核对原任务，不自动重发。切换任务/账号或离页后忽略迟到响应，既有终态不宣称已取消或已退款。验收覆盖二次确认、重复点击、排队与运行回执、成功竞争、关闭/未知/401、状态核查及跨任务/账号隔离；实际组件源码交互不替代缺失依赖下的HBuilderX/浏览器验收。

跨用户与不存在同为 404/40403；参数 400/40001；身份 401/40100、依赖故障 503/50301；取消/提交/超时或异常状态为固定 503/50303，隐藏驱动详情。错误不自动重试/退款；提交结果可能未知，可 GET 原任务或重复同一取消请求受控核查，不换任务/直接改账。所有认证响应 no-store，Cookie/x-token/查询令牌不参与鉴权；不新增 CORS 放行。

验收先覆盖开关/启动失败关闭、严格输入、DTO 脱敏、短父期限与提交未知，再在 MySQL 8/9 的 RC/RR 下实测真实 JWT→当前会员→用户隔离→取消事务：排队/运行/终态重放、并发取消/worker 竞争、事件故障原子回滚及实际已提交但回执未知。启动装配另用隔离真库与受限账号验证。公开生产开关、线上网关/前端和真实远端取消不在本轮验收范围。

#### 2.4.3 会员任务事件增量查询（2026-10-16 开发增量，沿用读取开关）

`GET /api/v1/ai/tasks/{id}/events?after_seq=<非负整数>&limit=<1..100>` 用于普通轮询的断点续读，不是 SSE 或完成百分比。沿用默认关闭的 `TM_AI_TASK_READ_ENABLED` 与严格会员鉴权，不启用写开关；关闭时不注册路由。身份仅来自 Bearer 上下文，先按会员读取任务，事件 SQL 另联本任务归属过滤用户；非本人和不存在同为 404/40403。新增仅需 `tm_ai_task_events` SELECT，不需 DDL 或新迁移。

路径为规范正整数，`after_seq` 默认 0、显式 0 有效，`limit` 默认 20。拒绝未知/重复/空参数、畸形转义、非规范整数与越过当前上界的游标。单次服务最多 3 秒并服从更短父期限。任务行和事件页在既有只读 RR 事务中读取，以该快照的 `event_seq` 固定 `upperSeq`，事件按 `(task_id,seq)` 主键范围升序、至多读 limit+1，不 COUNT 全历史或锁账户。

返回独立 `{items,nextAfterSeq,hasMore,upperSeq}`。事件只有 `seq,type,status,step,errorCode,at`，`at` 是数据库 UTC 创建时点的 Unix 毫秒；读取 DATETIME 字符串后按 UTC 解析，不受驱动 loc 再次转换。序号而非墙钟决定先后。`nextAfterSeq` 始终为最后已交付序号，空页保持原游标；无更多只表示本次上界已读完，运行任务后来仍可轮询新事件。报告可用性、百分比、原文、任意错误、预算、租约、围栏和内部主键不在事件 DTO 内。

期望记录数必须等于 min(upperSeq-after_seq,limit+1)，逐条核对任务、精确连续序号、类型/状态/错误闭集、步骤范围及页内不倒退、有效毫秒时点。created 只能在序号 1/步骤 0；step_completed 必须步骤正值；终态事件只能是该快照末事件，末事件状态/步骤/错误必须与任务行一致。任一异常或事务提交失败返回固定 503/50302 和空结果，不能静默跳过或按局部数据伪造完整性。这是有限页校验，不审计游标之前/上界之外的全历史或证明真实模型质量。

验收覆盖闭集 DTO/输入、缺失/重复/错序/终态与快照不符、整数边界、UTC/驱动时区及读取提交失败；双版本真库验证真实 JWT/会员隔离、分页重放、查询不写账本/事件、阶段与取消/重试进度、读任务后并发提交仍不混入当前 RR 页、结构/数据破坏拒绝。生产前端/网关、限流容量、SSE、报告与真实执行保持未验收。

#### 2.4.4 会员报告读取与页面（2026-10-18 开发接线，公众读取关闭）

依ADR-0020，独立 `GET /api/v1/ai/tasks/{id}/report` 与 `TM_AI_REPORT_READ_ENABLED` 默认关闭。复用严格会员身份、原终检前缀/报告/任务/事件/锁价结算核，再核对当前来源与发布批准；不执行Review或模型，也不写账。关闭不注册；缺发布控制器/策略或联合结构自检失败时启用会导致启动失败，不受开发付费开关影响。当前主程序没有生产控制器工厂，公众读取继续关闭。

#### 2.4.4.1 报告反馈受理与处理（开发契约，真实调用不启用）

用户2026-10-20要求接通提交、查询与处理闭环。沿用现有四类`fact/source/display/other`，不增加自由文本、联系方式或模型问答。会员`POST /api/v1/ai/tasks/{id}/feedback`仅接受`{"category":"fact"}`；同会员/报告/类别唯一，重复提交返回原记录，不重复受理。`GET`同一路径返回该报告至多四条反馈；身份仍来自当前会员Bearer，非本人和不存在同为404。只对真实成功报告受理；后续来源/发布权限撤回不阻断历史反馈，但这些接口不返回正文、来源副本或内部判定。

反馈独立于报告内容与积分：受理不重跑模型、不修改报告/授权、不结算或退款。状态`received → processing → resolved/dismissed`；处理结果仅允许固定复核/转交/证据不足/不适用枚举，不返回内部自由文本。终态不允许会员覆盖；同类别不另开单。每次状态变化与不可变事件在同事务提交，版本递增；原版本的同一内部操作重放可核对，过期或竞争操作拒绝。提交未知只查询该报告原类别，不自动补交。

处理复用`cmd/ai-admin`独立回环服务、当前内部凭据与操作人绑定：分页`GET /internal/v1/ai-feedback`、详情`GET /internal/v1/ai-feedback/{id}`、处理`POST /internal/v1/ai-feedback/{id}/decisions`。独立默认关闭的会员/内部反馈开关，开启须结构自检通过；不受AI执行/创建/发布开关放行，不把会员JWT用作内部凭据。反馈身份和创建信息不可变、无删除入口；公开DTO不含会员、操作人、报告摘要或内部事件字段。前端在成功任务详情内独立查询反馈，来源撤回/报告不可读时仍能查询；确认后单次提交，错误/未知核查原类别，切任务/账号/离页清理迟到响应。

会员开关`TM_AI_FEEDBACK_ENABLED`还要求任务读取已启用且会员鉴权配置有效；内部开关`TM_AI_FEEDBACK_ADMIN_ENABLED`不隐含模型开关。两者仅接受空值、`false`、`true`，默认关闭。启动自检复用报告联合探针，再验证两张反馈表的元数据、唯一键/外键、强制CHECK和真实拒写，所有探针回滚，不自动DDL。MySQL禁止CHECK引用自增列；显式反馈编号由插入触发器限制，自动编号在同事务内经领域校验，超界会连受理/审计一起回滚。

会员DTO固定为`id,taskId,category,status,resolution,version,createdAt,updatedAt`，时间为Unix毫秒；列表为`{taskId,items}`，至多四条、编号递增、分类唯一。`received(v1)`与`processing(v2)`结果为空；`resolved(v3)`仅`reviewed/referred`，`dismissed(v3)`仅`unconfirmed/not_applicable`。终态表示核查记录，不承诺报告更正、恢复授权或退款。内部处理JSON精确为`{expectedVersion,status,resolution}`，同身份同操作重放返回当前记录，异身份或不同结果冲突409；未知统一503且不返回候选DTO。分页只接受`after_id`与`limit`（默认20，1..100），省略游标为首批，后续按编号递增；不是待办独占分派队列。

会员受理与查询先锁本人任务、再锁报告、再锁反馈，避免与报告事务反向锁序及RR空分类间隙锁升级；内部处理只锁反馈与事件，不碰账户/任务/报告。状态变化与不可变事件一同提交，读写均核对完整版本历史；直接缺失或篡改历史失败关闭。后台处理页面及专用桥接见下；自动纠正、通知或退款流程仍不包含。

后台页面增量（2026-10-20）：复用GVA Vue/Element Plus管理界面，组件路径`view/quant/aiFeedback/index.vue`，通过私有`GET /quant/ai-feedback`、`GET /quant/ai-feedback/:id`、`POST /quant/ai-feedback/:id/decisions`转接原内部接口；不是公开会员入口。GVA后台JWT、改密守卫、Casbin/DataScope之外，服务端还须配置逐后台用户→内部actor/专用凭据的一对一登记，逐次核验当前后台用户启用且未删除。浏览器只用原后台会话，不接收内部密钥，不直连内部监听。桥接独立开关`TM_AI_FEEDBACK_CONSOLE_ENABLED`默认关闭；配置上游仅允许字面量回环HTTP地址/明确端口，精确Web Origin及处理人登记只在服务端环境变量，不加入可查询的全局系统配置。无代理/重定向/自动重试，只转接三个固定反馈操作，不开放模型、通用HTTP代理或原始报告。

页面提供编号递增分页（无虚构总数）、按受理单编号查询、详情和至多三条不可变处理历史；不把列表缓存当详情版本。处理仅使用新近GET详情的版本，动作与结果为原闭集，二次确认后单次提交；成功/冲突/未知后清除旧操作上下文，必须显式GET核对，禁止自动POST。未知时保留原受理单编号和操作提示，不能切换到其他工单掩盖未知；允许先查询恢复。加载/空/错/无权限独立显示；离页、keep-alive停用或后台账号/令牌变化清除列表、详情和确认草稿并丢弃迟到回包。页面不自动修正报告、恢复来源、退款或通知。菜单和三个API权限由既有后台菜单/角色管理显式配置，不自动授予全部后台人员，也不迁移生产权限表。

#### 2.4.5 会员报价、创建与原键核查（开发中，创建默认关闭）

依ADR-0021复用既有 `POST /api/v1/ai/tasks/quote`、`POST /api/v1/ai/tasks` 契约。报价只接受 `analysis_type,subject_type,subject_id`；创建再加 `price_version` 并要求单个规范 `Idempotency-Key`。任务类型为light/deep，内部映射1/2；目前只有light/theme具备执行核，新建其他已知类型返回不可用，不冻结。身份仍来自严格JWT/实时会员，不接受客户端用户编号、模型、费用、预算、来源或自由文本。

报价DTO提供当前题材名称、价格版本/积分、以实际可用批次计算的可消费积分、数据库UTC报价时点、冻结时限与批准资料范围（来源类别代码/链接/采集时点，不含原文或许可）。来源类别为来源域既有announcement等闭集代码，不混用报告中的中文展示标签。冻结时限按秒向上取整提示，实际创建按原毫秒预算固化截止。控制器Plan/Recheck必须实际核对模型、质量、当前来源及远端硬预算，调用都在数据库锁外；缺控制器或证明失败关闭。报价不是余额预占、定价或授权永久有效保证。

创建成功DTO只含 `taskId,pricePoints,priceVersion`，是不可变创建收据，不以queued或success伪装当前状态。先查原用户/键与原请求摘要，再作新请求准入；最终复用原任务创建事务，锁价/预算来自服务器。提交未知不得返回候选收据。

`GET /api/v1/ai/task-receipt` 为只读原键核查：只接受单个Idempotency-Key和会员Bearer，拒绝查询参数/正文；返回相同三字段收据，本人与不存在的区别不对他人泄露。该路由沿用任务读取开关，不开启报价/创建，模型或来源撤回不阻断查询已经确认的创建。服务校验原冻结与流水身份/金额/版本及摘要；不会借核查补冻结、重新执行或改终态。服务及HTTP已接线，完整回归与前端验收仍需分别取证。

会员创建交互按ADR-0021：使用既有题材搜索选择对象，先展示服务端报价与可消费积分，再显式确认冻结。创建前持久保存原键并协调同账号页签；不支持安全随机数、存储或互斥时拒绝发送。页面恢复只核查原键，不自动重新创建。未知结果及核查404保留现场；收据仅证明创建，必须再查任务和报告，不显示“已交付”。待核查记录只含最小请求信息，不保存令牌、报告或证据正文；本地身份分区不代替服务器JWT校验。首次准入持久绑定接线见下一节；生产价格簿与实际批准登记/核验仍待实现，不能把测试控制器当作生产装配。

确认创建后点击查看，会重置旧历史游标/响应轮次和已显示正文，分别GET真实本人历史与原任务详情，不用创建收据补造摘要、状态或报告许可。历史失败不伪装为空列表，详情失败不伪装已交付；401、换账号、离页及重复查看后的迟到响应均丢弃，本地原键不删除。列表明确区分历史查询状态和同一范围任务的当前详情状态；仅更新可见文案，不改写历史快照或其恒false的报告许可。源码交互回归包含旧首页/分页迟到、独立查询故障与原键保留，但仍不代替真实H5验收。

#### 2.4.6 首次准入计划与执行绑定（ADR-0022，开发验收中）

### 3.2 流水线步骤

| 步 | 做什么 | 性质 | 失败时 |
|---|---|---|---|
| 1 规划 | 从封闭题材分类法产出子问题或命题 | 模型（只见题材库） | 回退为固定模板命题 |
| 2 采集 | 白名单域名抓取，限页数与并发，SSRF 防护 | 代码 | 记录缺失，来源标"不可用"，不猜链接 |
| 3 固化 | 正文规范化后存不可变快照（内容哈希、链接、采集时点、授权标签） | 代码 | 授权标签缺失则拒收 |
| 4 抽取 | 快照在固化时已按句切分并编号。每份来源单独交给无工具模型，**模型返回句子编号与命题，不返回自由文本引文**；引文由代码按编号取原文。输出封闭 schema（命题、关系、句子编号、来源编号），不得含评价文字 | 模型 | 畸形输出最多修复重试 1 次，仍失败则该来源丢弃 |
| 5 逐字与数字校验 | 逐字性由"按编号取原文"构造保证，仍保留规范化后的子串校验作防御纵深（编号越界、偏移回填出错即丢弃）；数值、日期、代码逐字一致；含省略号的摘录分段校验 | 代码 | 丢弃，不做近似匹配 |
| 6 共现校验 | 引文内须同时出现实体（简称、全称、代码，查别名表）与题材锚词（同义词表） | 代码 | 不送裁判，丢弃（专治"推断出的关联"） |
| 7 蕴含裁判 | 假设句用**我方标准模板**而非自由文本；两个异源模型各自 yes 或 no，只认"无需额外推断即明确支持"，**fail-closed** | 模型 | 任一不同意则丢弃该条 |
| 8 红线检测 | 禁用词、句式、数值模式 + 结构白名单（只许模板句与引文块），模型二道报警；**对展示引文同样检测** | 代码为主 | 命中则丢弃该句；引文命中走 5.4 第 4 条 |
| 9 渲染与终检 | 模板渲染；注入标识、模型名与备案号、举报入口；检查最小可交付标准 | 代码 | 不达标则整任务失败并释放积分 |

L1 与 L2 共用这条流水线，**不增加自由度**：L1 **只读已固化的快照**（来自 L0 或运营导入），不实时采集，因此结果可复现、延迟与成本可控、没有实时抓取的攻击面；L2 才在白名单域名内增量采集，并增加并行、对称取证与对账。L0 在第 8 步之后进入待审队列，不渲染给用户。

#### 3.2.1 L0 人审事务契约

- 候选依据与模型追溯字段不可修改。审核请求只接受候选编号、导出时的证据摘要、决定、原因和幂等请求编号；审核人由服务凭据绑定，不接受客户端指定身份。
- `pending → approved/rejected` 为一次性终态，由候选编号唯一的审计事件推导，不修改候选。相同请求编号、相同身份与载荷重放返回原审计事件；改载荷重放或再次决定返回冲突。驳回必须写明原因，来源停用后仍可驳回。
- 通过前锁定来源、候选与主数据，重新校验当前授权、快照逐字内容、共现、红线与主数据身份。插入带完整依据且 `audit_status=2` 的归属、写不可变审计事件及刷新可见股票数在同一事务内执行；任一步失败全部回滚。
- 已存在的存活题材/股票归属一律冲突，不能借 AI 审核覆盖人工记录。节选候选须与守卫重算的逐字分段及节选标记一致，通过后将 `excerpt_trimmed` 同事务写入归属；依据接口显式返回 `excerptTrimmed`，C 端浮层标注“原文摘录（节选）”。“原文转载”特殊放行仍未提供绕过入口，不能靠节选标记跳过红线。
- 正例验收：通过、驳回、同请求重放；反例验收：摘要被改、身份伪造、授权停用/过期、主数据变化、已有归属、同时审核、审计写入失败及审计篡改。真实 MySQL 验收不能用静态 SQL 检查代替。

#### 3.2.2 L0 内部运行入口（不替代阶段 3）

- `cmd/ai-admin` 独立回环监听，同时提供资料登记、快照、抽取与审核；`cmd/ai-review` 是非浏览器薄客户端。模型抽取默认关闭，单独批准配置要求精确 HTTPS 域名、注册模型/备案引用与结构能力、提示大小和有限调用数；配置非空不证明真实批准或能力已经核验。
- 同步抽取先持久化 `tm_ai_l0_extraction_runs`，请求编号全局唯一、绑定审核身份和快照；相同请求返回既有状态，不重复模型调用。调用前/后追加不可变 `tm_ai_l0_call_events`，记录脱敏输入输出及用量。候选与成功终态同一事务保存，复用同证据候选时保留首次候选追溯，本次模型另由运行记录追溯。
- 结果未提交或崩溃后保留 `running`，只能先查询原请求并人工核对；没有自动恢复/重新付费调用。已终结请求不得追加调用，成功终态要求每次调用的前后审计配对。数据读取校验状态、模型、用量和终态内容，损坏记录不作为成功返回。
- 单进程串行、单次抽取 60 秒、最多两次调用（只修复畸形输出）；审计/终态有额外有限落库时限。进程调用数上限重启重置，只是内部尝试限制，**不是日费用上限、积分冻结、租约围栏或公众计费任务**。阶段 3 的持久化预算/任务恢复仍须独立实现和验收。
- 原始调用审计不经接口返回，仍需按授权管理数据库访问与留存。来源管理独立审计与抽样复核已接内部接口与脚本，五份初始迁移及相关事务已在全新 MySQL 8.0.46 / 9.7.0 隔离实例各连续验证 10 次；另补节选增量迁移及展示链后，仓储全集成与 GVA 真库用例在两个版本各连续通过 3 次。这不是生产升级演练；原文转载放行、运行度量等仍未完成，不能据内部入口已接线宣称 L0 退出标准已达成。

#### 3.2.3 L0 抽样复核契约

抽检只针对已人工通过的记录，不替代首次 100% 人审。服务端读取按审核编号递增的有限窗口（至多 2000 条），排除本人的原审核，再用密码学随机数做不放回等概率抽样（至多 200 条）；持久化完整窗口编号、窗口内容摘要、末游标、总体/可选数量和不可变分派，不把客户端自选候选伪装成随机抽检。相同批次请求编号、同身份/参数重放返回首次选择。审核扫描使用 `(decision,id)` 索引；问题历史使用同口径复合索引。

复核由批次创建人执行，且不得为原审核人。每条的证据摘要绑定批次、条目、原审核事件与不可变候选；`confirm` 表示本次核对无问题（原因留空），`issue` 必须记录原因。确认前重新校验来源授权、逐字依据、主数据与现存归属；发现问题时允许来源已失效，但只暂停与原候选依据仍精确一致的归属，并在同一事务写不可变复核事件、刷新可见股票数。不得改原候选、原审核事件或删除依据；归属已被其他流程改动时返回冲突，转既有治理流程，不能覆盖。

复核事件按条目唯一、按请求编号唯一；相同身份/载荷重放返回原结果，其他终态重审冲突。问题记录有独立分页入口，暂停后不会被另一次 `confirm` 自动恢复。纠错/恢复由既有归属治理流程另行核对，保留原问题历史。抽检是有限窗口的随机样本，不据此宣称总体零错误或用作模型准确率；相关真库并发、回滚和约束仍须集成实测。

#### 3.2.4 来源管理操作审计

资料管理写操作显式接收凭据绑定的操作者编号，不从业务 JSON 或隐式上下文取得身份。登记、启用、停用、导入、采集的**成功提交**分别追加 `tm_ai_source_audits`；登记保留默认停用的来源副本，启停保留变更前后副本，导入/采集保留当前授权副本和不可变快照编号、哈希、规范化链接。来源/快照和操作审计由 Service 在同一事务内提交，任何审计故障全部回滚；重复内容复用原快照，但每次成功操作仍独立留痕。

采集准备服务只读来源并在事务外执行有限网络请求，不提供无审计写入接口；保存时持来源行锁、按数据库时钟复核当前授权，避免采集期间停用仍落库。启停也先锁来源，保证同来源操作的前后副本连续。审计表禁止更新/删除，有来源/快照外键与 `(source_id,id)` 历史索引；只读历史接口按来源分页，不因当前授权过期而重写或拒读历史副本，所有 API 时间均为 Unix 毫秒，不返回正文或凭据。

该表不是请求任务日志：被拒绝、网络失败及未提交的操作不会留下“成功”事件，也不提供请求级恰好一次语义。它不替代采集失败观测、持久化幂等或授权撤回后的归属治理。来源停用不自动修改历史人审归属；发现相关归属有问题时仍须通过复核/既有治理流程暂停展示并保留依据。测试覆盖身份伪造、历史过期授权、重复导入、采集中撤销授权、审计故障回滚、非法快照引用和并发启停；双版本真实 SQL 验证只针对全新可丢弃实例。

#### 3.2.5 节选依据展示契约

`20261011_add_theme_stock_excerpt_trimmed.sql` 是共表收敛之后的增量迁移，不修改旧迁移权威定义或历史原文。新增 `tinyint NOT NULL DEFAULT 0` 与强制 0/1 CHECK；重复执行保留值，未知列定义或被替换的同名约束主动中止。历史默认 0 仅表示未记录特殊节选，不承诺摘录是完整原文。

候选的节选标记已绑定不可变证据摘要；审核入库不得丢失，抽检比较现存归属时也必须包含该标记。GVA 以可空请求指针区分“省略不改”和“明确改为 false”，修改标记与修改原文一样使原审核作废；列表、详情和两处编辑表单均显示标记。C 端严格要求布尔响应字段，缺失/字符串/数字标记拒绝展示；文本使用普通插值而非 HTML，节选时提示结合原文核对上下文。

上线须先迁移，再更新 API、GVA 与 H5 并验证清除旧静态缓存，最后恢复内部审核；旧客户端没有节选标签，不能在它仍对外服务时开始通过节选候选。已存在可见节选归属时禁止单独回滚前端；须先暂停相关展示。当前验证包含双版本真库、模板编译、实际页面验证器正反例与 SSR 文案/转义，不等同于 HBuilderX 整体构建和真实浏览器交互验收。

#### 3.2.6 持久化抽取阶段的确定性策略

内部 `pipeline.NewExtractionStage` 只构造 `extract` 阶段的纯策略，不调用模型、不启动 worker、不写人审候选或公开报告；L0 Runner 的部分候选筛除/修复重试契约不变。策略重用现有严格抽取守卫，但要求至少一条、所有条目通过，重复条目与需要截取的引文整体拒绝；v1 不将未经记录的节选或被拒条目混在一个“已完成”原始响应里。目录来源只允许 `LISTED_IN_CATALOG`，其他允许来源只允许 `DISCLOSES_BUSINESS`，仍不是语义蕴含、主数据解析或事实准确性的充分证明。

可信调用方须先通过 `SnapshotForExtraction` 等当前授权读取路径取得快照、按任务主体缩小词汇；工厂不替代当前来源启停/授权检查。构造时验证快照、HTTPS 规范链接及容量，复制快照/词汇到私有不可变输入；上限为正文 1 MiB、10000 个句子、128 个题材、每题材 32 个锚词，词长 2..64。输入摘要绑定快照身份/正文哈希/链接/采集时点/授权副本、封闭系统提示/Schema/提示版本与输出上限。策略摘要另绑定输入摘要、确定性算法版本、实际词表/句式文件内容和规范化词汇（别名排序去重，不因 map 顺序漂移）。确定性实现的语义改变必须升算法版本；改词表/句式内容自动改变摘要，不把手工版本号当成代码自动证明。

校验只接收匹配的 `extract + input_digest` 与隔离 JSON，复核结构、谓词、题材、编号、逐字回取、实体/题材共现、否定关系与红线；上下文取消及任何拒绝均不推进。输出仍留在隔离表，不将原始 Agent 研究报告删字段后送进此策略，不把模型返回的“已校验”字段当证据。当前阶段服务可装配该策略，真实调度器须在调用与复用前另行核验当前来源授权/主数据；报告生成前还须蕴含裁判、语义二道防线、公示与终检。其他阶段类型不注册默认放行策略。

### 3.2.7 报告编号选择与证据自动转换

新增开发接线见 ADR-0019：`SelectionModelPlan` 将已校验身份的隔离 Agent 结果作为不可信线索（最多256KiB），仅向选择模型发送题材、线索与授权来源句子列表。固定2048输出token、单次直连、无工具与重试，Schema只能返回章节/快照/连续句子编号；`AIReportSelectionWorker` 每次调用和回放前亲自读取 Agent 第一步已完成回执。与双判定复用封闭 `ModelStep` 的预留/审计/捕获协议；实际用量不明、模型不符、截断或编号非法都不生成候选。`ConvertModel` 在同一报告事务内复核 Agent 前缀、选择检查点及当前全部授权，允许后续判定已完成时回取同一候选，不接受调用方正文。无生产控制器/启动装配。

`finalreport.SelectionStage` 与 L0 归属抽取分开：可信装配方从当前授权仓储加载任务题材与最多32份快照，绑定 `closed-report-selection-v1`、最终策略摘要及完整来源/授权副本。模型响应只能是 `{"selections":[{"section":"definition","snapshot_id":9,"sentence_ids":[1,2]}]}`；该片段仅展示一条格式。原引文政策要求四节非空；ADR-0025的显式公司政策只允许选择前三节，公司节由完整审核集合填入，模型返回companies编号则拒绝。其他字段、原始研究报告、重复键/大小写别名、空值、越界、不连续/重复/重叠编号整份拒绝。每条最多8句、每个引文章节最多16条、引文全文最多64条，公司全集最多32行；既有256KiB响应与1000字引文上限不变。

代码回取快照连续字节区间，不接受模型文字/链接/偏移；可信公示与出处由代码注入，排序只按快照编号/原文位置。候选再次通过既有 Decode/Bind，仍不等于章节蕴含或语义安全通过。纯转换策略可作为版本化 `extract` 检查器装配，不改变原 `pipeline.NewExtractionStage`。

`AIReportService.Convert` 默认随终检核关闭，从原用户/任务的已完成抽取检查点读取原始编号响应；先后两次事务核验当前租约/取消/步骤与全部候选来源授权、题材，事务外构建候选。它不调用模型、不增预算、不写阶段结果或报告、不结算。候选 `Payload` 禁止 API 序列化/日志输出，下游 judge 输入摘要绑定任务、抽取键/输入/输出/策略及最终策略；新围栏可复用已捕获结果，不能伪造旧响应。judge 仍须独立预算、Capture/Complete 及 Finalize；来源在转换后撤回仍由最终事务拒绝。详见 ADR-0017。该独立转换核不是完整交付；内部L1固定编排现已复用`ConvertModel`及3.4.2的受限判定步骤，会员读取见2.4.4。生产选择/质量控制器及真实模型验收仍缺失，不据此开放真实调用或完整L2。

#### 3.2.8 报告公司事实准备（ADR-0024，内部只读）

`AIReportService.PrepareCompanies` 在同一报告事务中核对本人任务、原准入、到时/取消状态和原材料当前授权，再读当前已审核资料库的题材及直接环节公司映射。复用可见性约束，以证券代码、环节编号、映射编号排序；最多32条，查询第33条发现超限即整批拒绝，不做模型选择或静默截断。审核人/时点、主/冗余代码、名称、原文/链接/类别/采集时点须完整一致；同一主数据编号出现矛盾、依据不属于原批准快照时无候选返回。读取持有共享锁，提交回执不明同样不返回候选，不写步骤、报告或积分。

输出为不可直接API序列化的内部公司候选，数据行来源是 `library`，节选标记继承资料库，行情为空而非0。空公司集合保留为空，不自行满足最小交付条件。准备核本身不授予发布许可；后续接线须经ADR-0025的首次独立事实摘要、完整执行摘要、双判定及最终当前读。原四节引文政策继续拒绝公司数据行；新增显式公司政策不代表完整L1质量/生产最低交付已验，也不开放真实调用、发布或结算开关。

### 3.3 输出契约

公司报告开发政策见ADR-0025：显式绑定首次`CompanyDigest`与完整执行摘要，前三节仅编号引文，公司节为已审核全集且标`library`。不沿用旧四节引文政策来接纳公司，不允许模型增删或改变顺序。原材料集合全部进入公司证据复核和蕴含输入，可见公司字段进入语义输入；转换、最终提交及会员两次读取在当前事务内重建事实摘要，已知失效拒绝交付/读取，成功结算历史不因后续撤回而倒改。`AIReportSection.companies`仅含名称、代码、环节、逐条出处及节选标记，旧引文章节编码不变；前端显式区分AI整理和资料库人工审核，无行情值或个股详情。该政策仍是关闭真实调用的开发形态，不替代生产最低交付/质量证明。

用户可见节点只有三类：**模板句**、**引文块**、**数据行**。模板句来自封闭谓词库（示意）：

| 谓词 | 渲染示意 | 对象来源 |
|---|---|---|
| `DISCLOSES_BUSINESS` | 〈公司〉（〈代码〉）在《〈来源标题〉》（〈来源类型〉，采集于〈时点〉）中披露：「〈引文〉」 | 引文块，≤ 1000 字 |
| `LISTED_IN_CATALOG` | 《〈目录名〉》将〈对象〉列入〈类别〉 | 官方目录条目 |
| `EVENT_OCCURRED` | 【〈日期〉】〈来源标题〉（〈发布机构〉） | 来源标题**原文**，不由模型改写 |
| `QUOTE_CHANGE` | 〈公司〉（〈代码〉）涨跌幅 〈x.xx〉%（延时 15 分钟，数据时点〈t〉，数据来源〈vendor〉） | 行情数据，代码计算 |
| `EVIDENCE_STATE` | 该命题的证据状态：〈枚举〉 | 枚举：权威披露、多来源一致、存在冲突、仅单一来源、证据不足 |

claim 的结构草图：

```json
{ "claim_id": "c1", "subject": {"type": "stock", "id": 123}, "node_id": 45,
  "predicate": "DISCLOSES_BUSINESS",
  "quote": {"snapshot_id": 9, "start": 1024, "end": 1180},
  "evidence_ids": ["e1"], "provenance": "ai_extracted_quote" }
```

`provenance` 取值：`library`（资料库人工审核内容）、`ai_extracted_quote`、`code_computed`。报告页按它分节标注，"AI 生成"标识只落在 AI 抽取与整理的部分。

**AI 与广告隔离**：广告位不得嵌入 AI 报告页；报告不引用、不排序、不呈现广告主；广告收入与积分账本零过账关联（I9）。依据：《金融产品网络营销管理办法》第二十一条第二款禁止以"投教、课程"名义变相营销，第二十条禁止平台就金融产品互动咨询（requirements 3.3）。

**这是有意为之的取舍**：MVP 不允许模型写自由段落。只有当蕴含裁判的指标达到 AC-E5 且律师确认后，才评估"逐句蕴含校验的受限自由句"（决策 D3 的 B 选项）。

### 3.4 红线检测的细节与一处调研分歧

- 词表单一来源是 `scripts/compliance-forbidden-words.txt`。Go 侧不在运行时读 `scripts/`，而是在构建时复制一份到 `server/internal/ai/guard/words.txt`（`.txt` 不在合规门禁的扫描后缀内），并加一个 CI 守卫：副本与源文件不一致即失败。
- 红线检测要比"用户可见文案词表"更宽：除词表外，还要句式（价位、点位、"建议""预计将""有望""看好"之类）与数值模式。**词表规则不变**：禁止为过门禁删词。
- **两份调研对"引文要不要过红线检测"意见相反**：一份主张引文豁免以免误伤"公告减持"，另一份主张"有据不等于合规"。本方案取严：默认检测；命中的引文不原样展示，截取不含评价词的最小事实子句，截不出就转人工；人工放行须标"原文转载"并留痕。这与 compliance-redline.md 的转载规则一致（原文转载不改、标来源、不加我方定性）。
- 误杀与漏杀：确定性规则可审计、可复现，但合法事实里的词会误杀，谐音拆字、中英混写会漏杀；模型分类器覆盖语义变体但受阈值影响。所以**串联**：任一命中即拦截或转人工，用自建回归集量化两类错误率。

#### 3.4.1 第二道防线（语义分类器 + 抽检）：契约与门槛

确定性层（词表、句式、结构）按设计拦不住的几类，在红队集里以 `known_gap` 逐条登记（`eval/redteam/check_text.jsonl`，数量以夜间评测报告为准）：谐音、拼音与 emoji 替代，Base64 与百分号编码，以及不含任何规则字眼的纯语义改写与绝对化断言（如"没有对手""闭眼入就对了"）。HTML 数字实体与 `\u` 转义已由确定性层"出现即拦"，不在此列。

它们在 L0（内部、100% 人审）里由人兜底；**面向公众的 L1/L2 不能只靠确定性层与人审**，所以公开上线前必须补上这一道并达标（AC-G2 第二层、任务 P4-0）。

| 项 | 契约 |
|---|---|
| 位置 | 串联在确定性层之后，**只增加拦截，不放行**：确定性层或结构校验器已拒绝的，分类器说"通过"也不改变结果。 |
| 输入 | 只有"待展示的最终文本"（模板句渲染结果与引文块文字）。不接触来源全文、用户输入、系统提示词与其他任务数据；无工具、无外联。 |
| 输出 | 枚举 `pass` / `block` / `uncertain` 与原因类别码（枚举，不含自由文本）。只判定，不生成、不改写。 |
| 失败即拦 | 模型报错、超时、预算耗尽、返回格式非法、未配置：一律按 `uncertain` 处理；对公众的路径上 `uncertain` 与 `block` 都**不出报告**（任务终检不通过，释放积分）。**不得默认放行。** |
| 被注入时的最坏后果 | 待判文本本身可能带注入语句。输出受枚举约束，且它只能"不增加拦截"，所以最坏后果是漏拦一条语义类违规（与 `known_gap` 同类），不会让自由文本进入展示层——展示层仍只认模板句与引文块。 |
| 模型 | 受决策 D2 约束：仅国内已备案模型；模型名、备案号、提示词版本与每次判定入调用日志（留存不少于 6 个月）。 |
| 评测 | 评测集 = 红队集里全部 `known_gap` 样本 + 新增语义对抗集（逐版本只增不减）；对照集 `eval/benign` 用于测误杀。指标：对抗样本拦截率、对照样本误杀率。 |
| 门槛 | 起点值（工程经验值，**不是实测**，须产品与法务确认后固化）：对抗样本拦截率 ≥ 95%，对照误杀率 ≤ 2%。没有真实模型的实测就不得声称达标；达标记录写入夜间评测报告。 |
| 线上抽检 | 对已展示的报告文本按比例随机抽检（比例由用户定）；抽检命中即下线该报告，并把样本加入红队集。 |
| 前置 | 模型 API 账号与评估用途来源的法务确认（与 P1-7 同一前置）。缺失时真实调用关闭；受限开发接线见3.4.2，没有真实模型质量实测数字。 |

#### 3.4.2 受限判定执行与纯回放终检（开发接线，真实调用默认关闭）

`Policy.Inputs` 与终检共用输入构造：先 Decode/Bind，蕴含得到候选与本任务来源正文/编号/哈希，语义只得到最终可见文字。`CheckPlan` 固定系统提示、严格 Schema、64输出token、一次请求，不开放工具、重试或路由。判定只接受与类型一致的 `pass/block/uncertain + 封闭理由码`；错模型、截断、无回执、缺失/估计/异常/超界用量、畸形字段都不能产生通过。原始判定正文保留隔离，不进入报告。

`provider.NewDirect` 使用独立无代理传输、禁止重定向/自动重试、16KiB响应上限；HTTP仅接受显式回环IP及端口的本地评估。非秘密摘要绑定厂商、精确端点、模型、时限、响应上限与评估模式，不含密钥；`CheckConfig.ProfileDigest` 必须与实际客户端一致。普通 Provider 不能冒充该适配器。

`AIReportCheckWorker.RunOwned` 在已有租约内执行一个 `judge` 判定步骤，随总开关默认关闭。`ReserveStep` 在原预算事务内绑定下一步与固定操作键，再调用前审计→模型→调用后审计→隔离 Capture/Complete/Load；只有新确认预留可以调用，未知预留/提交结果/缺响应不得补发。独立心跳贯穿网络；失败不伪装任务成功或直接退款，新围栏只复用已捕获结果。检查点不等于报告终检通过。

`CheckEvidence` 是输入哈希绑定的纯回放；计划另绑定不可变任务号（蕴含另含题材编号），执行前核验实际用户/任务/主题，不能跨任务组合两道判定，也不能借同一端点摘要覆盖成另一模型。`NewCapturedPolicy` 核验实际提示/Schema、直连配置、模型/备案与审批/质量/硬预算引用的版本。蕴含不通过可跳过语义，不补造一次调用；蕴含通过而缺语义不能构造可放行策略。最终候选仍使用独立 judge 检查点及原 Finalize 原子结算，重放不再调用 Provider。该本地候选步骤的预算预留是保守上界，不宣称实际发生模型调用。

必须显式提供当前准入和持久审计 `AIReportCheckControl`。本仓库没有生产放行实现，非空归档引用不是证明，测试控制器只在测试文件；判定步骤没有独立CLI或公开执行路由。`AIL1ReportWorker`已在内部固定串联Agent、受限编号选择、授权证据回取、蕴含/语义及原子终检提交；有限批次沿用该核，会员报告页面和默认关闭的读取装配见2.4.4。模型真实质量、生产选择/发布控制器及远端硬预算仍未验，不将测试接线当作生产自动装配或完整L2。详见 ADR-0018/0019及后续准入绑定契约。

### 3.5 提示注入防御

- 抽取模型无工具、无外联，输出被 schema 约束；来源正文用定界符包裹并明示"以下是数据，不是指令"。
- 来源进入前：NFKC 规范化、去零宽字符、剥 HTML、按上限截断。提示词注入检测模型只作**告警信号**，不作安全边界（其评测语种多不含中文）。
- 控制流与数据流分离：规划只见可信输入，数据只经隔离模型解析，后果性动作只由代码执行（CaMeL 一脉的思路，research.md 第 3 节）。
- 前端渲染 AI 文本与链接一律转义，链接仅白名单域（OWASP LLM05）。

### 3.6 采集器

只访问 `tm_ai_sources` 里启用的域名；拒绝解析到内网、回环、链路本地的地址（含 DNS 重绑定后的二次校验）；限制响应体大小、重定向次数与总时限；遵守来源的访问频率约束。**免费行情或网页接口（AKShare、yfinance、新浪腾讯东财、通达信、问财、Tushare 个人账号）只可本地开发对照，不得进生产**，除非取得书面授权；这与 compliance-redline.md 的行情数据授权一节一致。

## 4. 任务编排与积分账本

### 4.1 为什么自研

冻结与建任务必须**同一 MySQL 事务**，而现成方案做不到或代价过高：

| 方案 | 仅 MySQL | 额外进程 | 冻结与建任务同事务 | Go 1.24 可用 | 结论 |
|---|---|---|---|---|---|
| **自研状态机（推荐）** | 是 | 无 | 是 | 是 | 约 600 行加崩溃注入测试 |
| go-workflows | 是 | 无 | 否（建实例自开事务） | 否（要求 Go 1.25） | 预发布、无版本管理 |
| Temporal | 是（8.0） | 四个服务 | 否（需 outbox） | 否（SDK 要求 Go 1.26） | 过重 |
| Hatchet、River | 否（PG） | 有或无 | 否或仅 PG 内 | 否 | 不选 |
| Asynq | 否（Redis） | Redis | 否 | 是 | 违背少中间件 |
| Eino、adk-go 等 AI 框架 | 无持久化 | 无 | — | 视版本 | 自主工具回路不适合 |

取舍：自研要自担租约与恢复的正确性，由第 4.4 节不变量与崩溃注入测试兜底。升级触发条件：阶段数 ≥ 10、出现人工审批、天级定时或跨服务编排时再评估 Temporal，并以 `task_no` 作 workflowID。

### 4.2 数据模型（已落迁移部分与其余草案）

表名统一加 `tm_` 前缀：这是 tm-stock **自有**表，避免重蹈 F7（与 GVA 的 AutoMigrate 同名冲突）。时间字段用 `DATETIME(3)`，所有写入显式使用 UTC（不依赖会话默认时区），对外返回毫秒时间戳。积分一律有符号 `BIGINT`，不用浮点。

账本结构的权威定义是 [`20261011_create_points_ledger.sql`](../../../server/migrations/20261011_create_points_ledger.sql)，不再在此复制 DDL。共有八张表：账户、流水头、批次、分录、冻结单、冻结分摊、欠款、欠款抵扣分摊。流水记录完整请求摘要与全局唯一幂等键；所有关联都通过复合外键约束同用户归属；只增表禁止修改/删除，快照禁止改身份、来源、锁价和原始数量，冻结终态禁止再改。数据库只保证行级约束，不保证分录汇总或业务类型与关联事件的语义，后两者由 P3-2 服务事务与对账承接。

`cmd/points-check` 以回滚事务验证版本、金额列、外键、唯一键、强制 CHECK、真实拒写行为与冻结终态保护。业务账号只需八表的 SELECT/INSERT/UPDATE/DELETE，不需 CREATE/ALTER/TRIGGER；不可变由数据库触发器拒写。探针可能消耗自增编号，不能把序号连续当作业务正确性。此入口不迁移旧积分、不启用收费；任务联合自检已复用该校验器并接入恢复型 worker（4.2.3），其他未来账务/执行路径仍须接线。

账务核心已实现于 `internal/points`、`internal/service/points*.go` 与 `internal/repository/points.go`。服务拥有事务边界，仓储暴露同一 SQL 事务适配器；任务创建和非成功终态已复用 `FreezeInTx` / `FinalizeInTx`，未来报告提交亦须复用，禁止另开账务事务。收据只含首次操作的不可变结果，重放不返回已变化的余额或冻结状态；同键异请求拒绝，结算金额只能取冻结单锁价，不接受追加 token 扣费。

流水还以 `(kind,biz_type,biz_id)` 全局唯一防止换幂等键重复入账；业务编号须包含全局命名空间，如 `signin:<user_id>:<date>`，不可只用用户内序号。数据库时点取 `UTC_TIMESTAMP(3)`，DATETIME 参数和扫描采用 UTC 字符串，避免 MySQL 驱动 `loc` 将无时区字段再次转换。新冻结同时核对账户余额和已生效、未过期批次；账面 `avail` 不等于完成过期清扫后的即时可用额，不可直接当作 C 端报价依据。

`ReverseInTx` 仅整笔冲正原始入账，`reverses_id` 唯一保证一笔原单最多冲正一次；只回收该批次剩余积分，不挪用其他批次本金，已消费/用于抵扣的部分形成欠款，已写过期分录的部分不重复记欠款。批次仍有冻结时拒绝冲正，须由上层先终结关联任务，不能破坏锁价。原流水不改写，冲正与欠款同事务提交，购买批次仍暂拒设置有效期。

后续赠送、贡献、签到奖励在**入账时**优先抵扣欠款，不等待消费生效时间；生效时间只约束剩余奖励的使用。按欠款 id 升序分摊，购买本金不抵扣；奖励正入账与 `debt_offset` 负分录各有不可变流水，分摊关联奖励批次与欠款，账户只增加净剩余奖励。入账收据中的 `Amount` 是不可变原额，不能当作净到账额；撤销已抵扣奖励会重新形成欠款，不回写历史抵扣。内部抵扣幂等键由奖励流水编号与用户的摘要确定，唯一业务编号为 `grant:<流水编号>`。

同事务调用不能假设上层尚未建立 REPEATABLE READ 快照。重放批次、冻结单与分摊、冲正过期额及对账均采用当前读，在账户锁之后读取同用户事件；普通 SELECT 的旧快照会导致漏读新分摊，甚至把已记账过期额错误记作欠款。回归测试先固定旧快照，再由另一连接提交入账/冻结/过期，验证重放、终结、冲正与对账。对账强制使用用户前缀索引，冻结/欠款分摊各补一个用户索引，结构自检检查七个用户范围索引的列序与可见性，防止持锁查询退化为全表扫描。RR 仍有范围/间隙锁成本，单用户事务受超时约束，不能据此宣称生产大历史量压测已通过。

当前对账检查账户/批次/分录/冻结分摊、欠款原额与抵扣分摊，并从流水类型与关联事件重建应有分录；任意精度求和防溢出漏报，结果按代码与记录编号排序。缺少事件、额外分录、购买批次参与抵扣、欠款与账户一起减少而无抵扣分摊均能检出。尚缺任务锁价关联与批次过期清扫，不构成阶段 3 完整验收。

`cmd/points-audit` 装配同一结构自检与账本服务，默认单次，也支持显式 `-interval` 定期运行。每轮读取账户主键上界后按主键游标分页，逐用户单独事务对账，不持全库大事务、不修余额、不创建缺失账户。每用户事务上下文期限 30 秒，整轮另有可配置期限；异常账户输出 JSON 告警后继续，数据库/告警通道故障或超时则中止并标记 `complete=false`。标准输出与纯内存计算不支持强制中断，故该期限不是操作系统级硬超时，部署仍须有进程监督与完整轮次新鲜度告警。单次异常退出 2，未完成退出 1，中断退出 130；周期模式失败后等待再从头重扫，同一进程不重叠，不宣称跨进程独占。它只提供告警采集出口，未连接线上告警平台或部署调度。各用户是独立时点快照；扫描期间新建的低编号账户可能在本轮游标之后才出现，须下一轮覆盖；不是严格的全库同一时点审计。大历史量可能令轮次持续超时，不能仅看进程存活，必须监控完整轮次与覆盖范围，调整期限或排查阻塞账户，禁止忽略失败而假报健康。启动约束探针仍执行写入后回滚并可能消耗自增编号，不是仅 SELECT 权限的命令。

任务与进度事件已落地 [`20261011_create_tm_ai_tasks.sql`](../../../server/migrations/20261011_create_tm_ai_tasks.sql)，须在积分账本迁移之后执行；不复用 L0 同步运行表。任务固化 `analysis_type`、`subject_type`（仅 `theme|topic`）、`subject_id`、锁价、预算、冻结单与截止时点，冻结单按同用户复合外键一对一关联；主数据/授权解析仍由后续可信入口负责。进度事件只有类型、状态、步骤编号及白名单错误码，不保存自由正文；CHECK 同时限制事件类型/状态/错误码的组合。任务身份与策略不可变、终态不可改、事件只增不改。

`AITaskService.Create` 先锁账户、按用户和键当前读重放，再用服务端随机任务编号冻结、建任务、写首事件，同事务提交；创建收据不可变，价格/预算配置变化不改变已有任务的重放。父事务适配器返回的结果在父事务提交前不得对外返回。创建失败/提交未知结果返回空收据，未知结果只能按原键核查。失败、排队取消、到期释放与任务终态/进度同事务，运行中取消仅置请求，worker 在边界确认后释放。

抢占采用“候选提示 → 账户锁 → 任务当前锁 → 再验时点/状态 → CAS”而非先锁任务再追加账户锁，防止清理/取消与抢占逆序死锁；候选查询不授予执行权，碰到已被抢占的候选即放弃。心跳只锁任务，不访问账务；所有 worker 写入核对 owner、fence 和未到期租约，续租不倒退、不越过任务截止时点，旧 worker 不能续租或终结。接管增加 fence 与 attempt，重试只排队、不再冻结；重试次数耗尽或无剩余时间时失败释放。所有时点取数据库 UTC，用户不提交租约/金额/预算。这一候选路径尚未完成大队列吞吐/公平性压测。

`AITaskSchemaVerifier` 与 `cmd/ai-task-check` 已实现任务核及账本依赖的回滚自检；不运行迁移、不读取 GVA 旧积分，也不修复历史。单个 READ COMMITTED 事务验证实际连接的 MySQL 版本/严格模式/外键开关、账本结构与拒写探针、任务全部运行列/二进制字符口径/索引/FK/CHECK，以及身份/单调状态/四种终态/历史的真实拒写。随机高位用户和新任务只 INSERT，不覆盖既有记录；任何非预期错误均失败关闭，成功及失败均回滚，可能消耗自增编号。业务账号不授 TRIGGER，故不用触发器元数据可见性代替实际保护行为。15 秒探针期限、20 秒命令期限，诊断出口隐藏驱动详情及凭据；不声称覆盖未知的任意 CHECK 改写或历史一致性。

#### 4.2.1 调用前持久化预算预留

固定L1统一编排核 `AIL1ReportWorker` 见ADR-0019：可信计划包含任务绑定Agent计划、同一批准模型、授权快照及终检配置；预检整条链路保守容量，再固定执行Agent→编号选择→蕴含→语义→本地候选→原子Finalize。蕴含未通过不补语义调用；只有已知拒绝/取消走原失败释放，未知响应/审计/提交继续保留原键及冻结。Agent独立入口仍使用单操作约束，Owned入口只复核或执行步骤1。所有网络阶段独立续租，候选准备结束后先收回心跳，再续足一分钟租约进入30秒终检，避免心跳把已成功终态覆盖成错误。缺少真实准入/审计控制器不能启用，当前已有默认关闭的HTTP提交、会话意图与报告读取入口，以及L1/L2有限批次和可取消轮询核；最新隔离H5已验证深度会话交付及一次结算。正式API仍向创建/报告准备函数传入空可信控制器，ai-worker命令仍仅支持恢复，尚未装配生产规划器和常驻执行入口，不能直接开启功能。深度执行规划与复核须同时检查上下文、当前模板、任务身份、派生操作键及预算；模板摘要刻意排除任务身份，不能单独作为执行归属证明。

已知来源拒绝覆盖规划与外呼前后的边界。先以当前读排除未知调用，避免领取时的尝试耗尽路径提前终结；再取得当前围栏，在同一事务重查原准入、预算明细和已完成阶段/事件前缀及原冻结身份，原子提交失败与释放。若还有未完成预留，返回`response_unknown`保留原键/冻结，不把来源拒绝冒充调用已知。依赖、普通404、配置或计划冲突保持错误，不由此取消原任务。拒绝事务失败返回空收据，已提交但回执未知只重读原终态，不补外呼或重复释放。

共用`finishTask`在所有失败终结写账前按当前锁复核预算及每个预留的原始响应，覆盖普通领取的尝试耗尽、直接失败和重试/退避容量耗尽。响应缺失返回`ErrUnconfirmed`、事务回滚，保留原尝试/围栏/事件/冻结；领取的三个worker入口只重读原本人任务并返回`response_unknown`，不重发或创建报告。读取故障、预算/摘要/身份/阶段/资源异常均失败关闭。只有步骤零、无任何预留的旧任务允许没有预算记录；有效Capture只是已知响应，不证明检查点或报告质量，已知失败可以按原政策释放。来源拒绝的更严格完整前缀证明不放宽，明确取消和实际到期政策不变。没有新增表、公开DTO或真实执行开关。

ADR-0011 采用保守预留而非事后扣量：`tm_ai_task_budgets` 固化任务限额和预留累计，`tm_ai_task_reservations` 追加不可变操作。模型操作至少预留调用数与输入+最大输出 token 上界；页面采集可只预留页数。所有维度非负，操作不能全零，每任务明细至多 1000 条。任何已提交预留均不退款/清零；未知调用不能当零消耗，预留不是实际供应商用量，也不决定用户应扣积分。

`AITaskBudgetService.Reserve` 只接受可信 worker 的任务/会员、owner/fence、幂等操作键、封闭输入摘要和上界；不接 C 端或 HTTP。10 秒事务先锁任务、核对数据库 UTC/租约/取消/期限，再锁预算与按序当前读明细（RR 旧快照不能漏读），核对每条、累计与限额。相同键/摘要/上界复用且 `NewlyReserved=false`，不比较为新一轮接管伪造的执行身份；改变输入冲突。首次明细与计数器增量由 SQL 同事务执行，服务确认计数器符合期望后才提交；提交未知或任一步失败只返回空收据。预算不足只拒绝预留，不隐式改变任务或积分；未来调度器负责终结任务/释放冻结。

初始化预算采用直接 INSERT：只有明确的 MySQL 1062 表示“已存在”，随后仍须按用户/任务当前读核对全量限额与明细；不在 INSERT 前锁不存在的预算行，不用 IGNORE 或无条件 upsert 吞掉其他错误。插入成功的新预算由复合 FK 证明尚无明细，不再对空明细区间加锁；任何已存在的预算即使计数为零也仍读取明细。真实 40 个不同任务、连续两轮预留的 RC/RR 用例专门守住首次初始化的空区间锁死锁，不据此宣称大队列吞吐已经压测。

`cmd/ai-task-check` 的联合 Verify 已加入这两张表的结构与实际拒写探针；缺表也拒绝通过，业务账号仍无需 DDL/TRIGGER 权限。探针检查限额初始化、整数/二进制字段、索引、归属、租约/围栏、序号、超限、明细不可变及计数器对应增量；有限反例不是对任意 DDL 改写或全库历史的证明，未知的旧表仍须先迁移和核查。

数据库 CHECK/FK/唯一键和触发器约束初值、限额身份、序号、当前 owner/fence/租约、不可变明细、计数器对应增量及超限。预算和明细只锁任务相关行，不取账户/冻结单锁；不会与账务路径形成反向锁序。保守容量 1000 条意味着每次最多核对 1000 条明细，未做大队列吞吐压测。旧任务无预留时初始化仅从当前不可变预算复制上限，不追认历史调用为零；没有历史调用证明的旧运行不得借此接入真实 worker。

验收包括正向模型/页面预留、相同键重放、改输入冲突、40 并发同键/不同键、RC/RR 与父事务旧快照、接管不重置、取消/租约拒绝、整数边界、SQL 审计故障/缺保护回滚、双表对账和联合自检。当前服务不执行网络：未来 worker 必须另行强制硬上界/有效租约，未满足 TradingAgents-CN 远端预算与来源条件前仍不能调用真实多 Agent。

#### 4.2.2 隔离响应与阶段检查点

ADR-0012 将阶段保存分为 `Capture → Complete → Load`。仅内部能力，没有 HTTP 或实际模型调用；恢复型 worker 只接 Complete/复用，不补捕获响应（4.2.3）。阶段类型封闭为 `collect/extract/judge/agent_call`，编号 1..64；必须绑定已存在的预算预留及相同输入摘要。`collect` 要有页数预留，其余要有调用/token 预留；不为纯代码校验/渲染伪造资源消耗。

`tm_ai_task_step_results` 不可变地保存原租约收到的脱敏 JSON 响应；严格结构检查与 SHA-256 只是隔离完整性，不是事实通过。Capture 仅接受当前下一个阶段、有效且与预留一致的 owner/fence，重复相同内容只返回既有元数据，改内容冲突；提交未知只返回空收据。先 INSERT 再当前读，避免锁空索引区间；跨接管不能补造旧预留的响应。

`AITaskStageService.Complete` 先在有限事务当前读响应与任务，再在事务外运行固定策略的纯校验函数；校验输入中的正文为不可变字符串。校验失败只返回固定错误，保留隔离数据、不推进进度；最终重新当前读并复核租约、取消、期限、原内容和策略。`tm_ai_task_steps` 的 INSERT 通过触发器同事务推进步骤/事件，服务核对写后结果才返回已确认收据。已有检查点只有输入、响应、策略摘要与不可变事件均一致才复用，策略改变拒绝；任意失败、提交不明不返回候选成功状态。

`Load` 只给有当前租约的可信内部 worker 读取已完成检查点，正文始终隔离、不进入 JSON/公开 DTO 或事件。新 worker 可完成之前已捕获但未校验的响应，不再调用模型；缺响应返回未知/不存在，不自动补交。用户取消、过期、旧围栏或跨用户一律拒绝。进度事件仍仅状态/步骤/白名单错误码，任务维持 running，报告可用性不改变，也不结算积分。

联合自检须核对两表、外键/索引/字段、不可变保护、原预留绑定、阶段初值/连续推进和事件原子性。验证包含捕获/重放/改内容、错误输入、策略变化、校验拒绝、校验期间取消/接管、40 同任务及独立任务并发、父 RR 旧快照、真实提交未知与 SQL 故障回滚、保护破坏及受限命令。该存储验证不是阶段校验质量、来源授权或完整 worker 恢复的验收。

#### 4.2.3 恢复型 worker 与有限命令入口

ADR-0013 规定 `AIRecoveryWorker` 不持有外部执行器，不创建预算预留、响应或任务。`cmd/ai-worker recover` 只接受明确的会员/任务编号和可信本地计划文件；32 KiB 内的严格 JSON 对象只有 `steps` 数组，每步只有 `snapshot_id` 和 `operation_key`，1..64 步，按数组位置连续编号。重复/大小写歧义/未知字段和非法值拒绝，计划不接受正文、URL、模型配置、自由问题、输入摘要或通过标志。

`AIExtractionRecoveryPlanner` 只支持题材 extract：按任务固化的 subject_id 精确读取当前题材名称，读当前授权仍有效且副本匹配的来源快照，重建固定纯策略及输入摘要。计划绑定会员/任务/原任务编号与完整步骤前缀；构造失败不接管。每个步骤校验前后重新读取来源/题材并比较原摘要；不能据此宣称来源授权与检查点提交间的撤回竞争已完全封闭，报告路径仍须独立核验。专题或其他阶段不猜测处理。

命令先做任务/账本联合回滚自检，再有限 Inspect/过期检查/Claim。核心清理已取消或尝试耗尽的任务时不构造来源计划，不受来源失效阻塞；CLI 前置仍要求格式有效的封闭计划和自检通过，不能把任意坏文件当清理入口。有活跃租约不能重复接管。已获租约后独立 goroutine 心跳，失败取消上下文并等待退出；每步依次核对所有已完成前缀，未知/损坏前缀不跳过。完成计划只输出 `report_pending`，任务仍 running、冻结不变、报告不可用；缺响应为 `response_unknown`，不重发、不新预留、不自动退款。确定性拒绝沿现有失败事务释放，已请求取消由有效围栏确认，其他数据库/提交/进程/来源错误保留现场；到期只走原 Expire 事务。

默认租约 60 秒、心跳 20 秒，单轮恢复最多 5 分钟；心跳单次上下文最多租约的三分之一，不与发起间隔混用，父上下文可进一步收紧，所有租约资格仍由数据库 UTC 裁决。命令返回/中断停止心跳，不自动重复，租约到期后再接管会消耗既有 attempt 限额。内部选项允许测试缩短时间，但不暴露 Provider、故障注入或默认成功策略。恢复命令本身没有全队列调度或自动清扫，禁止当生产周期任务反复执行来代替完整 worker；显式有限清扫由 4.2.4 的独立命令负责。

操作账号需十四张账本/任务/预算/阶段表的 SELECT/INSERT/UPDATE/DELETE，以及来源三表与题材主表的 SELECT，不需 DDL/TRIGGER 或来源写权限。成功输出仅有任务编号、状态、当前/计划步骤、封闭 outcome、固定 false 的报告可用标记；退出码 0 为恢复完成待报告/已有终态，2 为响应未知，1 为未完成，130 为中断，不能把 0 当成任务成功/已结算。

验收包含 RC/RR 的多阶段恢复/重放、未知响应、拒绝释放、取消/来源撤回/主数据变化、独立心跳取消、真实事件故障回滚；独立测试二进制在校验阻塞时被杀死、旧租约到期后新围栏继续校验，原预留/积分不重复；实际编译命令验证已有/未知响应、受限账号、来源停用与缺保护拒绝。测试阻塞校验器不进入产品。真实 Agent、全队列容量、公网上线、报告/结算及全部事务边界崩溃验收仍保持开放。

#### 4.2.4 显式有限过期清扫

`AITaskExpiryService` / `cmd/ai-task-expire` 依 ADR-0014 单独清理已有任务，不构造来源计划、不抢占租约、不重发未知调用。启动先做联合自检，命令不自动启动、不挂公开路由、不配置生产周期任务。预算、隔离响应和检查点不因清扫删除或清零；未生成报告、不成功结算，也不清扫积分批次自身的有效期。

一次读取 `COALESCE(MAX(id),0)` 与数据库 `UTC_TIMESTAMP(3)` 固定可见上界/截止时点。主键 `(after,upper]` 范围升序读 id、user_id、status、deadline，所有状态均计入扫描量；不在无期限索引的过滤结果后 LIMIT，不新增迁移。时间经 CHAR 与 UTC 解析，不受驱动/会话时区影响。先校验完整页的单调游标、范围、会员、状态与毫秒期限，空页未到上界视作错误，不假报完成。

服务仅把截止时点已到期的 queued/running 候选交给既有 `Expire`，其当前锁和当前数据库 UTC 再裁决。竞争者已终结则保持原终态；时钟回拨尚未到期则跳过，下一轮重查。账户/冻结/任务/事件仍在原单任务事务，其他任务不会因本页后项失败一起回滚。任何错误/提交未知都停止，返回已确认游标及部分统计，失败项不越过游标。`expired_observed` 含竞争者已过期后本进程读到的终态，不是写入计数或模型用量。

选项为 after≥0、page-size 1..1000、max-tasks 1..100000；服务最长五分钟并服从更短父期限，命令默认 after=0、page-size=100、max-tasks=1000、timeout=30s。限量未读完返回可续扫但不完整；自检最多20秒，整段输出不是操作系统级硬超时。只读分页不跨整个清扫保持快照：Complete 仅表示本轮可见上界读完，新提交/较小自增编号晚提交/刚到期任务仍需新轮从零扫描。续扫每次重新取范围，禁止把 after 永久作为全局水位。

退出码：0=本轮可见上界读完，2=正常限量可续扫，1=参数/自检/访问/输出/未知提交失败，130=本地中断。标准输出仅封闭事件、固定提示与范围/统计，不含 DSN、正文、操作键、租约或原始错误。未知/输出丢失后原任务重读或从零重扫，不补扣、不重发，也不承诺远端执行已停止。权限同联合自检的十四张表 DML，无 DDL/TRIGGER/来源/会员权限。

#### 4.2.5 任务与外部 Agent 的关闭接线核

依据 ADR-0015，`AITaskAgentWorker` 将显式已有任务的第一步 `agent_call` 接到既有 `AIAgentService` / TradingAgents-CN V2 适配器，复用预算预留、隔离响应/检查点和独立心跳。只有内部接口，没有生产规划器、启动装配、公开路由或新执行命令；`agenttask.Options.Enabled` 默认 false，关闭时连任务读取/抢占也不执行。不会因既有 Agent 开关或会员读取开关打开而自动运行此核。

`agenttask.Planner` 是可信准入边界：构造绑定会员、任务/任务号/主体的 Plan，证明题材或专题与股票代码的可信关系，独立内部操作人、固定配置和保守资源上界，并在关键边界 Recheck 当前来源/许可及远端硬预算。当前上游 V2 缺上述证明，产品没有默认放行实现；测试规划器不进入产品。普通上游调用次数上限不能替代 LLM/token/页数/金额上限，也不把上游默认 token 数当用量。

请求编号与唯一预留键由固定 `agent_call:1` 域和会员/任务/不可变任务号派生。计划内变更股票、操作人、配置或资源不会换远端键，但会改变输入摘要，与旧预留冲突；人为改预留键直接拒绝。`ReserveSingleOperation` 与原 Reserve 共用当前锁事务，额外拒绝其他键、多项预留或不一致进度；不会先启动远端，再发现任务已有其他阶段。此核尚不能嵌入任意既有多阶段流水线。

先规划/准入，再 Claim；独立心跳贯穿数据库与 HTTP，父期限最长五分钟且可收紧。租约与心跳沿既有选项，轮询间隔50毫秒..5秒。原预留重放但无执行登记为 `response_unknown`，不补交；新预留也必须重新核对心跳/准入才 Submit。复用原持久登记的提交最多一次/取消未知保护；网络不持数据库事务。查询到上游完成后获取并隔离结果，再捕获四字段回执、事务外纯校验和原子检查点/事件。

回执只有 RequestID、RemoteID、ProfileDigest、ResultDigest，精确编码与输入摘要绑定；没有正文、引文、金额或用量。不与抽取/蕴含裁判共享放行策略。检查点只把当前步骤推到1并返回 `evidence_pending`，任务仍 running、积分冻结不变、报告始终 false。上游终态不等于本项目业务终态，返回 `upstream_terminal` 后仍须独立处理。用户取消、网络/提交/上下文/准入错误不自动退费、终结或远端取消；原运维/取消/过期路径继续有效。

上游确认失败/取消采用独立版本的终态回执，第四字段为封闭State而非ResultDigest；原成功回执的编码/策略不变，二者不可互用。先Capture→Complete确认阶段回执/检查点，才返回`upstream_terminal`供L1复用原失败/释放同事务核；不读取研究结果或调用选择/蕴含/语义模型。持久确认、阶段提交或失败终结回执不明时不返回候选成功，原键重放可在原有效围栏复用已保存响应；旧围栏缺回执仍不补造，L1将`capture_pending`归一为`response_unknown`以供有限队列处理。独立Agent入口不自行终结任务；上游取消不等同于会员取消或报告交付。

跨预留与上游登记、上游隔离与任务回执分别是独立事务：前者断点保守未知；后者有任务回执可复核，没有且旧预留围栏已失效时为 `capture_pending`，不能补造旧响应。没有承诺消除所有跨系统崩溃窗口。新的公开报告路径必须转换为绑定授权快照的封闭事实，经语义第二道防线/当前授权终检后，同事务保存报告、任务成功和积分结算；完整公开链路尚未接通，关闭的内部终检/提交核见4.2.6。

#### 4.2.6 关闭的报告终检与原子提交核

依据 ADR-0016，新增 `internal/ai/finalreport`、`AIReportService`、`AIReportSchemaVerifier` 与 `20261016_create_tm_ai_report_commits.sql`。这是内部开发核：没有生产回调/规划器、公开路由、执行命令或对原 worker 的自动注册；构造选项默认关闭，关闭时不读取任务/配置或访问模型。现有会员读取继续固定报告不可用，不因内部成功状态暴露正文。

输入是原预算/隔离结果/完整连续检查点，末步必须是匹配策略摘要的 `judge`。预留数量必须等于步骤数且逐个对应，存在未知/未完成预留拒绝成功。首版只接题材 L1 保守引文档案：四个固定章节各至少一条不同引文，全部为 `ai_extracted_quote`，公示模型/备案号来自可信配置。规范 JSON 编码逐字一致；自由句、模板参数、公司行/行情、L2、专题、节选、人工转载标记和自报来源标题都拒绝。此工程测试下限不等于生产最小可交付政策已确认，也不替代已审核公司库。

初读释放事务后做结构/证据校验，来源读取与最终提交分别当前复核。账户→任务→预算/检查点/冻结单，再按来源编号共享锁定来源、快照/正文和题材；来源授权副本必须与当前登记一致且有效。逐项核对 UTF-8 偏移、逐字文本、内容哈希、精确规范链接、采集时点及来源类别。最多32个快照、每份正文1MiB、合计4MiB、每份10000句，报告隔离结果沿用256KiB上限。来源撤回与提交被共享锁串行裁决；按数据库UTC判定到期，不声称授权到期时间在提交之后仍有效。

蕴含与语义回调必须显式版本化且受限纯校验，没有默认通过实现。蕴含只接本任务候选及来源正文/编号/哈希，不接许可归档或账户；语义只接最终可见文字，不接来源全文/URL/许可。`block / uncertain / 非法枚举 / 校验错误` 均不出报告；上下文取消或存储结果不明保留现场，由原取消/过期机制处理。不引入真实 Provider，不把测试回调当作第二道防线的质量验收。策略摘要绑定本包版本、确定性规则摘要、域名、公示与两个校验器版本；规则语义变化须递增版本。

最终重新验证后复用原 `FinalizeInTx`：锁价结算/释放、任务终态及事件、`tm_ai_report_commits` 在同一 SQL 事务提交。成功收据才含不可变报告 JSON；失败收据只留摘要、策略、封闭判定/原因码，无候选正文。FK/CHECK/真实拒写探针保护任务、检查点、事件、终结流水绑定与收据不可变。失败、未知提交不返回候选成功收据；原任务/键重放核对全链与锁价/流水哈希，既不再校验也不重复结算；更换策略拒绝，不删隔离数据或清零预算。合法取消优先走原取消释放路径，不伪装远端已停止。

`AIReportSchemaVerifier` 在一个回滚事务核对十五张账本/任务/预算/阶段/提交表的元数据与真实保护，不要求TRIGGER元数据权限，不自动迁移。未来真实入口须先装配此自检。来源三表与题材表仍需SELECT；本地仅验证MySQL8.0.46/9.7.0的共享锁权限，不据此承诺其他部署版本兼容。该核不执行抢占/心跳、不构造或捕获报告；完整编排器仍须以既有租约机制维持校验期间的资格。

验收包含两个隔离级别的成功/拒绝与原键重放、来源撤回/到期/授权副本变化/主数据改名、共享锁阻止并发撤回、取消成功互斥、旧围栏/新租约复用、40并发单报告/单结算、实际事件/账务/报告故障回滚、真实提交后回执未知、受限账号和六类自检破坏。没有新增本支线杀进程证明，也未完成上游原文→合规事实的自动转换、真实语义/蕴含评测、完整L1/L2或会员交付。

### 4.3 状态迁移（每行一个单事务）

CAS 写法：`UPDATE … WHERE id=? AND fence=? AND status=?`，影响 0 行即放弃（别人已处理）。

| # | 触发 | 迁移 | 同事务内的账务与事件 |
|---|---|---|---|
| 1 | 创建服务（公开 POST 待接） | ∅ → 排队 | 锁账户行、重放当前读；服务端随机编号；冻结与分摊、流水、分录；插任务与事件 #1；同事务提交 |
| 2 | 抢占服务（worker 调度待接） | 排队，或运行且租约过期 → 运行 | 候选仅提示；账户→任务当前锁后复核状态/时间，CAS 置租约、`fence+1`、`attempt+1`；超过重试上限走 7 |
| 3 | 心跳 | 运行 | 续租；0 行即被抢占，立刻取消本地上下文 |
| 4 | 阶段完成 | 运行 | CAS 写步骤、`current_step+1`、`event_seq+1` 并插事件 |
| 5 | 可重试失败 | 运行 → 排队 | CAS 置 `not_before` 退避；**不碰账务** |
| 6 | 终检通过 | 运行 → 成功 | **同一事务**：插报告 + CAS 成功 + 冻结单 CAS 结算（只按锁价） |
| 7 | 失败、预算或重试耗尽 | 运行 → 失败 | CAS + 冻结单 CAS 释放 |
| 8 | 用户取消 | 排队 → 取消；运行则置 `cancel_req`，在阶段边界或上下文取消后 → 取消 | 释放 |
| 9 | 超过 `deadline_at`（抢占循环顺带清扫） | 排队或运行 → 过期 | 释放 |

Provider 全部熔断时，创建前直接返回 50201，**不冻结**。

### 4.4 不变量

- **I1 单任务单冻结**：冻结只出现在创建事务；重试与恢复路径不含冻结代码；`uk_tm_points_hold_biz` 与 `uk_tm_ai_task_hold` 兜底。
- **I2 终态互斥**：结算与释放只由终态 CAS 成功者在同一事务写；0 行即别人已终结；取消与结算的竞态由 CAS 裁决。
- **I3 围栏**：worker 的所有写入带 `fence` 与 `status`，被抢占的旧 worker 晚到也写不进。
- **I4 租约**：租约 60 秒、心跳 20 秒且在独立 goroutine（不依赖模型调用返回）；时间一律取数据库 `UTC_TIMESTAMP(3)`，不用进程时钟；心跳失败即取消上下文。（均为起点值，压测后定。）
- **I5 步骤幂等**：调用前持久化保守预留；同操作键重放不再取得新预留，未知结果不自动重发（ADR-0011）。返回后先隔离落库再在事务外校验，恢复只复用输入/内容/策略摘要及事件均一致的阶段结果（4.2.2、ADR-0012）；确定性抽取纯策略与有限恢复命令已接线（3.2.6、4.2.3），其余阶段/全量执行未接。另一次策略允许的尝试必须用新操作键并继续占原任务预算，不能把本地预留当作远端硬上界已经生效。
- **I6 锁价**：`price_ver` 在创建时固化为 `price_points`，结算只用它，**不按 token 补扣**；token 只供成本核算。
- **I7 余额非负**：`CHECK` + `UPDATE … WHERE avail >= ?` 并校验影响行数 + 用户行锁；**没有"信任旁路"**（不因余额远大于预扣就跳过预扣）、没有欠费通道。
- **I8 对账**：从零累计，初始入账也写正分录；批次 `remain` = Σ 该批次全部桶分录 `delta`，**不能再加 `total`**；批次 `frozen` = Σ 冻结桶分录，`remain − frozen` = Σ 可用桶分录；账户 `avail` = Σ(批次 `remain − frozen`)，账户 `frozen` = Σ 批次冻结 = Σ 非终态冻结单金额，账户 `debt` = Σ 欠款未抵扣金额。每个冻结单的分摊之和必须等于锁价；欠款原额减抵扣分摊之和等于未抵扣金额。定时任务告警，测试中人为破坏后必须检出。有效期不抹去账本余额；过期扣减必须写负分录。
- **I9 广告隔离**：广告收入与积分账本零过账关联；账本的消费目标白名单只有内容解锁与 AI 任务，**不得兑换会员**（沿用已确认需求第 1 条）。

### 4.5 并发与锁（须在目标 MySQL 版本实测）

单事务内先 `SELECT … FOR UPDATE` 锁账户行（同用户串行），新冻结按 `(prio, exp_at, id)` 锁批次，终结按分摊 `lot_id` 升序锁批次；同用户账户锁在两种路径之前，避免相互交叉。条件更新检查影响行数，写流水与分录后提交；幂等靠唯一键并捕获重复键错误；不用 Redis 先行扣减；系统汇总账户不存运行余额（防热点）。账本核心已在本机 MySQL 8.0.46 / 9.7.0 的 READ COMMITTED 与 REPEATABLE READ 下验证 200 并发冻结、同键入账、终态竞争与事务失败回滚。任务创建、抢占、失败/取消/到期释放已接入同一事务适配器，默认 READ COMMITTED；全局锁顺序为账户→任务→冻结单/批次，纯心跳只锁任务且不反向追加账户锁。抢占候选不是租约，须在事务中重验 owner/fence/租约/期限；候选扫描的积压吞吐与公平性尚未压测。内部任务核不等于独立 worker 崩溃恢复的 AC-B1/B3 验收。CI 已配置双版本矩阵但远端未验证（P3-4）；`CHECK` 自 8.0.16 起才被强制执行，任务核须用 ai-task-check/同一 Verify 核对任务与账本，points-check 本身仍只覆盖账本；未来启动路径装配属于 AC-B7 剩余范围。

### 4.6 经济风险（对抗性审查）

- **凭空造分回路**：赠送积分 → 小号解锁自己的内容 → 作者拿分成 → 转去花 AI。不可提现、不可转账只降低、不消除。默认只对 `cash_backed` 批次的消耗分成（决策 D10）。
- **有效期与冻结**：过期清扫只作用于 `remain − frozen`；冻结中的批次到期后顺延到结算或释放之后（设计选择，须产品确认）。
- **退款冲正**：新增冲正流水，不改原流水；若积分已花掉，记入欠款表待抵扣后续奖励，**不让余额为负**。
- **反作弊（工程建议，非官方规则）**：签到按（用户、日期）唯一；分享奖励只给"被邀请者完成注册、手机验证与首个有效行为"，按（邀请人、被邀请人）唯一；每来源日、周上限与递减；奖励池日预算熔断；新号冷启动限额；设备、IP、手机号关联风控；奖励 T+N 后可用并可冲正回收。
- **预付合规**：购买所得积分设有效期的消费者权益与预付监管风险**未调研**，须法务；赠送批次可设期、购买批次默认不设期（决策待定）。

## 5. Provider 演进

### 5.1 接口草案（Go 1.24 可用）

向后兼容地扩展现有 `Generate(ctx, Request) (Response, error)`：新增字段全部可选。

```go
type Request struct {
    TaskID string; Step, Attempt int            // 追溯键
    Model string
    System, Prompt string                       // 来源正文只进 Prompt，并以定界符包裹
    MaxTokens int; Temperature *float64; Seed *int64
    Format Format                              // Text | JSONObject | JSONSchema{Schema, Strict}
    AttemptTimeout time.Duration               // 总时限由 ctx（= 任务 deadline）控制
}
type Usage struct{ Prompt, Completion, Total, Cached, Reasoning int }
type Response struct {
    Text, Model, FinishReason string
    Usage Usage; UsageEstimated bool; RequestID string
    Raw []byte                                 // 留审计，剔除 Authorization
}
type ErrKind uint8 // Auth, Billing, RateLimit, Overloaded, Timeout, BadRequest, ContextLen, ContentFilter, Malformed, Canceled
type Error struct{ Kind ErrKind; HTTPStatus int; Code string; RetryAfter time.Duration; Err error }
type Middleware func(Provider) Provider        // Logging → Budget → Retry → Breaker → Router
```

流式（`Stream`）一期**不实现**：进度只推阶段状态。

### 5.2 中间件与错误处理

- 自写约 300 行 `net/http` 适配层，只用 `/chat/completions`；**不直接依赖官方 SDK**：官方 `openai-go` 的 `go.mod` 要求 Go 1.25，而 `server/` 是 1.24；其余差异（默认隐式重试、需要审计原始字节）来自调研读取，未复核。
- 关闭一切隐式重试，只在 Retry 层重试，且每次尝试落调用日志：`Auth`、`Billing`、`BadRequest`、`ContentFilter` 不重试（前两者告警并熔断）；`RateLimit`、`Overloaded`、`Timeout` 指数退避加抖动并遵守 `Retry-After`；`Malformed`（2xx 但 JSON 畸形、内容为空、schema 不符、来源编号不在语料）至多修复重试 1 次。对外统一映射 50201，不透出供应商原文。
- Breaker 按（厂商、模型）统计滚动失败率；全断则任务回排队退避，不判失败。Router 只在"合规白名单且能力满足"的模型间回退：要 `json_schema` 的步骤不得退到只支持 `json_object` 的模型。
- 结构化输出：声明 `Format`，不支持 schema 的厂商降级为 `JSONObject` + 本地 JSON Schema 校验；来源引用、禁用词校验放在**我方闸门**，不依赖模型。
- 超时：`http.Client.Timeout = 0`，每次尝试用上下文加 `ResponseHeaderTimeout`；日志在装饰层留存原始请求与响应，账号与请求 ID 类字段脱敏。

### 5.3 模型注册表与能力表

`tm_ai_models` 与配置同源：厂商、模型名、**备案号或上线编号**、`enabled_for_c`、能力位图（`json_object`、`json_schema`、`tools`、`stream`）、`temperature` 取值范围、错误码映射、单价（配置项，不入代码）。**缺备案号的模型不可启用于 C 端**（AC-L4）；页面公示的模型名与备案号取自这张表。

### 5.4 国内厂商的已知差异（官方文档所述，**均未实测**，上线前逐家跑 5.5 的场景集）

国内主流厂商都有 OpenAI 兼容端点，但这些点各不相同：`json_schema` 是否支持、`stream` 与 `tools` 能否同用、`temperature` 的取值边界（有的不支持 0）、空 `content` 与 `max_tokens` 截断、欠费与限流的错误码、专属套餐端点与通用端点不可混用。故能力必须**表驱动**，不得假设一致。

### 5.5 确定性测试

用 `httptest.NewServer` 加"按请求出队的场景脚本"自建 mock（约 150 行），场景：成功并带用量；401、402；429 并带 `Retry-After`（前 N 次失败后成功）；500、503；畸形（截断 JSON、`choices` 为空、内容为空、schema 不符）；超时（handler 等待上下文取消）；响应中途断开。Retry 与 Breaker 注入时钟接口。断言上游请求数**精确**，借此证明没有隐式重试。现成的 OpenAI 兼容模拟器只适合夜间黑盒冒烟，不宜当单测底座。真实厂商另做一次性契约快照。

### 5.6 预算放在哪

预算（调用数、token、页数、总时限、重试）在**网关层与任务层双重强制**，而不是写进提示。每轮须新增"已核验断言"，否则终止；触顶返回已核验部分，由最小可交付标准二值判定。

### 6.1 三层

| 层 | 触发 | 内容 | 是否阻塞 |
|---|---|---|---|
| 确定性门禁 | 每个 PR | 校验器链、渲染器、账务、状态机、红队回归集；模型输出用**录制或 mock** | 阻塞 |
| 模型质量评测 | 夜间与发布前、改模型或提示词时 | 蕴含裁判对金标、红线违规、注入成功率、成本与时延；真实模型调用 | 发布阻塞 |
| 线上抽检 | 持续 | 新题材、新来源类型、裁判分歧、红线边界命中 100% 人审，其余随机抽（起点 5%–10%，按违规率与 κ 回调） | 运营流程 |

### 6.2 指标与起点阈值（须产品与法务确认）

红线违规 0；展示引文逐字通过率 100%；注入成功 0；蕴含裁判"支持"精确率 ≥ 95% 且 κ ≥ 0.7；另报 P95 成本与时延。**统计说明**（推导）：n 次零违规，违规率的 95% 置信上界约为 3/n；要宣称违规率低于 0.1%，至少需要约 3000 个独立样本。因此"零违规"是对样本集的断言，不是对总体的保证。

### 6.3 数据集

公开集（ALCE、RAGTruth、LLM-AggreFact、HalluQA、CRUD-RAG、AgentDojo）**没有一个覆盖"A 股题材归属"**，且 CRUD-RAG 等无许可证声明不可再分发，只作离线参照。必须自建：红线拒答变体与正常事实问法对照；含评级、目标价、看多暗示的越界输出与合规输出；近似改写硬负例（改数、改否定、换主体、换时间、扩范围）；含指令的注入来源；超长页面与诱导循环的成本样本。蕴含裁判对中文金融语境**没有已验证的开源模型**，先用两个异源 LLM 裁判、只认明确支持，以人工金标校准。

### 6.4 工具与 CI 接法

- 评测框架用 promptfoo（MIT，已并入 OpenAI 但仍开源）离线跑：确定性断言用 `javascript` 或 `python`，蕴含用 `llm-rubric` 或 `context-faithfulness`，中文红线写入 `policy`，另挂成本与时延断言；其红队插件含 `financial:*`（公平性、幻觉、迎合等）、`harmful:specialized-advice`、`indirect-prompt-injection`、`rag-poisoning`，但内置插件偏英文与美国监管，须补中文用例。
- **避免门禁自伤**：现有合规词门禁会扫描 `server/` 下的 `*.go`、`*.json`，而红队样本与禁词夹具必然含违规词。夹具放仓库根 `eval/`（不在扫描范围），Go 测试按相对路径读取；绝不为了过门禁而删词表里的词。
- CI 增量：集成作业把"执行数下限"调高；新增 `ai/guard` 的覆盖率棘轮；模型质量评测走独立作业，密钥放 CI 密文，不进仓库。

## 8. 成本与定价公式（参数全部待实测，不编价）

```
成本_P90(任务类型) = Σ_调用 [ P90(输入 token)·p_in + P90(输出 token)·p_out + P90(缓存 token)·p_cache ]
                    + 检索与数据费用
积分价 = ceil( 成本_P90 ÷ (1 − 失败率) · (1 + 加成 m) · 会员系数 g ÷ v )
```

`v` 为每积分折合人民币（由充值包均价定），`g ≤ 1`，价格版本与明细快照写入冻结单。**价格按任务类型的"上限包络"锁定，不按实际消耗**；封顶项见 5.6；触顶则交付已核验部分，不追加扣费。需要实测的量：两档任务的 token 分位数、调用数、重试、失败与终检不过率、缓存命中率、各供应商当期单价、`v`、`m`、`g`、赠送积分破损率、日预算上限。免费与试用额度遵循"初始赠送一次性 + 每来源每日上限 + 单任务硬上限 + 日预算软告警"，具体数值待定。

## 10. 风险与回退

- **总开关与分级开关**：全局、按级别（L0、L1、L2）、按模型三层停用属于运行控制目标，实际入口遵循各自默认关闭的开关及启动检查。停用拒绝新执行，不直接改写在途任务或释放积分；已知取消/失败由原任务事务释放，外部调用结果未知时保留原键与冻结，按原恢复流程核查，不能把停用当作退款证明。
- **紧急拒答模式**：终检规则热更新（只增不减）；终检命中率异常上升时自动停止创建新任务，历史报告仍可读。
- **回退**：功能默认关；灰度先邀请制；账本与任务表只增，无需回滚数据。
- 主要风险：蕴含裁判在中文金融文本上的可靠度未验证；来源授权未落地；法务意见未取得；MySQL 锁行为只经推演。每项都对应第 6 节的门禁或 tasks.md 的阶段关口。

### 12.2 会话、消息及任务关联

存储归`server/`独占迁移，GVA不AutoMigrate、不直写。初步为三类表：`tm_ai_conversations`（本人会话、创建键/摘要、标题、归档态、版本、消息序号、UTC时点）、`tm_ai_conversation_messages`（会话/用户/序号、消息类别、对象/技能、问题或结果引用、创建键/摘要）、`tm_ai_conversation_tasks`（会话/用户、生成意图键与摘要、对象/档位/价格版本、可空任务编号）。问答执行检查点/证据引用另按12.3落专门契约，不将任意模型字符串塞入消息JSON冒充已审核答案。

- 表间复合外键包含会员编号；任务关联复用既有`tm_ai_tasks(id,user_id)`唯一键，不能仅凭任务ID建立关联。使用同用户任务唯一关联和意图键唯一约束，不悄悄把既有任务搬到另一会话。
- 所有对外编号为正整数且不超JS安全整数；时间为UTC毫秒。会话列表仅主表摘要，按本人`(user_id,id)`游标分页，不查总数；消息按会话连续序号分页。标题上限40个Unicode字符，问题上限1000个Unicode字符/4000字节；拒绝无效UTF-8、控制字符和空白输入，展示原输入时只作转义纯文本。

首个前端面板复用TMUI组件及当前会员令牌，支持新建、列表分页、切换、详情/连续历史、CAS改名及二次确认归档。只展示用户问题纯文本和任务编号，点击引用后重新走原任务/报告GET；历史不复制报告正文、不取得报告许可。切换会话即清除当前任务/报告/流，切账号或离页用代际标记丢弃迟到回包。元数据变更后提示显式刷新列表，不以旧列表快照充当当前详情。

#### 12.2.2 会话生成意图与原任务绑定

在原收费接口之外增加受控会话门面，不复制冻结/任务/准入逻辑。意图先保存服务端报价，再由用户明确确认一次；生成过程仍是原任务/worker/终检/结算。新增`tm_ai_conversation_tasks`保存本人会话、客户端意图键/摘要、服务器随机原任务键、对象/档位、已确认价格版本及积分、状态/版本、可空任务及消息序号。输入仍为原`analysis_type/subject_type/subject_id/price_version`，不接金额、用户身份、来源、厂商/模型或问题文本。

状态闭集：`prepared`版本1→`unconfirmed`版本2→`linked`或`not_created`版本3。只有将prepared原子改成unconfirmed且**确认事务成功返回**的请求可调用一次原`CreateQuoted`。其它确认重放只核查Receipt，绝不再次调用Create；提交权限回执未知/进程在此后退出也不重新发出创建。原任务不存在只能显示未确认，不能据一次404宣称取消、退款或安全重发；该极端窗口可能无任务但仍保持未确认，须独立核查，不能用自动重建掩盖。

Prepare首次调用原Quote，服务端保存报价积分，版本不符拒绝；原键重放只读首次意图，不重新报价/改金额。新增内部`AITaskCreateService.CreateQuoted`仅在原创建核中增加冻结前金额比对，旧Create入口/请求编码/锁序不变；避免同价格版本被误改后先按更高金额冻结再拒绝。任务键仅服务器随机分配，不对会员返回。

确认及恢复都先在会话事务外用原Receipt核验原准入、冻结及请求哈希；绑定时短事务按会话→意图→任务共享读核对原键、身份、对象、档位、版本、金额及task请求摘要，然后原子追加唯一task引用消息、推进会话序号并关联任务。任何绑定/提交故障保留unconfirmed，重试只查原键/重绑，不再冻结或执行。linked重放验证现有任务/消息关联，不发模型请求、不增消息、不授予报告可用性。

只有原创建同步返回闭集的已知不创建错误，且原Receipt确认不存在，才可记not_created（价格变化、积分不足、准入/创建关闭、输入无效）；未知、超时、依赖异常及不匹配收据均不能据此封为失败或退款。not_created不重开原意图，新报价须由用户另行确认新意图。unconfirmed期间数据库独立归档守卫拒绝归档该会话，避免任务已创建却因归档无法写引用；prepared可归档并拒绝后续确认，linked后正常归档，不代替原任务取消。

新增`GET/POST /conversations/{id}/task-intents`、`GET /conversations/{id}/task-intent-receipt`（原Idempotency-Key）、`GET /conversations/{id}/task-intents/{intentId}`、`POST .../{intentId}/confirm`（精确`{"confirmed":true}`）、`POST .../{intentId}/reconcile`（精确`{}`）。GET为只读，核查/重绑显式POST且不创建任务。分页仅意图主表摘要；单条linked才重核任务及引用。DTO不返回原任务键、请求摘要、租约、原始报告或完成百分比。`TM_AI_CONVERSATION_TASKS_ENABLED`默认关，依赖会话/会员读取；创建关闭时不注册Prepare/Confirm，但允许原身份下查旧意图和reconcile。生产准入工厂仍空，原模型/创建开关不因会话开启。无写路由可能返回404或405，不可据此更换原键重建。

迁移`20261021_create_tm_ai_conversations_tasks.sql`排在原会话迁移之后，仅增意图表及4个触发器（其中一个阻止未确认意图所在会话归档），不改原任务/账本表。新启动检查先核原会话保护，再核意图列/索引/复合外键/CHECK/触发器和回滚正反例；探针不创建任务、不锁账户、不调用模型。40001参数、40100身份、40403归属、40903冲突，原价格/余额/准入失败沿用原任务错误，50308表示原任务结果未确认；不可将未确认当成失败退款或成功报告。H5轻度、深度题材均复用此门面；专题未开放，真实执行与各问答范围的验收证据分别记录。

测试必须覆盖20路确认仅一次原Create/冻结，claim与bind真实提交回执未知、创建成功后引用写入失败、同键异体、跨会话/身份/对象/价格错绑、同版本金额变化在冻结前拒绝、确认和归档互斥、关闭创建仍可核查、未知/404不补交，以及原报告/结算/反馈回归。消息、意图与任务的正反约束另用真库验证，启动回滚探针不冒充真实模型、原报告终检或完整L2。

H5会话任务面板放在已选会话之下，复用原创建组件的只报价模式，不另造搜索/资料授权或冻结服务。会话是默认入口，原独立任务在“全部任务”页签核查，不自动迁入会话。轻度、深度题材技能是否可提交须经原报价与准入接口核验；专题仍不可用，不用修改输入冒充支持。会话内先显式保存报价意图（不冻结），再重新读取原报价、精确核对对象/版本/金额与资料范围、展示二次确认后才一次Confirm。列表摘要不授予确认/任务/报告权限，须独立详情核验；已归档只读。

技能卡不把开发价格写成正式固定套餐，只提示“需报价确认”；金额以实际报价及意图精确匹配为准，后端深度开发价格规则不因此改变。切换轻度/深度技能不改写本机原意图：待核查区与详情明确显示原类型，重新核价及二次确认始终绑定原类型、原对象和原金额；不得拿当前技能替换原确认对象或另建收费任务。取消/超时也不能仅凭前端状态承诺已退款，结算或释放以原任务核查为准。

深度验收复用原L2计划、SQL限流器、会话创建核、异步worker及原注册报告读取器，不用独立读取器绕过类型准入。普通`TestIntegrationDeepH5GatewayHTTP`覆盖RC/RR并清除浏览器专项环境；实际页面另用`integration && browser`的`TestIntegrationAIReportH5Deep`，须由公开报告GET读取及重读后才能结束，服务层自读不算页面交付。结束同时核对四节六引文、原任务唯一、30测试积分单次结算/冻结归零、重读零改账和原会员登录。十分钟窗口只供浏览器交互，原worker30秒、任务300秒及预算不变；CN/模型回环替身明确标注，不作为真实多Agent质量证据。

待核查意图按本人分区与原任务/会话元数据键隔离，每个账号最多保留一项，含会话编号/原意图键/对象/价格/已知意图编号/确认已发标志，不存报告正文或凭据。Prepare前用WebCrypto/WebLocks先持久化并读回；未知只GET原意图收据，404不换键不重发Prepare。Confirm前在同一互斥区持久化一次性已发标志，重载/跨页签后也不重发Confirm；结果未知只能GET详情或用户显式Reconcile（后端仅原收据核查/绑定，绝不创建）。收据与本地对象/价格/已知编号不符拒绝确认；切换会话/账号/离页丢弃迟到回包。终态linked/not_created经独立详情核对后才允许显式清同键本地记录，未确认不能清键或以失败/退款文案替代。新阶段须实际组件正反例、实际H5→真库会话意图→原任务→报告/测试结算及未知恢复验收，不以原独立创建链代替。

两个生成入口的reserve/确认标记/清键共用`tm_ai_creation_gate_v1_<会员编号>` WebLock；独立任务键和会话意图键仍分别存储。准备任一新请求时，在同锁内检查另一入口有无记录，损坏/未知记录也阻止新建。独立入口重载发现待核查会话意图只给指引；会话入口有独立原请求时只读既有意图，不准备另一项。无论跨入口还是跨页签，不能以新键绕过原请求保护；原服务端幂等和账务保护不依赖这个客户端锁。

### 12.3 资料问答与报告追问

输入独立为`question + subjectType/subjectId + skill + 可选taskId`；服务端取得会话及当前会员，校验技能与对象支持、报告归属和当次可读性，再构建已授权且固化的资料范围。历史问题不自动扩大对象范围，不接受客户端的来源URL、厂商/模型/提示词、费用、工具或身份字段。

检索和问答走有界服务端工作流：保存问题→检索当前资料/本人报告→候选证据集合固化→模型仅选择证据编号/受限意图→从快照回取引文→逐字/数字、蕴含及语义终检→保存结果引用→按固定模板展示。不得把关键词命中、模型自称有据或归档delta当终检；不得令模型自由补写答案。当前既有报告选择器/guard只在契约满足时复用，不能强行把问答伪装成原L1收费任务或绕过生产批准。

问答状态为`queued/running/answered/refused/failed`；结果只存证据/模板引用与拒答闭集原因，不保存可直接公开的模型自由正文。无证据、超出范围和要求投资意见时固定拒答；技术故障与证据不足分开表达，不能误报已完成。结果重读和报告追问每次复核授权与报告可读性，来源撤回后不从旧消息缓存继续显示引文；历史问题仍可显示为用户输入。

首版不按消息扣积分，但必须有服务端单次调用/token/资料数量/时限、用户与实例配额，超限明确拒绝；数值是开发保护参数而非正式套餐，生产问答启用必须显式配置及批准。需要重新生成报告时先返回待确认操作卡，用户选择档位并确认现有报价后才创建一次原任务；用户提问、模型分类及重连均不能触发隐式收费。多来源核验/L2执行未满足原质量门槛时保持不可用，不降级包装为已完成深度服务。

#### 12.3.1 问答证据执行核（先于公共接口和问题写入开放）

问答不能套用绑定四节报告/收费任务的终检格式。新增独立`ai/qa`核，复用原Provider单次直连、快照/切句和合规规则；不依赖积分账户、创建器、Agent工具或互联网检索。首增量只实现`material_qa`，`report_qa`须后续通过原报告当前可读性构建独立范围，不能退回全资料或借其他报告充数。

计划固定可信会员/会话/消息序号、原始问题摘要、题材/专题、当前获授权范围证明、快照全文/句子索引和模型审批/质量/预算配置；每份快照必须逐字验哈希/偏移、当前授权期限/类别/域名。范围只能由受信任授权仓储与控制器提供，客户端不能提交快照编号/URL。上限显式配置，快照最多8、候选句最多512、总证据最多64KiB；超过整份拒绝，不静默裁剪。范围为空时明确无证据，不能查其他对象或联网补全。第一步对全部有界候选句进行受限语义选句，模型只回闭集拒答原因或至多4组连续原文编号；代码回取并检查重复/越界/长度/红线，按出处编号及位置客观排序。

第二步独立蕴含判定须同时核对原问题、对象、候选原文上下文和选句是否直接回答问题；第三步独立语义判定须拒绝投资意见/引导、范围外问题、提示注入及语境失真。两步只回封闭枚举，不得输出解释/正文，block/uncertain不交付。用户问题和资料始终在JSON data内，不进入System、不获取工具权。最终对象只包含经核验的引文引用或固定拒答模板；所有链接/文字/时点由当前快照回取，模型没有自由正文输出通道。编号正确、关键词命中或模型自称通过均不能单独替代这条链。

执行至多3次单次直连、无网络/结构修复重试或回退；每次请求显式最坏token预约及超时，必须精确匹配配置的端点档案和模型。模型/质量/预算等非空归档引用只是格式检查，不是批准真实性证明。受信任控制器须在第一调用前以持久唯一执行权限和用户/实例配额接纳计划，每次调用前持久预约/当前重验、调用后持久保存真实用量与结果摘要（未知亦留痕），最终存证成功后才返回。任何提交未确认、用量缺失/估计、模型漂移、审计失败、授权撤回或期限到期都不交付，不重新执行；重复运行须被持久权限拒绝。每次读取结果仍须当前授权复核，持久问答/API接线未完成前不注册问题POST、不启用生产问答。该核的模拟/回环Provider测试只证明执行与引用边界，不冒充真实模型质量、真库持久配额、完整问答服务或C-4整项验收。

通用Provider允许的缺失model/total补全、token舍入不能视为问答供应商存证：本核另核原响应JSON的显式model、唯一choice、整数用量、合计及缓存/推理明细；缺项、重复键、浮点数、漂移或截断完成一律不交付。失败但适配器取得用量时保留该用量及请求编号；未知/估计/元数据异常与已确认耗用区分，不把零值记成零成本。故障时不签发Outcome，不以拒答代替技术失败；已取得执行权/预约由持久层保留并显式核查，不开放自动重跑。上下文取消可能令结果存证本身未确认，不能仅以本核返回错误释放持久预算。已新增12.3.2的SQL持久控制器，但尚未装配生产或公开问题提交路由；仍不能将内存测试记录器作为生产控制器。

#### 12.3.2 问答持久控制器（内部开发，公共入口仍关闭）

持久化复用原会话/消息，在独立迁移中新增问答范围批准、日配额政策、日配额预留、问题执行记录和逐次调用记录五表；不改账户、冻结、任务或报告表。范围批准按题材/专题主键固化名称、批准引用、策略摘要、有效期及有序快照编号/哈希，仅默认关闭登记；日政策也默认关闭，绑定模型预算引用及会员/实例每日请求数与最坏token预留上限。没有内部审批/生产装配即不可用，不凭资料快照存在就授权问答。主题下的资料归属须由这份受控批准记录确认，不能从全库关键词或客户端快照编号推导。

当前仓储只对`theme`核验实际题材目录；`topic`保留表契约但仍返回不可用，专题资料归属不得擅自按题材转换。配额上限下调不释放既有最坏预留；停用批准/政策会阻止后续模型调用及结果交付。所有当前授权复核都是新短事务，读取不持锁等模型；写入共享锁仅维持该次预约/终态事务的授权一致性。

问题入队在同一短事务内锁本人会话→核原键→CAS推进版本/序号→追加原始question消息→插入queued问答记录；快照正文不重复保存。原键重放必须身份、完整计划/原问题一致，只恢复本人原输入与状态收据，不回引文/授执行权限；归档或来源撤回不妨碍核查原问题是否保存，执行与答案读取仍独立核当前授权。同键异体、跨用户拒绝；新入队另拒绝归档、版本冲突或当前批准/来源不可用。请求身份为本人会话/消息序号，原键用于查未知提交；队列记录本身不表示已有回答，也不预留积分或调用模型。

执行开始只允许一次queued→running，核验当前会员、本人会话/原问题、批准/政策、模型预算引用和当前来源；以数据库UTC日期，先实例再会员锁定配额行，在同事务内各增加一次请求数及完整计划最坏token预留。日预留计数只增不减，不以实际消耗抵扣/退款，跨日调用仍归属首次执行日期；这是明确的开发安全配额，不是用户收费套餐。未知提交、调用取消或失败均不自动返还配额/重新执行。执行/调用/终态写事务不跨模型请求保持，所有模型HTTP在提交成功后才发出。

调用按select/entailment/semantic最多三步，前步已存证且通过才可预约下一步；每步先存reserved记录和请求摘要，调用后保存recorded的供应商请求编号、真实/估计用量标志、异常闭集、结果摘要及经严格解析的闭集选择/判定，不存模型自由正文。末次存证必须回放这些闭集阶段与逐字引用，对照原问题/范围/摘要决定answered/refused，不能仅信Complete收据或三条用量记录。取消后的内部有界审计允许在独立清理上下文保存，不能因此继续模型调用；无原始用量时保留未知，零值不当零成本。

结果重读只读原记录/阶段并重新核验当前批准、会员、来源及原消息；由当前快照回取引文。缺阶段、篡改、漂移、范围撤回/来源授权变化则不交付，不通过重新运行修复。技术失败可显式running/queued→failed，保留所有预约/未知状态与日预留；若原最终提交已成功，后到的失败处理不得覆盖answered/refused。归档阻止新入队/执行，但已完成且当前仍获授权的历史可读，不撤销原报告/任务。当前增量不装配公共POST、worker、真实模型配置或生产开关；现有问答执行核测试不能替代新真库原子性、并发/回执未知和来源撤回验证。

仅本次已确认取得queued→running权限的执行尝试才可在错误后自动记录failed；并发/重放、权限提交后回执未知均不因此终结别人的执行。逐次审计允许对本请求原reserved记录在failed后完成一次recorded（迟到已耗用不得丢失），但不恢复状态、不继续调用、不交付结果。所有存储时点须是有效UTC毫秒，时钟回拨不倒退记录时间；原日预留日期不可被调用/终态/失败操作改写。公共问题服务、原键收据/状态查询DTO、启动结构/回滚探针、生产批准管理与实际问答页面仍待接线。

测试设计：MySQL8/9各RC/RR实际执行，验证入队原子/并发原键/CAS、撤权和跨用户拒绝、唯一执行权/每日双层预留、三阶段存证及重建读取、故障不签发/不重跑/不释放预留、真实提交后回执未知与后到失败不覆盖终态、当前来源撤回、缺失/篡改阶段拒绝、归档读写边界和跨日归属；断言拒绝后调用数、问答/消息/配额记录及原任务/账本计数。DDL重跑与直接反例验证不可变/单调/外键约束；产品启动须另补元数据与回滚探针并默认关闭，在该检查接线前不作为可开放服务。

#### 12.3.3 会员问答服务与只读答案（默认关闭）

新增`GET /conversations/{id}/question-receipt`（原Idempotency-Key）、`GET /conversations/{id}/questions/{seq}`状态及`GET .../{seq}/answer`答案；提交独立为`POST /conversations/{id}/questions`。正文精确`{version,subjectType,subjectId,skill,question}`，只支持题材material_qa；原始问题受既有1000字符/4000字节约束，HTTP正文上限8192字节。拒绝未知/重复/大小写冲突字段、null、压缩/查询/身份/模型/来源/费用字段。不对任意messages开放写入，不把问题转成收费任务。

状态DTO只含seq/state/subjectType/subjectId/skill/question/createdAt/updatedAt，不含来源、批准、摘要、预算、内部故障或“答案可用”授权。归属及当前会员在所有读写入口核验；来源撤回后仍可查询本人原输入/状态，但答案单独读、每次当前授权。已完成状态不代表当前可展示答案。答案DTO只有seq/state/template/subjectName/aiGenerated/modelName/filingNo及有序quotes（snapshotId/startByte/endByte/excerpt/sourceType/sourceUrl/collectedAt）；不含模型自由正文、问题之外用户数据或内部判定。零模型调用的固定提示不冒充AI生成。

可信配置目录按policy摘要提供仅含元数据/限额/域名的原Config，不含密钥或模型客户端；新问题从当前批准范围加载快照，旧答案从原Proof/原问题及当前固化快照复建同一Plan，摘要不一致整条拒绝。读历史不构造Provider或调用模型，配置缺失/版本变化/来源撤回不回退其他模型或范围。状态查询不依赖这个配置目录，不能因撤权而丢失原键核查能力。

提交先查本人原键，原问题一致仅返回原状态，不能再执行；未存在时核会话版本/序号及当前范围，原子Enqueue后显式调用现有唯一执行控制器。首次执行为有界请求内工作流，最多25秒总期限，模型仍最多20秒，事务仍2秒；不启动无管理goroutine/隐式重试。实际存证未知只报未确认，客户端必须查原键；已存queued/running不得因重复POST补跑。每次模型阶段及返回前重验原Bearer及会员，过期/撤权后只允许内部有界审计，不交付答案；令牌不落库或进入模型。需要异步worker/SSE扩展时另验，不把同步问答冒充原收费任务流。

问答读取/提交开关独立默认关闭，读取依赖原会话及严格会员鉴权，提交另依赖可信策略和执行器装配。生产策略/执行器工厂缺失时启用提交必须启动失败，普通测试只装配回环模型；开会话不会自动开放问答。启用前核验五表列/索引/FK/CHECK及15触发器定义，再做可回滚正反探针；不生成真实消息、调用模型或改账。实测包含实际JWT→HTTP提交/原键恢复→真实MySQL→三次回环模型→阶段存证→只读答案，跨用户、过期令牌、来源撤回、同键异体/提交未知、关闭创建仍可核查和答案不依赖模型凭据；不以静态接口存在称作页面联调。

#### 12.3.4 会话资料问答客户端（H5增量，不开放报告追问）

在现有会话面板内接独立资料问答面板，复用同源会员请求、题材目录、TMUI输入/按钮与安全外链；历史question仅material_qa提供“查询问题状态”入口。归档会话只读；题材须从实际目录选定，不将未选择的自由问题交给默认对象。输入最多1000个Unicode字符、禁止控制符；提交前读取当前会话版本，原键/原问题/对象/版本先持久保存到会员分区，由Web Locks授予一次发送权。缺随机、互斥、可靠存储或已有待核查问题时拒绝新提交；本地不保存令牌、模型输出或引文。问答不创建收费任务，也不调用报价/确认接口。

仅问题POST使用28秒客户端期限，原有请求10秒不变；超时/断线/409/503/404均保留原键，不重发、不换键。恢复仅GET原收据，原输入/对象不符整份拒绝；queued/running显示待核查而非假进度，failed固定故障说明，不冒充无证据拒答。只有重新GET确认终态后才允许用户显式清理同键本地记录；未查到不视为确定未保存。明确400参数拒绝也不自动重发。异步任务SSE与报价积分流程保持原实现，不为问答伪造逐字流。

状态不携带答案，answered/refused仍须点击单独GET答案；客户端验证闭集固定模板、AI标识、模型/备案字段、有界且有序不重叠的引文、UTF-8字节偏移及安全HTTPS出处。不渲染HTML/Markdown自由正文、不本地缓存答案或导出。每次状态/答案读取前清空旧引文，失败清空；切换会员/会话/历史问题、离页、归档变化以及弹窗期间上下文变化均失效旧回包。打开出处须重新GET当前答案、对应引文一致且当前会话/会员未变，再二次确认，不以旧已显示答案授外链权限。

验收先执行实际UTS/UVue源码正反例（固定请求/期限、原键未知/重载/跨页签、失效身份/上下文/乱序、答案模板/标识/偏移/出处损坏、转义），再用官方HBuilderX构建和实际本地H5→JWT/API→MySQL→回环模型→存证/答案纵向验证。纯源码宿主、占位H5代理或回环模型都不冒充真实浏览器或实际模型质量；生产开关和工厂仍关闭。

#### 12.3.5 报告追问（测试装配，生产默认关闭）

报告追问只使用本人当前可读报告内、已终检的 AI 章节引文；公司事实行不进入追问范围。证据逐条转为合成快照并强制正文与报告引文逐字一致，唯一引文上限 16 条；2 分钟是新执行授权期限，不是历史答案保留期限。每次提交/答案都经原报告读取服务重验当前可读性。历史答案使用独立只读计划重建原证据与原截止时点，摘要必须与原存证一致；只读计划禁止入队、取得执行权或写入，不重新调用模型。批准引用固定为 `report:<taskID>:<digest>`，任务号与报告摘要不符一律失败关闭。

服务复用	extbf{原问答会话/消息、请求、调用存证、配额与控制器}，不新建执行或扣费体系；提交按 `report_qa` 分流，在短事务外重读报告证据与可信配置，事务内复核会话版本/原键并构造计划；答案按原批准时点重建计划并回放存证后才交付引文。前端只在“会话内已打开报告”时显示追问面板，绑定报告任务，原键记录含技能/任务号；归档只读，401/切换账号/卸载丢弃迟到回包。

历史消息中的“查询报告追问”绑定原任务与原序号，先核对报告当前权限，再以只读面板查询原状态和答案，不依赖浏览器保留提交原键。提交或核查成功后刷新服务端消息列表；追问401同时清理父页面报告、任务、会话及追问状态。技能列表将此项标为“报告内使用”，不能单独提交；其他技能的可用性仍由实际接口核验，不能仅凭本地目录声称已开放。

会话历史后台刷新与标题写入/归档确认串行协调：交互期间合并只读刷新通知，不推进原写请求的详情轮次；交互结束且原会话仍有效时再发一次GET。刷新详情或消息期间，标题保存和归档同时在按钮与处理函数拒绝进入，避免反向交错。写失败、归档完成、401、切会话/账号及卸载清除待刷新通知，不能恢复旧详情或补发写请求。刷新历史本身不清空父页面任务选择；此契约不等于已定位所有任务详情消失原因。

刷新成功须同时把当前`archived`状态传给父页面的报告追问面板：会话在其他入口被归档后，不能只让会话栏变成只读而保留报告的新提问入口。该同步只更新显示门禁，不提交问题、不改变原报告读取权限；服务端仍独立检查当前归档状态。

新建或原键核查收据只含编号与时点，不能据其补造会话列表摘要。核实原详情后独立重新GET当前筛选的列表，仅此同步刷新保留当前会话/消息代际；原显式查询仍按原规则重置选择。列表加载与写交互期间的同步通知合并，当前账号/筛选重置或卸载时失效；列表故障不丢已核实的当前会话，401及换账号清理私有状态。当前会话已存在或正在读取时不显示“暂无会话”，必须等实际列表回包后展示相应行与分页信息，不以隐藏空态代替列表同步。

生产开关 `TM_AI_REPORT_QA_SUBMIT_ENABLED` 默认 false，必须同时开启问答读取/提交并注入受信任的报告证据与配置工厂；缺少工厂或依赖时启动失败，不能仅凭环境变量开放。测试装配（H5 网关/真库）不能替代生产批准、真实模型质量与容量验证。

历史答案读取不依赖新提交开关：开启问答读取且显式注入可信报告工厂时，装配当前报告证据和无密钥配置，不构造模型客户端。资料提交与报告提交在服务层分别授权，前者开启或只读工厂存在均不隐含后者；报告提交开启而总体提交关闭属于无效配置。工厂报错/只提供一半依赖必须拒绝启动，不能静默丢失历史读取能力。原历史摘要与当前报告权限仍逐次复核，来源撤回后只读模式也拒绝交付。

数据库先按历史迁移顺序执行，再追加 `20261023_allow_deep_ai_report_commits.sql`，不得靠重放旧建表文件升级。新增量只替换报告插入触发器，保留原任务、终检、账本联合校验及历史不可变触发器；执行前停止报告写入，失败时保持关闭，自检通过后才能恢复。Agent 执行摘要升级为 v2，绑定有效分析师列表及日期策略；默认列表与显式同列表一致，旧摘要不得自动改绑或重提，须保留原任务/远端收据待核对。

普通 `integration` 测试不按密钥环境切换真实执行器或扩大夹具预算。原深度真实/预完成分支迁至 `integration && liveagents` 的 `TestIntegrationAIReportDeepLiveAgents`，还须隔离脚本显式 `-LiveAgents -ReportsOnly -RunCount 1`、精确根选择器 `^TestIntegrationAIReportDeepLiveAgents$` 及 `TM_TEST_AI_LIVE=local-fixture-only`；密钥仅安全注入。预完成报告另须指定原任务编号，结果只算回放而非新多 Agent 实跑。报价、执行与最终预留应覆盖选择加两次独立判定，不以部分阶段预算作为完整预检。

### 12.4 任务SSE独立增量

新增`GET /api/v1/ai/tasks/{id}/stream`，保留原`/events`分页JSON。独立`TM_AI_TASK_STREAM_ENABLED`默认false，依赖任务读取开关/有效会员鉴权及原任务结构检查；只开流不启用创建、报告或模型。采用H5 Bearer fetch流；未验证平台/流不可用立即回退原GET轮询，不为兼容引入URL令牌或Cookie鉴权。

`after_seq`为非负规范整数；可选`Last-Event-ID`必须规范且与显式参数一致，拒绝重复/未知参数与重复头、HEAD/GET正文。先验身份、归属和游标，再发送SSE响应。每轮重验令牌和当前会员，调用原Events服务读取小页；连续序号去重/续读，遇到丢序或损坏失败关闭，不静默跳过。事件`progress`仅包含原AITaskEvent白名单；终态不是reportAvailable授权，客户端需重新GET任务并通过原报告读取。

单连接最多15秒、轮询间隔1秒，具备心跳、取消响应、写入期限与单用户/单实例并发限额；各读取是独立短事务，不持有数据库连接等待推送，不启后台无限goroutine。达到连接期限正常结束由客户端按原游标重连；错误只给固定公开码。内存限额仅约束本实例，生产跨实例限流及代理缓冲/超时、容量需另验。

客户端按UTF-8连续解码，缓冲完整帧、支持LF/CRLF及跨chunk拆分、有界缓存；不按网络包边界分割中文/JSON。只接受白名单事件及DTO，未完成帧不推进游标。流断开不重新提交消息或任务；只读重连退避有上限，切换账号/会话/任务或离页立即abort并用代际标记拒绝迟到回包。恢复时重新核验当前状态，终态停止轮询；不得用假百分比或推测远端已经停止。

首个H5接线复用当前任务/报告页，不先替换整个入口：初次详情取得当前序号后读取固定同源stream，独立解析器仅接公开事件六字段，不渲染data原文。单帧16Ki字符、单行8Ki字符、单chunk64Ki字符；进度帧必须完整且序号连续，重复帧校验后忽略，坏帧/缺序不推进对外游标。H5用fatal UTF-8解码及Bearer fetch（omit credentials、禁止重定向），18秒客户端看门狗；最多3次1/2/4秒重连，每次先重新核对当前详情且原游标不能倒退。连接不支持、404/429/503、结构/UTF-8失败即回退原串行3秒GET详情；降级展示当前状态而非伪造缺失事件历史。401/403停止并清除当前数据，GET详情404亦停止；终态只通知可重新核对报告，事件不授报告权限。所有退出取消网络/计时器，延迟GET回包也须当前令牌与代际吻合。用字节级拆包、重连/降级/账号切换测试，再以实际H5及本地真流验收；源码宿主不冒充HBuilderX。

实际事件去重验收独立于仅连接帧EOF/503场景：由原worker及数据库产生公开帧，只在测试ResponseWriter逐字复制原完整帧并中断一次连接；重连仍经过原handler鉴权与游标检查，再复放已确认的同帧并放行回环Agent完成。原帧必须与原事件读取DTO逐字对应，浏览器另验序号唯一及后续新事件；终态与报告仍分别GET核对。该专项只以`integration && browser`及精确隔离开关运行，原30秒worker期限不变，不制造业务事件、不开放生产调用。前端发现终态后可以停止通知流，不能把显示的事件列表称为完整审计历史；上游完成后的最终Agent持久记录应为结果隔离并核验原摘要，而非要求停留在中间完成状态。

执行期限、租约和任务截止时点是三个不同事实。原worker自然超时后，没有确认的任务不得在页面伪装成失败、退款或远端停止；原取消接口只登记请求，继续保留运行态及冻结，直到有效执行者或租约自然到期后的原恢复服务确认终态。恢复不得抢占有效租约、重建计划、重发上游任务或重置预算；确认取消只产生一次原账本释放，旧围栏不能续租/写入，终态恢复与L1重放不能增加外部调用或账务。长时间自然等待专项独立精确运行，不缩短原30秒worker/一分钟租约/300秒任务预算，不修改时钟或数据库终态，也不扩大默认报告套件看门狗。此项只验证已登记取消的恢复，不等于无取消时的任务截止清扫或进程崩溃恢复全部验收。

#### 下一阶段：可信装配来源（2026-10-29，用户确认本地文件方案）

本地合成计划增量：`TM_AI_LOCAL_PLANS`显式提供无密钥计划文件，未提供时保留原无控制器行为，提供但无隔离启动配置则拒绝。API和worker复用同一AILocalPlanSource及AILocalAdmissionControl。计划版本1精确顶层字段为version/instance_id/revision/scope/issued_at_ms/expires_at_ms/members/plans，scope固定synthetic-local-only；有效期不超过24小时，会员白名单1至16项、计划1至16项。嵌套字段以`server/internal/config/ai_local_plans.go`为精确契约，所有字段包括零值必须显式存在，拒绝未知/重复/大小写别名/null/尾随JSON；沿用本地普通文件身份核验，单文件上限128KiB。每次使用重读规范摘要，语义变更必须重新启动，不能仅改变原文件版本或价格后自动放行。

本地任务HTTP增量：独立LocalTaskBootstrap叠加前述初始化，显式开启轻深任务创建、会话意图、取消、余额及SSE；这些开关只注入本轮回环API进程，不因有本地文件而默认开启。由初始化所有者在本轮空专属库用原PointsService给两名测试会员各发50测试积分，再由GVA原密码路由签发JWT请求实际cmd/api，验证报价→prepared意图（不冻结）→confirmed关联原任务（冻结）→重复确认/原键恢复（不重复扣）→queued任务取消（一次释放）及终态SSE断点续读。原会员旧积分不迁移；真实模型、问答和报告发布仍关闭，不能把取消释放当成功报告结算。

本地计划在创建前读不到、过期或变更时，控制器返回ErrAdmissionUnavailable；取消上下文仍保留原错误，数据库实例异常不伪装为文件拒绝。会话确认按原键查无任务后记not_created，不能把这类创建前拒绝长期留作unconfirmed。证据读取后的第二次文件复核使用相同分类；恢复文件后原拒绝意图不会自动重提，需另行报价确认。此分类不授予释放未知外部调用的权利，既有阶段/预留和原键核对保护不变。

首个增量是版本1启动边界文件：精确字段为`version/environment/instance_id/database/listen/real_calls/poll_interval_ms/batch_size`，环境固定local-isolated，库名绑定`tm_ai_local_<32位小写十六进制instance_id>`，监听固定字面127.0.0.1及非特权端口。显式`real_calls:false`不可省略，此版本拒绝true。配置文件绝对路径由`TM_AI_LOCAL_CONFIG`提供；缺路径不启用本地装配。DSN只从环境注入，解析后须与实例库名、字面回环TCP及有效端口匹配并开启parseTime。API在连接数据库前预检，并在本地模式使用文件监听地址；worker的`check-local -config <绝对路径>`仅做配置预检，不连接数据库、不运行队列。预检成功不证明数据库所有权或批准有效；隔离实例标记、计划/控制器和实际命令执行仍待后续装配，不能把此增量称为完整本地服务。

两种方案都必须满足：配置只持有无密钥模型/策略/来源/价格/预算及批准引用，密钥单独安全注入；准入、执行、选句/判定、读取和报告追问使用同一已绑定配置身份，不能继续分别配置模型别名。配置存在或引用非空不等于批准有效，必须保留当前控制器的实际核验和持久调用审计。资料许可或发布权变化须在每次执行/读取复核，不能只在启动检查一次。

若采用本地文件方案，限定回环监听和显式隔离数据库，拒绝生产库及未知字段/重复字段/无版本/无效时限；启动先完成全部依赖、结构正反例、模型身份和来源绑定检查，再注册提交路由或启动循环。缺项时整个写入口失败关闭，禁止以默认价格、示例批准或测试工厂回退。文件更新需要明确版本及重新启动；不在运行中静默热更价格/计划。实际正式定价、资料许可和发布批准继续作为独立上线条件，合成资料的本地批准不可迁为生产批准。

装配验收先验证默认关闭、配置拒绝、同源计划绑定和受限数据库，再用原会话/原任务链验证轻深任务及进程退出；已有真实模型回执保留，只有涉及执行身份或请求语义的新变更才重新付费验证。命令入口可运行、取消收尾和未知调用恢复必须另有实际进程证据，不能只通过构造器测试即宣称完成。

常驻调度复用队列RunBatch串行执行，不建立第二套任务或积分状态。每批间隔1秒至1分钟且可取消；扫描完成后从零重新核查，不能把临时扫描游标持久化成已消费偏移。执行错误、未知结果或游标无进展必须退出交给运维核查，不在循环中自动补发外部请求。仅构造服务或提供RunLoop不会启动后台工作；命令装配、明确开关及可信控制面仍分别验证。

报告读取启动装配可显式提供轻度、深度两套策略，并复用同一账本、仓储及发布控制器。深度策略只能是类型2；双策略入口不接受两份深度策略或用轻度策略冒充深度。未提供深度策略保留原单策略行为；关闭读取不构造服务。启动装配不开放终检写入，也不能以配置存在替代实际发布授权，正式main仍须注入可信控制面。

本地发布读取增量：显式本地运行配置和同源计划准入控制器就绪后，实际API可单独开启原报告读取开关。新增按本人任务解析的策略来源，在原报告事务外读取原准入记录和当前计划；核验原准入摘要、执行摘要、成功提交的围栏/步骤/事件/时点、模型与公示身份，再将该任务的题材和轻深策略交给原读取器。不能只按类型选固定策略而让不同题材误用同一策略；缺历史准入或当前文件/来源许可失效均拒读。

策略解析不代替原读取器的报告正文、阶段检查点、预算和唯一结算复核，两次读取和两次当前发布复核保留；读取不执行模型、不写账。构造策略所需的判定回调仍返回不确定，不设置默认通过。非本地main继续缺控制器即失败关闭。新增本地worker规划接口适配仅复用同一ExecutionPlan，不启动队列或授予选句/判定调用权限；常驻命令、调用控制器及完整新入口成功交付仍需后续装配。

本地选句/双判定调用控制增量：服务层新增明确无密钥、字面127.0.0.1加端口的HTTP协议装配，只允许根或/v1路径，拒绝远端/域名/HTTPS、查询、格式回退及推理配置。它不启动请求，也不装入main；版本1real_calls:false不变。TaskService从同一准入仓储构造，不能另传其他数据库的任务服务。每次Recheck与Start重新核对原持久准入、同源计划、真实适配器配置摘要及当前资料；从原隔离Agent回执重建选句，从已捕获的选句响应经原ConvertModel重建两次判定。传入ModelStep摘要必须与重建一致；Start还逐字段比较完整请求和任务/步骤追溯字段，不能换提示、模型、输入摘要或操作键。

本地常驻执行增量：新增独立版本1执行文件，精确字段包含version/instance_id/revision/scope/issued_at_ms/expires_at_ms/model/agent/lease_ms/heartbeat_ms/worker_timeout_ms/agent_poll_ms，嵌套模型与Agent均精确必填且无凭据。范围固定synthetic-loopback-only、字面127.0.0.1 HTTP和非特权端口；模型可用根或/v1，Agent仅根地址。拒绝外部地址、域名、路径/查询/转义、跨实例、过期/超过24小时、未知/重复/大小写别名/null/缺字段；沿用8KiB普通绝对文件与规范摘要禁止热更。Agent许可/批准引用限local-eval，模型直连禁止密钥、重试/路由回退。Bearer仅从TM_AI_LOCAL_AGENT_BEARER注入，DSN仍独立环境注入，启动文件real_calls:false不变。

run-local -config/-plans/-execution显式装配同一隔离数据库上的原账本、准入、报告深度自检、调用审计自检和Agent存储自检，全部就绪后才构造原执行核及轻深队列。实际模型和Agent配置摘要必须与计划文件每项匹配，执行有效期不能超过计划有效期，worker时限/租约不超过各原计划任务时限。本版本一个执行档案供轻深共用，不能用一个模型别名覆盖其他档案。两队列复用原RunAIReportQueues共同生命周期；扫描、规划、调用前审计及最终报告复核重读受控文件，失效或未知结果即退出，不自动重启、补发、释放或另建任务。调用后存证不因文件撤回而丢失，后续阶段照常拒绝。

本地显式恢复增量：resume-local严格接受-config/-plans/-execution/-user/-task，复用run-local的全部装配、实例、实际档案与结构自检；只核当前计划会员的一个既有运行或终态任务，排队状态在入口拒绝，不扫描队列、不另创任务。原worker负责租约到期与围栏接管、原准入和已捕获阶段回放；具备完整回执的终检前缀可以继续原报告/账本事务，终态重放不再次结算。旧围栏尚未捕获的模型或Agent回执保持未知；远端后来完成也不能冒充原Capture已保存，不补造响应、换键或重发。退出0仅表示确认既有终态（包括失败/取消/超期），2表示仍待核查，1表示拒绝/未完成，130表示本地中断；任一退出码都不能单独作为报告可读或远端已停止的证明。本次不增生产恢复调度或改变原Capture跨围栏保护。

正式进程的本地HTTP纵向验收由LocalAPIWorker根组连接原GVA密码桥、实际API及实际run-local；同一计划/实例下的会话确认只创建原任务及唯一关联消息，worker从原数据库队列发现，原报告读取策略核验交付。API与worker分离随机受限账号，前者不读取会员密码、不写Agent或调用审计表；元数据仍经固定只读过程核验。轻度计划不误开深度准入。终态后的确认、原键回执、报告重读和SSE续读均不另建执行或结算；此进程测试不代替浏览器、真实模型和生产批准。

LocalAPIWorkerH5浏览器专项复用这两个实际二进制与密码桥，新增只转发的回环网关承载完整H5产物。题材搜索也使用正式目录仓储；浏览器网络成功头计数仅用于判定操作是否发生，不能单独证明交付，结束时还核同库原任务/报告/账本与登录存证。为观察运行阶段，新建合成计划可明确声明五分钟交互任务预算，原自动化默认预算不变；回环Agent在页面取得SSE连接后才由操作者放行。此模型替身控制不作为真实上游取消/恢复或推理质量证据，真实开关及生产批准边界不变。

默认通过原系统信号上下文停止；显式-stop-on-stdin用于管道控制，stop行或EOF取消本地循环并等两队列收尾，未知命令失败。该停止不是会员任务取消，不代表远端停止；尚未知的预算/冻结继续保留。日志只输出固定就绪/退出或阶段编号，不输出任务、资料、配置、凭据或内部错误。独立进程验收使用自己启动的回环Agent/模型替身和20表逐表DML、5表SELECT账号，不持DDL/TRIGGER/来源修改权限；不将该测试当作实际网站/API合流、系统信号/强杀重启恢复或真实多Agent复验。

系统信号专项另行直接启动实际worker且不传-stop-on-stdin：Unix向本轮明确子PID发送SIGTERM；Windows由独立隐藏控制台宿主启动新进程组worker，核GetConsoleProcessList仅含宿主及本轮worker后，才对非零且非自身的worker进程组发送Ctrl+Break。禁止附着用户控制台、广播事件或按名称清理。宿主必须等实际worker退出130才转交该退出码及固定证明，不能用宿主成功掩盖worker强退；控制管道只接受精确signal行，stop等非法输入必须拒绝，清理并回收自己启动的worker，不生成信号证明。

LocalWorkerSignal覆盖RC/RR准备与验收仓储、轻深计划下的空队列、远端已记录running、模型start审计已保存三个时点；分别核原系统信号停止路径、实际退出码、无额外上游提交/报告/结算/释放、无会员取消标记、原冻结及远端运行记录保留和原积分对账。WindowsCtrl+Break不等于关闭控制台、注销或系统关机事件；Linux分支编译不能代替实际SIGTERM取证。该专项不重写原main信号处理、不启动真实调用，也不代替强杀/自然租约恢复、网站浏览器或真机验收。

异步队列装配按轻度、深度显式选择：保留`NewAIL1ReportQueue`仅接受轻度任务，`NewAIL2ReportQueue`仅接受深度任务，共用原有限扫描、数据库准入复核、租约、worker及终检账务。扫描提示不授予执行权限，锁内必须确认任务类型仍与提示一致；缺准入、关闭worker或关闭队列均不能执行。构造器不启动后台循环、不创建任务或启用真实调用；正式命令与可信控制面装配及深度队列端到端验收仍单独完成。

协作增量的执行与读取约束（2026-10-29核对）：深度准入与worker共用完整容量预检，计入Agent、章节选择及两次报告核验的最坏预算；预检不替代执行时的持久预约。报告追问的历史读取保留原执行截止时点和摘要，但每次读取仍核对本人当前可读报告及来源证据；只读计划不能进入模型Run，也不能写入执行控制器。关闭新提交不应让已完成且仍获授权的历史答案失去读取能力，历史读取也不能延长新执行授权。

会员余额展示口径（2026-10-29用户确认）：会员首页“我的积分”只显示新账本当前有效批次可消费额，冻结额单列。`GET /api/v1/ai/points/balance`按已鉴权会员查询同一事务时点的余额，不接受客户端用户ID，不创建账户或清扫批次；失败清空结果，前端显示“暂不可用”，不回退`profile.credit`或旧缓存。旧积分不迁移、不合并；点击余额不再导向旧资产页。页面展示是查询快照，不能代替报价及创建时重新校验；迟到回包必须匹配当前身份和刷新轮次。接口独立默认关闭，不能由会员页访问隐式开启真实任务或模型。

会话、问答、SSE开关独立且默认关闭；关闭会话新入口不撤回原历史任务/报告读取，关闭SSE继续原轮询。先实现会话持久化与原任务关联的纵向链，再加入完整受控问答/报告追问、深度能力及主入口切换，不能以第一条纵向链标记全部目标完成。MySQL8/9、RC/RR、服务/handler反例与实际H5分别验收；真实模型只走另行明确授权的隔离用例，不由普通CI调用。所有旧门禁、覆盖率与生产关闭状态不降低。

## 13. 深度资料研究样板（2026-10-30）

### 13.1 复用与交付顺序

沿用sources的来源登记、许可、不可变正文/快照和句子索引；沿用qa的对象范围、本人报告读取和固定输出；沿用conversation关联原任务，finalreport负责最终交付及原账本结算。专题版本是资料集合及事实字段的版本，不重建会话或执行系统，不覆盖原报告。现有资料生产许可和正式模型装配仍是独立前置。

用途与版本边界见[ADR-0028](../../adr/0028-专题档案版本与用途授权分离.md)。qa的Scope/Authorize绑定现有问答模型与策略，不能作为档案发布授权使用；后续新增明确用途的版本与批准记录，同时复用原会员鉴权、来源当前许可和事务设施。首批只接既有theme主数据，topic目录保持尚未接线状态。

先实现确定性的单文档版本比较内核及反例，再做专题档案字段/审核绑定、授权服务和持久化、公开只读接口、会话内档案/原文/变化视图，最后做多来源核验与完整评测。真实样板限定2—3题材；未确认资料时用example.test及显著“仅测试”合成夹具，不向现有目录写入假题材。

### 13.2 档案和事实字段（待接线）

专题按定义与范围、产业环节、政策标准、公开进展、归属依据、资料缺口分组。事实项至少绑定专题版本、稳定字段标识、主体身份、所属期间、适用范围、阶段/口径/单位、快照身份与句子编号。发布/生效/所属期间/采集四类时间独立保存，未知保留未知；字段原文与规范值分开，不按文本相近自动合并主体。主体、口径、时间不齐时不产生数值差额或趋势。

首批显示原文和固定字段标签；不增加自由生成摘要、个股详情或投资评价。事实字段需经过抽取、原文绑定、当前许可及语义核验；引用真实存在不等于支持命题。多来源独立性另存可核验的上游来源链，未知不计独立；纠错/撤回关系必须有明确原文依据，不能从文本删除推导。

### 13.3 单文档版本比较内核

事实字段内核契约（DR-2开发）：`Draft`固定协议、题材ID、版本号、编制时点、事实卡与缺口项，不接受自由生成正文。卡片按固定章节分类，正文引用一整句；主体、发布日期、生效日期、所属期间、范围、阶段、口径、单位分别用`known/unknown`及精确原文区间表示。`unknown`不得带引用；`known`不得由客户端传入“规范值”，实际文字从所提供且完整性已核验的快照回取。字段区间必须位于声明句子内、在UTF-8边界、最多200字，正文句最多1000字；字段所在完整句也须通过原红线守卫，防止从不允许的句子中截出片段蒙混。

首版不规范化日期、不自动统一主体或阶段、不推导事实独立性。字段与原文绑定通过仅是结构证据；主体是否归属、原句是否支持字段含义仍须后续审核/语义判定，不能直接发布。事实卡缺少正文不以零值放行，缺口用固定原因单列。每版最多64卡、64缺口、32快照、总正文4MiB，快照仍受单份1MiB/4096句限制；编制时点不得早于引用快照采集。档案规范编码按卡/缺口键和快照ID排序，摘要绑定协议、原守卫版本、全部字段与快照元数据；快照必须恰好覆盖引用集合，拒绝遗漏、重复和夹带。

`server/internal/ai/dossier`只做离线纯计算，复用`sources.Snapshot.Validate`重算哈希及句子索引。输入必须为同来源、同类别、同规范HTTPS链接的两个不同快照，采集时间严格递增；比较的是采集版本，不代表发布日期或业务生效先后。跨链接版本须未来单独审核文档关联，本内核拒绝隐式合并。

每份正文最多1MiB、4096句，先限规模再验证；精确逐句、多重集合匹配，同文句按出现次序一对一配对。结果仅含快照/哈希/句号/字节偏移、正文变化标记、共有句子是否换序、新版增加的句子位置和旧版在新版未匹配的位置；不返回模型文字、原文正文、URL或授权材料。重复句数量变化不会被集合去重掩盖；只调换句序不伪造新增/缺失句。规范正文的空白或句间变化可表现为正文变更但无增减句，不推断实质变化。

“新版未匹配”仅表示文本差异，不表示事实失效、来源撤回或政策废止。本内核无会员身份、当前授权、HTTP/数据库/模型或发布能力，其结果不能直接作为用户响应/最终报告。后续服务必须先核双方当前权限，再比较，发布前再核验并通过现有模板/引文/终检；任一版本不可读时连变化数量也不返回。比较结构成功不能替代权限或事实核验。

### 13.4 后续接口与界面接线约束（未实现）

先确定专题版本/字段及来源授权绑定的持久化设计再新增迁移；接口只接收既有题材与版本标识，不接受客户端正文、任意URL、主体映射或许可声明。跨版本读取须在一致的授权范围内完成，不借历史缓存恢复撤权资料。只读比较零模型调用、零积分写入；生成新报告仍另行原报价确认。页内分“专题资料/原文核验/版本变化”，复用当前会话，不新增孤立聊天入口；未上线的能力保持不可提交。

### 13.5 评测与完成边界

建立固定合成反例集和另行确认许可的真实问题集，标注者依据原文确定答案与不可答原因。记录题材/资料/提示/模型版本、样本数、可答分母、支持精确率、覆盖率、主体/时点/阶段/单位错误、拒答是否正确、耗时和实际成本。来源转载不能重复计分；训练/调试样本与最终保留样本分开。同资料质量对照控制输入资料一致，完整任务对照计入找资料、核验和操作时间，不能混称模型能力胜出。

本次目标文本、内核单测不等于专题API、界面、真实资料或商业验证完成。现有AC-C移动端/平台证据缺口继续保留；R矩阵分别登记离线、真库、H5和真实模型进展，不用已有原报告链路证明新档案链路。

### 13.6 事实候选存储准备与版本时序（2026-10-30增量）

事实卡内核已提供规范编码、绑定摘要及严格重读：重读先核预期摘要，拒绝重复键、大小写别名、未知字段、额外正文及非规范编码，再从重新取得的快照重建字段。摘要绑定守卫版本、题材/版本/编制时点、全部卡片/缺口及来源元数据；返回副本防止调用方修改已绑定结果。内核没有语义支持或权限通过标记，当前无数据库、HTTP或前端装配。

下一步持久化必须保留三类身份：题材下的不可变档案版本（版本号/摘要/规范记录）、版本引用的不可变快照集合、可撤回的当前发布与会员读取批准。未知或不存在的版本不能自动创建；相同身份相同摘要可重读，相同身份不同摘要必须冲突。字段值仍从原文回取，不能在存储中增加未经核验的自由正文。发布审核绑定精确摘要及用途，撤回不能改写历史内容或旧报告结算。

**现存快照去重约束已核**：`tm_ai_source_snapshots`以(source_id,url_hash,content_hash)唯一，同文重新采集会复用旧快照。因此档案版本号/编制时点与快照首次采集时点是不同概念。DR-1的`CompareSnapshots`只适用于两个采集时点严格递增的不同快照，不能直接充当所有档案版本比较：档案新版重新引用旧正文、相邻档案引用同一快照，都必须由后续档案版本比较器按已绑定的版本身份处理。不得改写旧快照时间或复制正文来强行满足采集顺序。真库与服务验收须覆盖“A→B→A”和“档案升级但正文相同”；尚未实现该档案级比较，不能宣称已有完整版本回溯。

### 13.7 专题版本持久化与当前读取（2026-10-30开发增量）

版本目录及对照增量：`GET /api/v1/ai/themes/{id}/dossiers?beforeVersion=<可选正整数>`返回每页最多10个当前可读版本及编制时间，不返回未授权数量。候选只枚举本人当前启用且摘要匹配的发布/会员批准，降序每批8条；外层同一事务内借用原单版读取流程逐版回取/校验，跳过明确不可读版本，其他失败整组清空。借用器不开启/提交嵌套事务并拒绝写入；外层结束复核所有入选批准和来源的最早过期时点及本人身份。最多检查32个候选，未找到第11个可读版本且尚有未检查历史时返回暂不可用，不以伪空列表结束；游标只取第10个已复核版本，隐藏候选不出现在游标或计数中。绑定档案仍为单版4MiB/32快照，正文回取复用原读取器8MiB总保护，整个请求十秒；不承诺无限历史扫描。

`CompareVersions`按不可变档案身份/编制时间比较，接受同快照升级及A→B→A；同编号快照元数据冲突拒绝。优先同键同文，再同文多重集合配对，卡片改键不制造新增；剩余同键只标摘录调整。分别返回新增/本版未出现、文字/出处/引用位置/栏目与字段引用调整、缺口记录变化。原句相对顺序按被引用的原文句号定位判断，同档案混用同文档多个采集版本时不推断唯一顺序。此结果只覆盖已选入档案的摘录，不是全文差异、语义核验或显式事实更正；双方当前授权成功后才计算和返回，任一失败不返回变化数量。

会话页面复用问答题材选择：选题后可展开`AIDossierPanel`，主动查询可读版本、阅读单版、选择两版对照，查看八类字段/未知、原句上下文/出处和缺口。客户端白名单验证版本/位置/固定模板与比较引用，全部按纯文本渲染；复制任一出处前重读所选单/双版，失败清空正文和目录。账号、题材、会话、页签切换及卸载作废在途响应，不缓存至本地存储。此入口目前未固化为新的会话消息，不把临时选中的版本当历史消息；后续持久关联与实际登录H5验收保持未完成。

本地只读接口增量：`GET /api/v1/ai/themes/{id}/dossiers/{version}`只接受可选`compareVersion`，第二版本须严格大于第一版，单版/两版均使用原服务一次性当前授权读取。统一会员JWT中间件与服务前后复验共用同一真实会话服务。公开DTO只含版本编制时间、卡片原句、known/unknown字段、完整原句上下文、出处类型/链接/采集时间/快照句子字节定位及闭集缺口；不返回规范记录、摘要或许可/批准引用。不将两份版本内容称为差异报告，也不把known字段称为语义核验通过。未知字段不填Quote，响应固定提示资料摘录边界；`Cache-Control:no-store`，错误不序列化部分结果。

`TM_AI_LOCAL_DOSSIER_READ_ENABLED`默认关闭；显式启用只接受既有隔离本地配置、真实调用关闭、同一回环实例/专属库和不同数据库账号。`TM_AI_LOCAL_DOSSIER_PREPARE_DSN`仅环境注入，用于短期结构准备连接，完成隔离标记及回滚探针后关闭；业务连接单独验证隔离标记和读取权限。所有检查及会员认证装配成功才注册路由，不能用历史检查标记或单个开关跳过。DSN不写配置文件或日志；没有生产开启路径、候选写接口或隐式发布。新能力尚无会话页面、目录/版本列表及发布管理，已有数据库批准仍须另行登记；此读取接口不会自行创建批准、模型任务或积分记录。

结构保护增量：`AIDossierSchemaVerifier.Verify`由迁移/启动准备账号执行，十秒超时，核对四表的InnoDB、列类型/非空/排序规则、精确唯一索引、限制型外键、启用的检查约束、默认关闭值及四个不可变触发器完整动作。随后在单个仅回滚事务内创建随机测试来源/正文/快照及候选/许可，实际验证正常写入、默认关闭、字段边界、不可变、唯一键和摘要外键。探针无持久业务行，不涉及会员/会话/账本；源表自增序列可能消耗编号，不能宣称数据库完全未变化。业务读取账号不获这些写入或TRIGGER权限，仍单独执行读取权限检查。公开启动入口尚未装配，两阶段检查不能用过期的文件标记代替；启动后仍逐请求重建证据和重验许可。本检查覆盖专题四表，不冒充原资料库完整结构审计。

读取账号前置检查增量：`AIDossierRepo.VerifyReadAccess`在十秒上限内用无结果查询检查实际列权限、快照与正文关联读取及共享锁语法，并复用会话配置验证；只回滚，不读正文或写业务数据。它仅是读取权限检查，不替代结构约束/触发器定义与回滚保护探针，也不证明账号没有额外权限。后续启动装配须同时完成结构保护检查，不能仅凭本方法开放接口。真库测试用独立随机账号，仅授予九张依赖表SELECT，实读两版，再逐表撤权验证预检失败和读取不返回部分结果；另检查DDL、版本/引用写入、来源与发布/会员授权修改和账本访问被数据库权限拒绝。

新迁移`20261030_create_tm_ai_dossiers.sql`增加四张独立表，不修改账本/会话/报告表：`tm_ai_dossier_versions`以题材和版本为主键，固化规范记录、摘要与编制时点；`tm_ai_dossier_evidence`以题材/版本/快照为主键，绑定源编号和内容哈希；两者拒绝UPDATE/DELETE。发布表`tm_ai_dossier_publications`按题材/版本绑定同一摘要，会员表`tm_ai_dossier_grants`按会员/题材/版本绑定同一摘要；两者默认enabled=0，必须有用途批准引用和有效期。版本/证据引用受外键保护，会员/题材活跃状态仍实时查询原主数据，不假设另一套账户或订阅已存在。

`AIDossierService.StageInternal`只在显式允许内部导入的构造方式可用，没有路由/默认装配。服务按已选快照加载原文、按来源ID升序取当前许可共享锁，再锁题材、绑定候选、取版本当前读。相同身份同摘要重读，异体冲突；新增版本号和编制时点都须晚于该题材已有最高版本。版本及全部引用同一事务落库；数据库时间在写前、写后均复核来源有效期，避免共享锁不能阻止自然过期的问题。提交确认未知返回空摘要，重试仍只核原版本，不自动创建新版本。

`ReadVersions`一次只接受一个或两个严格递增版本号，最多两份档案，返回内部绑定对象而非公开DTO。JWT认证依赖由调用者显式装配，事务前后重验同一会员；事务内先锁当前会员，再按版本顺序锁发布/会员批准，取得版本和引用；来源按编号排序取共享锁，最后检查原题材状态。两版中的任一批准缺失/停用/过期、任一来源许可变化或撤回、记录无法重建，都清空整个结果，不返回部分正文或变化数量。末尾重取数据库时钟检查许可自然过期。RC/RR均对版本及引用使用当前读，不能让旧一致性快照掩盖刚提交的原版本。共享锁以本次事务为读取线性化边界，不承诺清除已经交付到用户设备的历史内容。

主键支持按题材取最新版本及按精确会员/版本鉴权，引用读取有33行探针上限；每版32快照/4MiB、两版最多64快照/8MiB，期限10秒且服从更短父上下文。来源/正文仍通过既有查询回取；独立运行账号、结构保护启动探针、公开DTO/接口、固定模板页面以及发布/授权管理审计尚未装配，不把测试中直接登记的批准记录当成生产批准管理完成。当前无公开路由、真实模型、积分写入或生产开关变化。档案级对照输出仍待接，不用两版读取冒充变化报告。
