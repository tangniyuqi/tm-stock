# AI 分析模块 · 任务拆解与路线

> 配套：[requirements.md](requirements.md) · [design.md](design.md) · [research.md](research.md)。
> 每个任务必须**可独立验收**。状态：⬜ 待办 / 🔄 进行中 / ✅ 完成 / ⛔ 阻塞（✅ 只表示"本机实测通过"，CI 首跑、生产环境、需要 Docker 的验证在各阶段"进展记录"里单列为未验项）。规模 S/M/L 为相对粗估（没有历史速度数据，不给工期）。
> 原则（ADR-0006）：写代码可以并行，**砸人力和上线不行**。每个阶段有退出标准，未过关不进下一阶段；"公开上线"另设关口（阶段 4）。

## 0. 路线总览

```
阶段 0 存量整改 ──→ 阶段 1 地基 ──→ 阶段 2 L0 内部助手 ──→ 阶段 3 账务与任务持久化
                                                              │
并行轨道 X（外部事项：律师、登记、授权、监管跟踪、需求验证）──────┴──→ 阶段 4 L1 轻度 ──→ 阶段 5 L2 深度 ──→ 阶段 6 优化
```

- 阶段 1 与阶段 0 的 P0-1 可**同时开工**；阶段 2、3 的代码可并行，但都**不对外**。
- 阶段 4 起才触及公众，必须先过关口 X1–X5。
- **不依赖用户决策、可立即开工**：P0-1、P0-5、P1-1 至 P1-6。其余任务的阻塞决策已在"依赖"列标明。
